# CCSwitchMulti v3.20.2-19

本版修复 DeepSeek 角色 slug 别名口径不一致导致的 V2 Agent 配置页“目录中缺失”误报与 flash 角色文件不生成的问题。根因是产品内部 canonical slug（`deepseek-v4-flash`/`deepseek-v4-pro`）与 DeepSeek 现行 API slug（`deepseek-flash`/`deepseek-pro`）不一致，各角色分类点硬编码了旧 slug；`deepseek-pro` 未变，所以 pro 侧一直正常。

## 问题

在模型目录里启用/选择 DeepSeek 现行官方 slug `deepseek-flash` 后，V2 Agent 配置页的 flash 角色覆盖徽章仍显示“目录中缺失”，且 `deepseek-flash` 的角色 toml 没有生成。用户已打开该模型（live 请求 HTTP 200 可用），但产品仍按旧 slug 判定，属于 bug。

## 根因

产品内部 canonical slug（用于 V2 默认 profile、catalog 模板、preset）是 `deepseek-v4-flash`/`deepseek-v4-pro`，而 DeepSeek 现行 API slug 是 `deepseek-flash`/`deepseek-pro`。各角色分类点硬编码旧 slug（精确匹配或 contains），当 catalog 使用新 slug 时：

1. **UI 徽章**（`CodexRouterWorkspacePage`）只认 `deepseek-v4-flash*` → 误报“目录中缺失”。
2. **V2 编译器**（`codex_subagent_profiles.rs`）按忽略大小写精确匹配 catalog → 旧 slug profile 被标 Unroutable，role 文件不生成。
3. **V2 自动生成**（`catalog_profile_draft` / `preferred`）按 identity 精确取默认 preset → `deepseek-flash` 落不到 `deepseek-v4-flash` preset，退化成 disabled 的通用 stub。
4. **V1 角色文件 helper**（role name/description/effort/guidance）contains 旧 slug → 新 slug 拿不到 Flash/Pro 角色语义。
5. **text-only guard** 精确匹配缺两个别名 → 新 slug 不会强制文本模态，Codex 会注入 DeepSeek 不支持的 hosted `image_generation` 工具。
6. **reconcile** 的 PruneUnroutable/Recover 按旧口径 → alias profile 可能被误删。

**上游验证（决定性证据）**：

- `GET https://api.deepseek.com/v1/models` 只列出 `deepseek-flash` 与 `deepseek-v4-pro`。
- 用 `model: "deepseek-v4-flash"` 发最小 `POST /v1/responses` → HTTP 200，响应回显 `"model":"deepseek-flash"`。两者是同一个模型，旧 ID 是被上游继续接受的 legacy alias。因此无需改动 catalog 模板或 preset，只需统一产品内部的别名口径。

## 修复（单一事实来源，不打补丁）

- 新增 Rust 共享 helper（`codex_subagent_profiles.rs`，pub）：
  - `deepseek_role_identity_for_model`：flash 族（`deepseek-flash`/`deepseek-v4-flash` 及其 `-` 前缀版本，排除含 `vision`）→ canonical `deepseek-v4-flash`；pro 同理。
  - `deepseek_role_models_match`：精确忽略大小写匹配，或同角色族等价。
- 所有 catalog↔profile 匹配点统一走该口径：V2 编译匹配、别名匹配时把 role 模型钉到 catalog 实际 slug、`catalog_profile_draft` preset 查找、两处 `preferred` 标记、`routable_by_identity`（prune/recover 别名键）、compile/preview 的 input_modalities 水合与 spec/role 查找、`route_classifications`/`reasoning_capabilities` 查询、V1 四个 helper、text-only guard 增加 `deepseekflash`/`deepseekpro` 精确项。
- 新增 TS 共享 helper（`src/utils/deepseekRoleModels.ts`，与 Rust 同口径）：徽章、“重点”名单、`modelNameLooksTextOnly`（顺带修掉 TS 侧此前漏掉的 `deepseekv4` 前缀过匹配）。

## 行为边界（有意为之）

- `deepseek-v4-flash-vision-exp` 不再被 V1 role helper 的 contains 命中为 flash 文本角色（走通用 slug 路径，独立角色名），与此前既定口径一致。
- V2 默认 profile 键、provider preset slug、profile 冲突身份均未改；alias 双 profile 同存时各自可路由，保持既有行为。
- 用户既有配置不会被自动“升级”：已存在的 disabled stub profile 保持原样；启用开关保存后即可生成角色文件（修复后编译匹配与徽章均正确）。
