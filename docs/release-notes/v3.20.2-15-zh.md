# CCSwitchMulti v3.20.2-15

“Codex 状态与修复”不再每次开机重复弹出同一个无法处理的提示，并找回了一批本来可以安全修复的分页历史。

## 修复

- **开机反复弹窗**：以前只要存在“保持原样”的历史文件就会自动弹出状态面板，而这些文件永远不会被处理，于是每次开机都弹。现在只有**存在可安全修复项**时才自动弹出。
- **“需要处理”说不清在做什么**：分页历史一行改为两种明确状态——可修复时显示**“需要修复”**并给出待处理数量和动作说明；只是保持原样时显示**“无需修复”**，并说明“不需要你处理”。
- **看得到原因了**：新增“查看原因明细”，按原因分组显示**原因 / 数量 / 示例**（例如“缺少可核验的迁移前备份，无法换算新的字节偏移 · 1114 个文件”）。
- **找回可安全修复的历史**：旧 CCSM Provider 迁移把 rollout 里的 `model_provider` 从 `openai` 改写为 `codex_model_router_v2`（每条 +15 字节），但没有同步 Codex 投影游标的字节偏移，导致游标落在记录中间。恢复流程原先只扫描部分备份目录，看不到可核验的迁移前快照，于是把这些会话全部判为“保持原样”。现在会把“当前桌面历史可见性修复”快照也纳入候选，仍按“逐记录只有 provider 字段不同 + 记录边界 + 序号连续”核验。本机只读预检：可修复项从 0 变为 1114，阻塞项从 1152 降到 38。

## 验证

- 真实数据字节级比对确认差异只有 `"model_provider":"openai"` → `"codex_model_router_v2"`，每条 +15 字节，与游标偏移的 15 字节倍数完全对上。
- Rust：`paginated_history` 27 passed / 1 ignored（含新增回归），`cargo test --lib codex` 1721 passed / 0 failed，`cargo fmt` 通过。
- 前端：`tsc --noEmit`、Prettier，`CodexConfigConsistencyDialog` + `useCodexConfigConsistency` 22 passed。
- 本机只读诊断用例 `real_history_blocked_reason_census`（默认忽略）输出：`affected=1114 blocked=38`。
