# CCSwitchMulti v3.20.2-21

本版聚焦 Codex 稳定性与历史可见性：修复打开 Codex 代理接管时可能长时间无响应、官方模型目录刷新阻塞接管热路径、分页历史修复被整批判为不可用、v25 迁移在缺少基表的库上失败等问题，并纳入官方模型目录刷新入口与 Token Exchange 静态 Provider 描述符集成。

## 修复

### 1. 打开 Codex 代理接管可能卡死（重要）

**问题**：开启 Codex 路由接管后界面长时间无响应，日志停在“已备份 Live 配置”之后、没有接管成功记录。

**根因**：两条同步阻塞都在持 per-app 切换锁的写配置路径上：

- v3.20.2-20 新增的 Desktop 版本门控首次探测会枚举 WindowsApps，失败回退 `Get-AppxPackage`，子进程 `.output()` 无截止时间；同一路径的 `codex debug models --bundled` 同样无超时。
- 官方模型目录刷新用 `block_on_tauri_runtime` 同步等待联网抓取；在 `futures::executor::block_on` 驱动的运行时里定时器不推进，会永久挂起，而不是超时返回。

**修复**：

- Desktop 版本与 bundled 模型探测移到取得接管锁之前预热，同步投影只读已完成缓存；失败/超时按“版本未知”继续，保留旧版行为。
- PowerShell AppX 与 Codex CLI 子进程都有截止时间，超时终止并回收直接子进程，stdout/stderr 读取同受截止时间约束。
- 同步投影不再联网：官方目录刷新改为去重后台调度（带时间预算），接管预热触发一次但不等待。

### 2. 分页历史可见性修复恢复可用

**问题**：只要本地存在任意分页 rollout，历史修复整批失败（`codex_paginated_history_immutable`），连不改写 rollout 的 state DB、session index、workspace hints、global state、focus 修复也无法执行。

**根因**：可见性入口对整个 Codex 目录执行 legacy guard，判定粒度过粗。真实数据里分页 rollout 占绝大多数（本机实测 2088 个分页 / 3 个 legacy）。

**修复**：改为逐 envelope 判定。legacy 文件继续做 Provider 状态改写；明确分页的文件只计数并保持字节不变；state DB 与索引类修复照常执行，恢复交给 live Provider 兼容层。批量 Provider 迁移、直接 writer、压缩与未知 envelope 仍 fail-closed。

### 3. 官方模型目录覆盖顺序

**问题**：合并官方目录时把当前 Codex 运行时（bundled）目录放在公共快照之前覆盖，导致公共目录覆盖机器上更新的元数据，并把公共目录独有的未来模型排到列表末尾。

**修复**：顺序固定为“随包基线 → 本机可信 cache/backup → 刷新的公共快照（字段级 merge）→ 当前 bundled（最后覆盖）”。

### 4. v25 迁移在缺少基表的库上失败

**问题**：v24→v25 迁移无条件查询 `providers` 表，对只带版本号而没有基表的库直接报 `no such table: providers`。

**修复**：按既有 v19→v20 的写法加 `table_exists` 守卫（无表即无 OpenClaw 旧行可投影），描述符表创建保持无条件。

### 5. 其他

- Codex Provider 草稿校验 fail-closed，非法草稿不再落库。
- 保存结果与取消操作的文案更明确，避免把无变更误读为失败。
- 保留显式 Responses prompt cache breakpoint，不再被热路径覆盖。
- 回滚失败的模型目录双文件投影，并区分“部分投影失败”与“无操作”。

## 新增

- **Codex 官方模型目录刷新**：支持手动刷新入口，并在后台按 TTL/失败冷却自动刷新；刷新失败继续使用已有快照，不影响路由。
- **Token Exchange 静态 Provider 描述符**：原子注册描述符并将 OpenClaw 公开投影隔离，避免污染公开 Provider 列表。

## 说明

- 本版不自动修改你的历史数据；历史修复需在应用内主动执行，且建议先预览。
- Codex 自身造成的重复 ordinal、失效投影游标、`history_base` 引用损坏属于另一层问题，需按备份逐项恢复。
