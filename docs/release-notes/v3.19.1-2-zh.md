# CCSwitchMulti v3.19.1-2

这是 CCSwitchMulti `3.19.1` 系列的首个公开修复版；此前准备中的
`3.19.1-1` 没有发布到 GitHub Releases。本版本集中修复 Codex 跨 provider
历史回放、远程压缩、MultiRouter 路由边界以及 GPT-5 token 参数兼容问题。

## 修复内容

- 修复官方 OpenAI Responses 拒绝第三方历史 ID 的 HTTP 400：按 item 类型将旧的
  `resp_*_msg`、错误的 `call_*` web search ID 等确定性规范到 `msg_`、`rs_`、
  `fc_`、`ctc_`、`ws_` 命名空间；保留已合法 ID 和带加密内容的 reasoning ID。
- 修复远程压缩返回 HTTP 200 SSE 却被判定为空摘要并上抛 422：兼容 data-only SSE，
  并在 reasoning item 已出现时继续聚合文本 delta。第三方 provider 默认仍使用本地
  压缩，只有显式 remote opt-in 才进入远程压缩。
- 修复 MultiRouter 将同一请求的 route 表误当作重试池：每次只物化最佳匹配 route，
  防止官方 GPT 请求失败后静默改投 DeepSeek/Qwen；显式配置的 provider 级故障转移
  仍然保留。
- 合入并补全上游 `#6069`：GPT-5+ 的 Chat Completions 使用
  `max_completion_tokens`；Responses 的探测预算小于 16 时提升到 OpenAI 官方允许的
  最小值；显式与 provider 默认输出预算两条 Responses→Chat 路径均覆盖。
- 保留 CCSwitchMulti 的 Grok reasoning effort 能力，没有因 OpenAI token helper
  重构而回退。
- 修复 Anthropic hosted web-search 桥接的陈旧测试预期，并让 Claude Desktop 代理
  接管测试使用临时端口，避免正在运行的 15721 服务造成假失败。

## 验证

- Rust 库完整测试：`2794 passed, 0 failed, 2 ignored`，未跳过端口相关测试。
- Chat 转换 `67/67`、Responses 转换 `82/82`、Codex Chat 转换 `119/119`。
- `pnpm typecheck`、`cargo fmt --check`、`git diff --check` 通过。
- OpenAI 官方 OpenAPI schema 确认 Responses `max_output_tokens` 最小值为 16；
  上游 `#5215` 的真实 400 与 `#6069` 的实时 review 共同验证 Chat 参数修复范围。

## 升级

从 GitHub Releases 下载对应平台安装包覆盖安装即可。Windows 用户可选择签名安装包
或 portable 压缩包；升级不会改写现有 provider、路由和会话历史配置。
