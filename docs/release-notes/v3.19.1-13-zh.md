# CCSwitchMulti v3.19.1-13

本版本集中修复 Codex Desktop 模型菜单在重启后失效、LM Studio Responses 请求格式、上游连接错误归因和 Claude Desktop profile 覆盖问题，并补充当前未签名 macOS 包的安全打开说明。

## 用户可见更新

### 1. Codex Desktop 模型菜单兼容层可自动恢复

- 修复首次解锁 Qwen、DeepSeek 等模型后，退出并重新打开 Codex Desktop，模型菜单再次只剩官方模型的问题（#32）。
- 新增与 CCSwitchMulti 代理生命周期绑定的 Codex guardian：代理启动、接管恢复或切回 Codex 时自动守护新的 renderer target。
- guardian 只对新出现且尚未注入的 Codex 页面执行模型目录注入；renderer 重启或 CDP target 更换后可重新恢复，不再依赖用户每次手动点击模型菜单解锁。
- 状态页增加 guardian 运行、CDP 可用性、已注入 target 数量和最近事件，便于区分“目录未生成”和“renderer 尚未注入”。

### 2. LM Studio Responses 请求补齐文本格式

- 修复 Codex 通过 CCSwitchMulti 调用 LM Studio Responses API 时，LM Studio 返回 `missing_required_parameter: text.format` 的问题（#34）。
- 仅在 effective Provider 明确为 LM Studio、请求仍走原生 Responses 且客户端没有提供 `text.format` 时，补充 `{"type":"text"}`。
- 用户显式配置的 JSON Schema 等格式不会被覆盖；其他 Provider 和 Chat/Anthropic 转换路径不受影响。

### 3. 上游连接失败不再误报为本地代理故障

- 修复官方 Codex 路由已经完成解析和认证、但连接 OpenAI 上游失败时，错误仍显示 `CC Switch local proxy failed` 的误导性归因（#6）。
- 发送阶段的 `ForwardFailed` 现在明确显示为 OpenAI Codex 或对应 Provider 的 upstream connection failure，并继续保留 Provider、模型、endpoint 和原始 cause。
- HTTP 状态映射、结构化错误码和重试策略未改变；真正的 CCSwitchMulti 内部错误仍保留 local proxy 分类。

### 4. Claude Desktop 切换 Provider 不再删除用户扩展字段

- 修复应用 Claude Provider 时全量重写 `configLibrary/*.json`，导致 `autoModeEnabled`、`toolSearchEnabled`、`prefer1m`、`inferenceCredentialKind` 等用户字段消失的问题（#35）。
- CCSwitchMulti 生成的网关字段继续覆盖旧值；只有新 profile 未托管的既有字段会被合并保留。
- 读取或写入失败继续进入原有事务回滚，不会用半写状态替换配置。

### 5. macOS 未签名安装说明

- README 新增 Apple `Open Anyway` 图形界面流程和仅针对 `/Applications/CCSwitchMulti.app` 的 quarantine 移除命令（#3）。
- 文档使用当前真实资产名 `CCSwitchMulti-v<version>-macOS.dmg/.zip`，不再沿用旧草稿中的 `aarch64` 文件名。
- 说明不会全局关闭 Gatekeeper；当前包仍是 unsigned/unnotarized，长期方案仍是 Apple Developer ID 签名和公证。

## 升级与验收

1. 完全退出 Codex Desktop 与 CCSwitchMulti，包括托盘中的 CCSwitchMulti。
2. 从本 Release 下载对应平台安装包并覆盖安装。
3. 启动 CCSwitchMulti 后重新接管 Codex；退出并再次打开 Codex Desktop，确认自定义模型菜单能够自动恢复。
4. 使用 LM Studio Responses 路由发送一次真实请求，确认不再返回 `text.format` 缺失。
5. Claude Desktop 用户在切换 Provider 后检查原有自定义 profile 字段仍然存在。

发布流水线成功只证明构建和远端资产完整，不等同于已经在用户机器上完成安装后运行验收。升级不会主动删除 Codex 历史、Provider、MultiRouter 路由或账号配置。
