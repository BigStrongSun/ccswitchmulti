# CCSwitchMulti v3.19.1-29

v3.19.1-29 是针对 Codex 配置损坏与 Sub-Agent V2 reasoning 编辑问题的恢复版本。重点不是粗暴删除用户配置，而是为旧版遗留坏数据提供可回滚的结构化恢复路径，并修复 v28 中未启用 profile 无法继续编辑的状态死锁。

## 主要修复

- Codex 热切换失败提示新增“强制覆盖”：仅在 Codex 切换失败时显示，并绑定本次失败的准确 Provider。
- 强制恢复会先备份 Live `config.toml` 与目标 Provider，再用 TOML 结构化迁移修复 Windows `notify` 裸反斜杠和 `[agents]` 并发字段别名冲突。
- 恢复过程中保留用户的 MCP、projects、plugins、memories 与非 CCSM 托管配置；任一步失败会恢复 Provider、当前选择、settings 和原始 Live TOML。
- 修复旧 DeepSeek V4 reasoning 默认档位错误；未知模型只使用自身声明的合法档位，不再套用 GPT 或 DeepSeek 默认值。
- Sub-Agent V2 现在严格区分“未启用”和“不可路由”：未启用但仍在模型目录中的 profile 可以继续编辑和启用。
- Provider reasoning 编辑器在取消档位时自动清理指向该档位的映射，保存时拒绝孤儿 target，避免配置保存后静默失效。
- 官方 Codex 模型可按精确 slug 从官方模型缓存读取 reasoning 档位，兼容字符串数组和对象数组；CCSM 托管缓存绝不会被误当成官方来源。
- 无效 reasoning 声明现在写入包含模型名与原因的 warning，便于诊断，不再静默消失。

## 安全与兼容边界

- “强制覆盖”不是删除整份 `~/.codex/config.toml`，恢复前有独立时间戳备份和完整回滚。
- 没有引入缺乏 Moonshot 官方依据的 K3/K3-256K 固定三档，也没有放宽 Unknown capability + Fixed 校验。
- V1 direct model override、V2 custom role、用户手写 Agent 文件和 reserved tool schema 保持原有边界。
