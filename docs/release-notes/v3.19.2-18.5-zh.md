# v3.19.2-18.5

## 修复

- **schema v2 路由被启动迁移污染（Issue #76 根修）**：旧版 DeepSeek 升级迁移 `repair_deepseek_native_responses` 此前会把 `apiFormat` / `match` 写进 `schemaVersion = 2` 的路由，而 v2 解析对这些继承字段 fail closed——表现为「保存 V2 子 Agent 配置」持续报 `v2_route_forbidden_field`，且手工清库会在下次启动被迁移写回。迁移现在对 schema v2 文档整体跳过（v2 的协议/模型事实由目标 Provider 目录承载）。
- **持久化边界兜底**：`save_provider` 对 schema v2 路由统一剥离禁用继承字段并记录告警，覆盖任何写入方（前端、同步、导入、手工编辑），防此类问题复发。

## 改进

- **子 Agent 孤儿可见化 + 一键清理**：未启用且模型已不在当前路由目录的 profile（模型下架/改名后滞留的旧键）现在显示「已过期：模型不在当前路由目录」标记，并提供「删除」按钮；保存后生效。
- **路由别名后缀改为拼音**：模型源重名消歧时，非官方来源的可见模型后缀不再使用完整 36 位 provider UUID。provider 名称为纯中文时转为无声调拼音（如「基元律动」→ `glm-5.3-flash-jiyuanlvdong`）；拼音不可用时回退 provider id 前 8 位。工作台重新保存一次路由规则后，存量长别名会自动收敛为新后缀（旧别名键按可见名集合清理，profile 由别名等价迁移跟随重命名）。

## 升级说明

- 从 3.19.2-18 升级后首次启动即可解除「保存 V2 子 Agent 配置」报错，无需手工清库。
- 若此前存在 UUID 长别名：进入对应 MultiRouter 的工作台，重新保存一次「路由规则」，可见模型名即收敛为拼音短后缀。
