# CCSwitchMulti v3.20.4-16

## Codex 请求压缩选择

- 修复原生 Codex 已关闭请求压缩，但 CCSwitchMulti 在官方 Responses 出站时仍强制重新压缩的问题。
- 普通 Responses 与 compact 入口在解码前保留客户端的编码选择；原生客户端发送明文或 `identity` 时，上游保持明文；发送压缩请求时，仍在 JSON 归一化后重新压缩，保留原有带宽优势。
- 编码选择通过内部类型传递，不增加上游请求头。损坏或不支持的压缩编码仍直接拒绝；托管 OAuth、外部 API、第三方和协议转换路径不改变原有策略。
- 保留 v3.20.4-15 的容量恢复机制，不将普通 HTTP 400 改为自动重试，不跨账号恢复或自动重放已结束的任务。

## 使用边界

本版不会默认关闭压缩。需要使用 Codex 的关闭压缩选项时，在现有 `[features]` 表中设置以下字段，并由新启动的 Codex 客户端加载：

```toml
[features]
enable_request_compression = false
```

新版 CCSwitchMulti 会尊重该原生客户端的明文选择；现有配置已有 `[features]` 时只修改字段，不重复添加表。

同一合成 JSON 的压缩／明文对照已复现压缩相关的通用 400，但不代表所有 HTTP 400 都由压缩引起。本版不更改数据库 schema；安装并加载新版进程后修复才生效。
