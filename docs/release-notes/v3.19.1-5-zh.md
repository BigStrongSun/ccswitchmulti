# CCSwitchMulti v3.19.1-5

本版本集中修复 Codex 官方模型长任务中的请求膨胀、SSE 断流恢复回归，以及应用内更新仍走原版地址的问题。它恢复了 CCSwitchMulti 托管模式下 Codex 原生客户端应有的两层恢复能力，但不会把官方明确拒绝的 HTTP 400 或已耗尽重试的故障伪装成成功。

## Codex 官方模型断流与重试

- 恢复托管 Codex provider 的 `stream_max_retries=5`，与 Codex 官方默认值一致。正文、Reasoning、output item 或工具事件已经输出后发生 incomplete stream 时，由掌握 session/turn 状态的 Codex 客户端重新采样，不再因 CCSwitchMulti 把预算写成 `0` 而直接终止长任务。
- `request_max_retries=2` 保持不变，继续覆盖流建立前可安全重试的连接失败和 HTTP 5xx；对结果未知、可能已经到达上游的请求仍使用 `ResponsePending/429` 边界，避免重复工具调用或重复计费。
- CCSwitchMulti 自身只在原生 Responses SSE 尚未输出实质事件时透明重连，最多五次，并抑制重复的 `response.created`；静默推理期间发送 SSE 注释心跳。实质事件之后不由代理整轮重放，而是交给 Codex 官方状态机恢复。

## 官方请求恢复原生 Zstd

- 修复 CCSwitchMulti 为路由解压 Codex 原生 Zstd 请求后，以未压缩 JSON 转发给 ChatGPT 官方上游的问题。
- 现在仅对官方 Codex OAuth/native Responses 与 compact 请求，在所有必要变换完成后重新进行 Zstd 编码；Responses-Lite fallback 和去头重试共用同一 wire body 边界。
- 现场复现中的同一长会话请求由约 `16.79 MB` 明文恢复为约 `10.87 MB` Zstd 传输体，降低大历史、内联图片和 encrypted reasoning 正常回放时的传输压力。第三方 provider、Chat/Anthropic 转换路径仍保持原有明文语义。
- `encrypted_content` 与内联图片本身不是此次 502 的已证实根因：同一完整请求经原生 Zstd 可返回 HTTP 200。本版不删除正常历史字段，也不把官方一次性的 `{"detail":"Bad Request"}` 猜测成固定字段错误。

## 应用内更新与 Multi 链接

- 应用内更新器复用 CCSwitchMulti 已配置的全局 HTTP/SOCKS 代理，避免模型转发正常而更新器直连 GitHub 超时。
- 数据库恢复页、设置页、应用标题和托盘入口统一指向 CCSwitchMulti 仓库或 Release，不再打开原版 CC Switch 页面。
- 保留 Tauri 签名校验、下载进度和 Windows 安装前清理流程；自动更新失败时仍可从 Multi Release 页面下载安装包覆盖升级。

- Rust 库完整串行测试：`2803 passed, 0 failed, 2 ignored`；WebDAV 本地用例单独连续运行 10 次通过。
- Codex 流恢复 `20/20`、Codex 配置 `114/114`、代理服务 `75/75`、forwarder `137/137`。
- TypeScript typecheck、renderer 生产构建、`cargo fmt --check`、`git diff --check` 通过。
- 发布工作流会在 Windows x64、Windows ARM64、Linux x64、Linux ARM64、macOS 五个平台构建，并生成签名 updater `latest.json`。

## 升级与下载

可在应用内“设置 → 关于 → 检查更新”升级；也可从 GitHub Release 下载对应平台安装包覆盖安装。升级不会改写现有 provider、路由和 Codex 会话历史配置。

- macOS：DMG 或 ZIP。
- Windows x86_64 / ARM64：Setup.exe 或 Portable.zip。
- Linux x86_64 / ARM64：AppImage、DEB、RPM。
- `latest.json` 与平台 updater 压缩包由应用内自动更新使用。

## 能力边界

本版修复的是 CCSwitchMulti 相对原生 Codex 的已确认回归：官方请求不再因代理解压而膨胀，托管配置不再关闭 Codex 的五次流恢复。官方服务最终返回的非重试型 HTTP 400、账号/额度拒绝、或所有重试耗尽后仍断开的场景仍会如实报错；任何客户端都无法承诺外部服务永不失败。
