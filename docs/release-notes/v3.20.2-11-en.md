# CCSwitchMulti v3.20.2-11

This build fixes "the proxy port is occupied and releasing it forcibly also fails": when a stale listener is held by a socket whose creating process has already exited, the app now finds the real holder among its own child processes and releases it.

## Root cause

- Reproduced locally: after duplicating the listening socket handle into another live process and killing the creator, the Windows TCP table still reports the **dead PID** as the owner. Binding then fails with 10048, and that PID can be neither verified nor terminated, which is exactly the reported failure.
- The previous implementation only looked at the TCP owner PID, so such a leftover could never be released or self-healed.

## Fix

- Startup recovery now locates live children of that creator PID and terminates only this product own images (msedgewebview2.exe, ccsm.exe, codex-history-repairer.exe, cc-switch.exe, or programs inside the install directory), then retries the start once; foreign processes stay fail-closed.
- The "release port and restore takeover" action uses the same release path and completes the takeover once the port is really free instead of only reporting an error.
- Port diagnostics still record the PID, socket state and why an identity could not be read.

## Verification

- New regressions: `release_stale_listener_holders_never_touches_foreign_children`, `stale_listener_owner_pid_ignores_a_live_owner`, `child_processes_of_reports_a_live_child`, `product_helper_allowlist_is_narrow`.
- `services::proxy` 104/104; full Rust suite single-threaded 4158 passed / 0 failed / 7 ignored.
