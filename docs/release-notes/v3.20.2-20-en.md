# CCSwitchMulti v3.20.2-20

This release fixes four reported issues: MFJS tool-schema 422s (#87/#101), Codex App cross-thread messages poisoning third-party sessions (#98), the settings-page "application failed to load" crash (env injection empty state), and the `unrecognized configuration settings` warning on strict-diagnostic Codex Desktop builds. It also merges community contributions: repeated Responses namespace consolidation (#95), official-fallback routing for native image edits (#97), MiMo 2.6 Chat tool-call adaptation (#103), safe Codex plugin registration repair (#69), and the Rust dependency group update (#90).

## Fixes

### 1. MFJS tool-level fail-open and Moonshot endpoint gating (#87, #101)

**Problem**: `/v1/responses` requests on third-party routes (including DeepSeek) returned 422 because Codex dynamic tool schemas (non-disjoint `oneOf`, unknown `encrypted` keys, etc.) failed Moonshot MFJS compilation.

**Root cause**: (1) the MFJS dialect contract was whole-request fail-closed — one unrepresentable tool poisoned the entire request; (2) probes misclassified model-behavior deviations as upstream schema rejections, persisting a `moonshot_mfjs` dialect into non-Moonshot route profiles, which the runtime then inherited unconditionally.

**Fix**:
- Tool-level fail-open: an unrepresentable tool is dropped with a log event while the request continues; non-disjoint `oneOf` is widened to `anyOf` with the tool downgraded to `strict=false`; unknown schema keys are dropped with a non-strict downgrade.
- MFJS switching/inheritance is double-gated: only on Moonshot/Kimi endpoints with explicit/ambiguous schema-rejection evidence; stale profiles on other routes no longer trigger MFJS.
- Empty/invalid tool-call arguments are no longer schema-rejection evidence; they trigger one same-dialect `tool_choice=required` silent retry.

### 2. Codex App cross-thread messages poisoning third-party sessions (#98)

**Problem**: standalone synthetic `function_call_output` items injected by `send_message_to_thread` / `automation_update` (`namespace=codex_app`, no `call_id`) were converted into tool messages with a missing `tool_call_id`, making every subsequent request in that session (including `/compact`) fail with 422 — permanently, re-poisoned on every cross-thread message.

**Fix**: the Provider-facing Responses-to-Chat converter now projects such orphan synthetic events as plain user messages (full output content preserved); orphan tool results in other namespaces and normal paired tool history keep the strict fail-closed validation. Affected sessions recover automatically on the next request after upgrading.

### 3. Settings-page "application failed to load" (ROG AMD, v3.20.2-19)

**Problem**: with `envInjection.enabled=true` and an empty variable list, opening Settings replaced the whole screen with the React error boundary and got stuck in a reload loop.

**Root cause**: six `Vec` fields on `EnvInjectionTargetSyncStatus` carried `skip_serializing_if`, omitting empty arrays; the frontend declares them required, so `undefined.map` threw a TypeError.

**Fix**: removed the six `skip_serializing_if` attributes (keeping `serde(default)` for old payloads), with Rust serialization and frontend empty wire-shape regression tests.

### 4. `unrecognized configuration settings` on strict-diagnostic Codex Desktop

**Problem**: new Codex Desktop builds (>=26.912) reported the inline `model_providers.<id>.models` projection as unrecognized configuration.

**Fix**: gated on the Desktop package version (26.MDD scheme only): >=26.912 stops writing inline models and cleans up leftovers from older versions, keeping only the top-level `model_catalog_json`; older versions and probe failures keep the old behavior (zero regression).

## Community contributions (merged this release)

- **#95**: consolidate repeated `tool_search` namespace declarations in Responses requests, gated to the gateways confirmed to reject duplicates; fixes `Duplicate namespace name 'mcp__...'`.
- **#97**: native Codex image edits (`POST /v1/images/edits`) use the same official-fallback provider resolution as image generation; multipart parsing reads routing fields only and never rebuilds the upload.
- **#103**: MiMo 2.6 Pro/Flash Chat tool-call adaptation: FREEFORM `apply_patch` raw-patch normalization and catalog/request parameter alignment.
- **#69**: safe Codex cached-plugin registration repair: detect enabled cached plugins missing from the personal marketplace and repair explicitly, preserving existing entries.
- **#90**: Rust dependency group update (58 packages). Three breaking major upgrades were reverted to their previous versions in this release (same split-batch precedent as #14): `rusqlite 0.40` (removes `u64`/`usize` SQL conversions, affecting ~30 DB read/write boundaries) and `toml 1.0`/`toml_edit 0.25` (`Value::FromStr` no longer parses documents, breaking the entire provider-config parsing chain; 200+ test failures). The remaining 55 updates are kept, with behavior-preserving adaptations for `sha2 0.11` (hybrid-array digest hex encoding), `hmac 0.13` (`KeyInit` import), `tokio-tungstenite 0.30`/`axum 0.8` (`Utf8Bytes` conversions, wildcard route syntax `/{*name}`, removed `Option` extractors).

- CI: `actions/cache` 5 -> 6 (#5).

## Not in this release (tracked)

- #14 (frontend-deps bulk update): includes TypeScript 7 (removes `baseUrl`); held for a frontend toolchain migration.
- `rusqlite 0.40` migration (u64/usize -> i64 SQL boundary semantics) and `toml 1.0`/`toml_edit 0.25` migration (document parsing API + serialization byte-identity semantics): reverted when #90 was split; to be re-merged after a dedicated migration with full regression.
- #100 (MultiRouter alias lifecycle), #94 (per-model context window persistence), #93 (official catalog sync diagnostics): larger improvements; decomposed/diagnostic paths posted in the issues.
