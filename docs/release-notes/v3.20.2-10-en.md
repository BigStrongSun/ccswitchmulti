# CCSwitchMulti v3.20.2-10

This build turns "proxy port is held by a listener we cannot verify" from a one-shot failure that needs manual work into a diagnosable, self-healing recovery, and carries the protocol/Provider fixes that landed on main.

## Port ownership diagnostics and automatic recovery

- A failed bind no longer only reports "listener identity could not be verified": it now reads every IPv4/IPv6 TCP row for the port, recording each owner's PID, state (LISTEN/TIME_WAIT/...), the executable path when readable, or the exact reason it could not be read (missing process / access denied / other Win32 error).
- Startup restore no longer clears the takeover state when the port is occupied. It registers a time-bounded intent (15 minutes by default) and the 5-second listener guard restores takeover automatically once the port frees up, then asks the UI to dismiss the stale failure notice.
- Fail-closed is unchanged: unverifiable processes are never terminated or taken over, and the manual "release port and restore takeover" action now shows the PID and the failure reason.
- Also fixed six double-encoded error strings in the provider switch path.

## Protocol and Provider fixes

- Manual protocol overrides are preserved, and valid probe evidence is restored before saving.
- The fix is limited to local routing and protocol probing; it does not change the semantics of an existing takeover.
