# CCSwitchMulti v3.19.2-2

## 修复 Codex 长时间网络波动仍会耗尽重连次数

`v3.19.2-1` 已支持上游真实 HTTP 429 自动等待并重发，但用户现场的失败并不是 OpenAI 返回 429。路由证据显示，同一时刻多个任务连续出现 TLS 握手 EOF；CCSM 原有的两次安全传输重试很快耗尽，错误随后被交给 Codex，连续占用了 Codex 自己的五次重连额度。最后一次连接在请求/响应边界中断，被 CCSM 的 `ResponsePending` 兼容状态映射为 429，因此界面显示了误导性的 `exceeded retry limit, last status: 429`。

本版本把 CCSM 内部、确认请求尚未到达上游的连接失败重试从 2 次扩展为 5 次，采用 200ms、600ms、1.5s、3s、6s 的有界退避。连接及 TLS 握手自身的等待时间也计入恢复窗口，因此短时边缘网络或 ChatGPT 网关波动会优先在 CCSM 内消化，不再过早消耗 Codex 线程的重连预算。

安全边界保持不变：

- 仅自动重放 `ForwardFailed`，即 DNS、TCP、TLS、连接超时或请求构造等确认尚未执行上游采样的失败。
- 上游明确 HTTP 429 继续遵循 `Retry-After`，最多 5 次、单次最多 60 秒、累计最多 180 秒。
- `usage_limit_reached`、`insufficient_quota` 等永久额度错误不会在同一账号空转。
- `ResponsePending` 表示请求可能已经到达上游，仍禁止 CCSM 盲目重放，避免重复采样、重复计费或重复副作用。

新增回归覆盖连续五次 TLS/连接前失败后第六次恢复，并保留 `ResponsePending` 不重放与真实 HTTP 429 的完整测试。
