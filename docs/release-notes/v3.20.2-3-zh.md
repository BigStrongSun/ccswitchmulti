# CCSwitchMulti v3.20.2-3

这是 `v3.20.2-2` 的定向修订版，修复 Codex 官方模型目录来源污染与无 OAuth 动态刷新、renderer 周期性高负载、OpenCode Go 深度探测会话身份，以及已保存路由 reasoning 声明丢失问题。数据库 schema 继续保持 v22。

## Codex 官方模型目录

- 官方模型身份现在由可信来源决定，不再依赖 `gpt-*`、`codex-*` 等名称前缀，因此未来新增的官方模型不会被旧规则误删。
- CCSM 接管产生的 `models_cache.json` 或旧版污染 backup 不再进入官方来源链；同步时会重建污染 backup 并清除 CCSM ownership，退出接管时不会把 Qwen、DeepSeek 等第三方条目恢复成官方目录。
- 即使没有在 CCSM 配置 ChatGPT OAuth，也会尝试刷新 OpenAI/Codex 公共 `models.json`。请求受 10 秒超时、8 MiB 大小、HTTP、JSON 与非空校验约束，失败时继续使用随包基线、可信本机 cache/backup 和当前 Codex CLI bundled 目录。
- 公共目录使用独立缓存并在落盘前剥离远程指令字段；同一模型仍由本机可信运行时来源覆盖元数据。GPT-6 Astra 和后续新模型不再依赖 OAuth 或等待 CCSM 按名称发版补录。

## Codex Desktop 性能

- renderer 兼容层不再每 1.5 秒同步枚举全部 DOM 并遍历大规模 React 对象图。
- 优先通过缓存模块轻量获取当前 app-server client；兼容扫描改为分片、单任务和退避调度，新增节点采用增量队列。
- 历史刷新完成后直接复用已发现的 manager 做 lineage hydration，不再在同一轮重复完整扫描；新版调度器会清理旧 interval 与 observer。

## 路由与探测

- OpenCode Go 直接深度探测复用最终出站的稳定会话身份策略，保留用户显式 session header，避免探测与真实请求身份不一致。
- 已保存的 Codex 路由现在从真实目标 Provider 保留 reasoning 能力声明，并且只投影该路由明确保存的 alias，不再受向导临时冲突别名影响。

## 边界与验证

- 本版本只修改 CCSwitchMulti，不修改或部署 Codex 本体，也不会自动重启 Codex、改写真实 Provider 或修复历史 SQLite。
- 聚焦 TDD 已覆盖官方目录来源、污染 backup 恢复、公共刷新、renderer 调度、OpenCode Go 会话身份与路由 reasoning 投影；完整发布门禁和跨平台资产结果以 GitHub Actions 与 Release 记录为准。
