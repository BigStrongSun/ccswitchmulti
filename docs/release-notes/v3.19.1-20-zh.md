# CCSwitchMulti v3.19.1-20

这是 v3.19.1-14 之后第一版面向 GitHub 的正式更新，集中交付 Codex Sub-Agent V1/V2 配置、登录与开机自启自愈、Windows 安全重装、小窗口布局，以及 Responses 断流错误可读性修复。版本没有数据库迁移，现有 Provider、路由、账号、会话和子 Agent 配置都会保留。

## 用户可见更新

### 1. Codex Sub-Agent V1/V2 可按方案选择

- MultiRouter 向导和工作台现在同时提供 `Sub-Agent V1（兼容）` 与 `Sub-Agent V2（推荐）`，每个方案只激活一种协议，切换版本不会删除另一套配置。
- V1 保留最多五个模型的 direct override 顺序，兼容旧版动态模型选择。
- V2 通过官方 custom role TOML 管理可扩展角色，不再把 Flash/Pro 模型名硬编码成固定能力；支持按角色配置模型、推理强度、沙箱和只读/复杂任务边界。
- V2 配置改为事务内原子保存，避免模型目录刷新与用户保存同时发生时覆盖刚编辑的 profile；畸形角色名、保留角色冲突和隐私敏感诊断均 fail closed。

### 2. 登录状态不再被过期请求覆盖

- 修复 OAuth device flow 已经完成登录后，较早发出的轮询或状态请求晚到并把界面重新标记为未登录/过期的问题。
- 登录状态更新带有生命周期与新旧顺序约束；启动后会主动对账真实账号状态，而不是只相信启动前缓存。
- 修复由此产生的“实际已经登录，但界面仍提示登录或授权过期”。

### 3. Windows 开机自启与升级重装恢复

- 修复事务式升级调用 NSIS 卸载器时删除 Windows `Run` 自启项，而应用设置仍显示已开启的问题。
- 启动时会对账设置、`Run` 与 `StartupApproved` 状态；配置要求启用但注册项缺失时会恢复当前安装路径。
- 任务管理器中用户明确禁用的状态仍会被尊重，不会在后台强行重新启用。
- 事务式重装增加进程句柄等待、目录边界、reparse point、SQLite 与失败回滚保护，避免误杀其他实例或在半安装状态继续运行。
- macOS 和 Linux 不会经过 Windows NSIS 删除链；本版没有宣称已经完成两端真实注销/登录验收。

### 4. 小窗口顶部操作不再被裁切

- 修复约 `900×600` 窗口下，全部应用入口、Codex 工具和“新增供应商”同时出现时，右侧按钮被 `overflow` 直接裁掉的问题。
- 应用切换器现在占用可伸缩中段，放不下的应用进入“更多应用”；当前应用始终可见，Codex 工具与新增按钮保留在独立右侧区域。
- 窗口放宽后会自动恢复全部应用入口，不需要重新打开页面。

### 5. Codex 断流显示真实类别

- 修复上游响应提前断开时，CCSwitchMulti 日志已经捕获具体原因，但 Codex 只显示 `error decoding response body` 的问题。
- 已输出正文或工具调用后仍然禁止自动重放，避免重复执行副作用；错误改为通过合法 Responses SSE `event: error` 返回，并干净结束本地 HTTP body。
- HTTP 分块响应提前关闭、真正的读取超时、其他传输中断和正文前自动重连耗尽现在会显示不同提示，不再一律伪装成响应体解码失败。

## 升级说明

1. 完全退出 CCSwitchMulti，包括托盘中的后台进程，再安装本版本。
2. Windows 用户若曾开启开机自启，升级后打开设置确认开关状态；可在维护窗口注销并重新登录做最终验收。
3. 登录页面此前错误显示过期时，升级后重新进入账号页，应用会按当前真实账号状态完成对账。
4. 使用 Sub-Agent V2 的用户可在 MultiRouter 方案中检查生成状态与角色预览；用户手写且不带 CCSwitchMulti marker 的 role 文件不会被删除。
