# CCSwitchMulti v3.19.1-23

本版本修复 `v3.19.1-22` 在新版 Codex Desktop 上可能生成无法解析配置的两个启动阻断。受影响用户可能看到：

- `AbsolutePathBuf deserialized without a base path in model_catalog_json`
- `duplicate field max_concurrent_threads_per_session`

这两个错误发生在 Codex 加载配置的最前端：模型目录还没有加载，V2 role 也无法被发现，因此 MultiRouter/Sub-Agent 链路尚未进入模型调用就已经停止。

## 修复内容

### 1. 修复模型目录相对路径不兼容

- CCSwitchMulti 过去会把生成的 `cc-switch-model-catalog.json` 以相对文件名写入 `model_catalog_json`。
- 新版 Codex 将该字段按绝对路径类型读取，相对路径会直接导致配置反序列化失败。
- 本版本在首次切换、MultiRouter 接管、模型目录刷新和 Provider 更新等投影路径中统一写入实际绝对路径。
- 旧版相对路径仍可被识别、迁移和清理，不要求用户手工删除配置文件。

### 2. 修复 Agent 并发字段重复

- Codex 目前将旧字段 `agents.max_threads` 视为 `max_concurrent_threads_per_session` 的兼容别名。
- 当配置已经包含新字段时，旧版 CCSwitchMulti 仍可能补写旧字段，造成两个名称反序列化为同一字段并报 duplicate。
- 本版本会优先保留用户的新字段值；只有新字段不存在时才迁移旧字段值，随后删除旧 alias，最终只写一个 canonical 字段。
- 用户已有的 `max_depth` 和自定义并发数量保持不变。

## 行为边界

- 这次修复位于 **config → catalog → role 投影链**，不是对第三方 child payload 兼容逻辑的再次修改。第三方 V2 child 仍使用既有的 mixed-router 明文协作、Provider 物化与 `agent_message` 投影链。
- 保存非当前 MultiRouter Provider 不会修改正在使用的 Codex live 配置、模型目录或 Agent 文件。
- 切回 OpenAI Official 时仍会按 Official Provider 自身的模型目录投影 managed roles；这属于既有多 Agent 行为，不是本次两个解析错误的来源。
- 上一版对 macOS 新版统一 `ChatGPT.app` 的发现和 MultiRouter 首次原子启用修复继续保留。

## 为什么这个版本重要

一个第三方模型要真正成为 Codex V2 child，需要先后满足：

1. Codex 能解析 `config.toml` 和 model catalog；
2. Parent 能发现并选择 custom role；
3. role 的模型请求能由 MultiRouter 物化到真实 Provider；
4. child 的协作正文能安全投影到目标 transport。

V23 修复的是前两步的入口阻断。如果 catalog path 或 Agent 并发字段无法反序列化，后面的路由和消息兼容即使实现正确也没有运行机会。

## 升级方式

1. 完全退出 Codex/ChatGPT app-server 与 CCSwitchMulti（包括托盘后台进程），避免旧进程继续持有旧 catalog/config。
2. 安装本版本；无需先手工卸载，也不要删除 CCSwitchMulti 数据库或 `~/.codex`。
3. 启动 CCSwitchMulti，重新切换一次当前 Codex Provider 或保存当前 MultiRouter，使 live 配置按新契约重新投影。
4. 完整重启 Codex/ChatGPT 并新建会话验证；旧会话不会自动重新读取全部 role 和模型目录。
