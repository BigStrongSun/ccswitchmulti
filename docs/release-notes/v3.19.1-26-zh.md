# CCSwitchMulti v3.19.1-26

这是 v3.19.1-26 的发布候选。它继承 v3.19.1-25 的 Windows Setup hotfix，并将 Provider 就绪、全局设置、MultiRouter 与 Sub-Agent 工作流收敛到同一条可验证的配置链路。

## 主要更新

### 1. Windows Setup hotfix 继续有效

- 完整继承 v25：未知第三方模型会写出必填的空 `supported_reasoning_levels`，不再因目录 JSON 缺字段使 Codex `config/read` 失败，从而阻断 Windows setup 重试前的正常启动链路。
- 此修复不会把 GPT 的通用推理档位重新套给未知模型；未声明能力仍保持保守、不注入 effort。

### 2. Provider 就绪与全局设置职责明确

- Codex Provider 表单始终呈现模型同步、默认模型、上游协议、连接验证和 MultiRouter 就绪结论；维护预设继续由 CCSwitchMulti 管理 `/model` 目录，但“由 CCSwitchMulti 维护”只表示元数据归属，不再把未经验证的当前凭据和端点标成就绪。
- 连接验证结果绑定到当前 Provider 的端点、凭据/账号、请求覆盖、协议、默认模型和模型目录能力；任一身份输入变化都会立即取消旧就绪，较早发出的探测即使更晚返回，也不能覆盖新身份的结果。
- 共享 Codex TOML 读取失败时改为 fail closed：显示真实错误和 Retry；成功读取前不挂载可编辑 TOML、Goal mode 或保存入口，避免占位内容覆盖真实配置。
- 全局设置只管理通用偏好和共享配置；Provider takeover、路由 TOML、模型目录与 `127.0.0.1` 本地入口仍由 CCSwitchMulti 的当前 Provider/MultiRouter 私有投影管理，不能写入共享 common config。

### 3. MultiRouter 四步向导与原地完成

1. 选择或新建目标 Provider，并初始化可路由模型与 V2 配置。
2. 同步模型、验证协议与连接，确认 Provider readiness。
3. 配置路由规则并启用本地接管。
4. 在状态工作台完成当前 Provider、监听端口、Codex 接管、路由入口和最近匹配转发的真实请求验证。

- 验证成功后保留在状态工作台显示结果，不会自动跳转 Sessions 或自动打开历史修复；历史修复仍是用户按需进入的独立工具。

### 4. Sub-Agent V1/V2 均保留

- V1 继续保留前五个 direct override 候选模型窗口。
- V2 继续根据完整可路由 profile/catalog 生成 managed roles，不受 V1 前五项限制；运行中的 Codex/app-server 仍需要重启并新建会话以获取新的 role snapshot。
- `inputModalities` 只持久化 `text` 或 `text + image`；已知模型从 catalog hydrate，未知模型保守不声明图像能力，并在手工覆盖路径提示图像任务的安全边界。
- 普通 Provider 的 `/models` 同步现在会端到端保留后端明确返回的 `inputModalities` 与 `supportsImage`，覆盖新增模型、已有模型、手动选择、Provider 保存以及 DB/live reload。即使没有 `inputModalities`，显式 `supportsImage: true` 与 `false` 也会独立保存；camelCase、snake_case 和 legacy `vision` 读入后统一为 camelCase，不会按模型名称或 modalities 猜测图像能力。

### 5. 配置写入后的 TOML 验证

- V2 initialize、reconcile 和普通更新统一确认数据库持久化、投影状态，以及每个 managed-role TOML 的绝对路径、存在性和精确内容回读。
- 当前 Provider 仅在 expected/actual TOML 一致时报告已应用；非当前 Provider 明确为 `not_required`，可重试状态保持 `pending_retry`。

## 已知非阻断边界

- 前端 catalog identity 的排序仍使用 `localeCompare`，与后端 NFKC + case-fold 尚未形成共享、完整、已测试的 Unicode 规范化契约；本轮没有加入不完整的 Unicode case-fold 补丁。
- Sub-Agent V2 reasoning effort 尚未从模型 catalog 端到端读取支持集合和默认值；只有在配置了上游不支持的 effort 时才可能在 Responses→Chat 能力校验中失败。本轮保留既有 reasoning defaults，不把条件风险误报为已验证故障或已完成修复。

## 升级与回滚

1. 从 GitHub Releases 下载与 `v3.19.1-26` tag 精确匹配的安装包；本地候选提交不等同于已上传或已签名资产。
2. 退出 Codex/ChatGPT app-server 与 CCSwitchMulti 后正常覆盖安装；不要删除 CCSwitchMulti 数据库、`~/.codex` 或用户自定义 role TOML。
3. 启动 CCSwitchMulti，保存当前 Provider 或 MultiRouter 方案，完成状态工作台验证；重启 Codex 并新建会话。
4. 如需回滚，只下载已发布的上一版本安装包并通过事务安装器执行备份、卸载/安装、恢复和健康验证；不要手动删除配置或直接复制未知来源的数据库。
