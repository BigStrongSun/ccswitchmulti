# CCSwitchMulti v3.19.1-4

## Codex 原生 Responses 流恢复

- 原生 Codex `/responses` 的 HTTP/SSE 连接在只收到 `response.created` 或 SSE 注释心跳后中断时，CCSwitchMulti 会对同一上游请求执行最多五次有界重连。
- 重连后的重复 `response.created` 会被抑制；推理静默期间每十秒发送 SSE 注释心跳，避免本地/客户端空闲 watchdog 误判为死流。
- 一旦已向 Codex 发出任何实质 Responses 事件（文本或 reasoning delta、output item、工具调用、完成/失败事件或无法识别的事件），不再重放请求。该边界防止重复工具调用和历史污染。
- 用尽重连次数时返回明确的流错误；不会无限保活或无限重试。

## WebSocket 边界

- Managed Codex 继续明确使用 HTTP/SSE。Responses WebSocket 仍返回标准 `426 Upgrade Required`，让 Codex 回退到 HTTP；本版本没有把尚未经官方端到端验收的 WebSocket relay 冒险启用。

## 验证

- Rust 流恢复回归覆盖：重连去重、注释心跳、`output_item.done` 禁止重放、显式上游失败与五次上限。
