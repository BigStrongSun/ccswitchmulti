# CCSwitchMulti v3.20.2-1

这是基于官方 `3.20.2` 语义迁移的 CCSwitchMulti 稳定版本，并加入 Trace 错误链修复和分页历史完整性恢复能力。数据库 schema 继续保持 v22，不引入迁移或降级要求。

## 官方 3.20.2 可靠性迁移

- URL 脱敏在 UTF-8 边界安全截断，避免多字节字符触发 panic；Claude workflow journal 不再产生幽灵会话，updater 保留真实错误 source 链。
- 补充 Novita model URL，并为已保存的 Novita/JieKou Anthropic 根地址提供精确 host fallback；用户显式 `modelsUrl` 始终优先。
- 可选 Provider presets、模型发现和价格选择器布局按 CCSM 现有所有权边界迁移；takeover 鉴权区分官方、Router、OAuth、文件、keyring 和临时身份，不修改 `auth.json`。
- 9 月价格变更因一手价格与活动期限证据不足而继续 deferred；预设源码契约通过不代表厂商在线服务已验证。

## Trace 诊断与界面状态

- 传输失败现在保留已脱敏的 reqwest source 链、失败分类和代理路径，不再只显示无法定位阶段的通用错误。
- 响应体 64 KiB 上限改为读取期间执行，覆盖 Content-Length、流式分块和精确边界。
- DNS 诊断与 HTTP 并发启动并限制为 2 秒；该上限仍可能计入完成等待，不宣称零延迟。
- 自动探测错误会显示给用户；新一轮手动探测先清除旧报告，失败刷新不再保留过期 Apply 操作。

## 分页历史完整性与恢复

- Provider 迁移、官方恢复、可见性修复和直接写入在首次修改前统一预检 JSONL 与 SQLite；分页、压缩、未知或证据不足的历史 fail closed，legacy 历史保持兼容。
- fork 仅要求活动段任务身份匹配；祖先可使用不同 ID，但 `history_base` 截止位置必须落在完整记录边界。
- 对旧 Provider 迁移造成的损坏，可依据 CCSM 自身迁移前备份逐记录重建 projection cursor 与 `history_base` 字节引用。只接受 Provider 字段差异；SQLite 使用事务 CAS，JSONL 保持长度和 mtime，失败时回滚。
- 真实本地数据只读预检识别到 442 个受影响 rollout、440 个迁移游标、16 个父段引用、共 4,897,657,672 bytes，以及 7 个仍需阻断的证据不足项。发布或安装本版本不会自动改写这些历史。
- Codex 自身的 ordinal 分配缺陷交由官方项目处理，本版本不修改或部署 Codex。

## 本地发布构建可靠性

- 每次本地 release 使用仓库内唯一的隔离 Cargo target，导出 sidecar、NSIS、portable 和 raw EXE 后调用 Cargo 清理，并恢复调用者原有环境。
- 修复 Windows PowerShell 5.1 把 `cargo clean` 的正常 stderr 进度误判为清理失败的问题；仍以 Cargo 真实退出码决定成功或失败，目录边界校验保持 fail closed。

## 边界与验证

- Qwen3.8 Responses Lite 的 `additional_tools` 兼容问题已在远端 vLLM 运行态修复，不属于 `v3.20.1-3..v3.20.2-1` 的 CCSM 产品代码增量。
- 源码、构建产物、GitHub Release、本机安装和当前运行实例是不同证据层；发布本版本不会自动替换或重启正在运行的 CCSwitchMulti 或 Codex。
