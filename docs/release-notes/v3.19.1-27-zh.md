# CCSwitchMulti v3.19.1-27

v3.19.1-27 在完整继承 v26 最终发布线的基础上，集中完成 Codex reasoning 能力统一、Sub-Agent V2 推理策略协调，以及长时间 ImageGen 请求的防重放保护。它不是对 v26 功能的重复打包：现有 v27 的 32 个独立提交已通过合流提交 `6fe99e9d` 与 v26 最终线汇合。

## 主要更新

### 1. 统一 Codex reasoning 能力来源

- Provider 原生支持档位、Codex 可选择档位、Provider 默认档位、关闭能力、来源置信度和 effort 映射现在由同一个 resolver 输出，模型目录、Sub-Agent role、预览/状态和请求转换不再分别维护推理档位。
- 未声明能力的第三方模型保持 unknown，不会继承通用 GPT 推理档位。
- DeepSeek V4 Flash/Pro 的维护能力为 Provider 原生 `low/high/max`、默认 `high`，并确认 `medium/xhigh -> high` 映射；不会凭空声明 `ultra`。
- 旧模型目录缺少 reasoning metadata 时仍可通过精确模型 ID 恢复维护能力，但显式目录能力始终优先。

### 2. Sub-Agent V2 推理策略与 UI 协调

- profile schema v2 将推理配置明确分为 `delegated`、`model_default`、`fixed` 和 `disabled`，不再把任务问卷隐式转换为固定 reasoning effort。
- legacy `auto` 平滑迁移为 delegated；legacy 显式 effort 与旧 override 迁移为 fixed，并保留字段优先级。
- role TOML、预览和状态页支持 `max`；具体可选值仍受目标模型的 capability 限制，unsupported effort 会 fail closed。
- UI 展示能力来源、Provider 接受值、Codex 可选值、默认值、映射和关闭能力；普通用户通过结构化选项配置，专家 JSON 在修改草稿前完成校验。
- v26 的父级 selection policy、preferred custom role 优先级、Codex 0.147 fork 兼容约束和 V1/V2 可逆切换全部保留。

### 3. 长时间 ImageGen 请求不再被错误重放

- Codex 图片生成/编辑是可能持续数分钟的非幂等 POST。过去 `connection_closed_before_message_completed` 被误归类为发送前失败并返回可重试 502，可能导致同一昂贵请求被再次提交。
- 现在只有 request builder 错误和 connect 阶段错误保留安全重试；请求已发送但结果未知时归类为 `ResponsePending`。
- ImageGen 的结果未知响应改为 HTTP 424、错误码 `cc_switch_image_result_unknown`、`retryable=false`，且不返回 `Retry-After`，防止 CCSM 和 Codex transport 重放。
- 共享 HTTP client 增加 HTTP/2 keepalive ping、ack timeout、idle keepalive 和自适应流控，降低长任务连接被中途回收的概率。

## v26 合流边界

- v27 原分支从 v26 的早期候选分叉。发布前已整体合入 v26 最终 30 个独立提交，保留 PowerShell 污染宿主修复、Tauri JS/Rust 配对、NSIS 安装态哈希推导、事务安装保护、图像能力持久化和 Sub-Agent 父级自动选型根修。

## 升级说明

1. 从本 Release 下载对应平台和架构的安装包，并核对 GitHub 服务端 digest 与 updater 签名。
2. Windows 覆盖安装必须由完整事务流程完成停止、卸载、安装、拉起、健康检查和失败回滚；不要在普通交互 shell 中单独结束 CCSwitchMulti。
3. 涉及 Codex Sub-Agent role 或模型目录变化时，保存当前 Provider/MultiRouter 后完整重启 Codex app-server，并新建会话读取新的工具与 role snapshot。
4. 不需要删除 CCSwitchMulti 数据库、`~/.codex` 或用户自定义 role TOML。
