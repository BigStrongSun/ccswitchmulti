# v3.19.2-18.6

## 修复

- **向导编辑不再弄脏子 Agent 数据（#78）**：编辑已有 MultiRouter 时，`buildCodexMultiRouterWizardPlan` 此前把 `subagentV2` 原样直通，而路由/目录已按消歧别名重建——profile 键与投影目录错位，产生孤儿/孪生 profile。现在构建时按 upstream 身份 + 旧路由别名把 profile 键与 `model` 字段重定向到新可见名（与后端 SyncCatalog 迁移同构：新身份被占用时不迁移；无关联条目原样保留，由等价映射/过期徽标兜底）。
- `spawnAgentModels` 候选在模型改名后先重定向到新可见名再过滤，不再静默丢失。

## 新能力

- **模型排序页支持移除模型**：每行新增「移除」按钮——目标 Provider 目录条目写 `enabled: false`，该模型从 Codex 选择器移除且不再被任何路由匹配（目录=路由表，fail closed）。条目保留在目标 Provider 目录，页面底部「已隐藏模型」列表可一键恢复。
- 模型目录 /models 刷新现在保留 `enabled` 标记，隐藏的模型不会被静默复活。

## 已知边界

- 模型排序页的移除对官方模型（gpt-5.4/5.5 等）同样生效。
- 路由别名收敛（旧 UUID 长名 → 拼音短名）仍需在工作台重新保存一次路由规则触发。
