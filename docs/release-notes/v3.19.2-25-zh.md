# CCSwitchMulti v3.19.2-25

这是 `v3.19.2-24` 之后的一次集中收口版本。它没有改变 Provider → MultiRouter → Codex 投影的基本架构，而是把第三方模型真实运行、历史任务恢复、运行接管、配置所有权和向导模型身份这几条链继续补到可验证、可恢复、不会静默跑偏的状态。

如果从 `v3.19.2-18` 或更早版本升级，Provider 分流、MultiRouter schema v2、V2 Sub-Agent、完整设置向导和双协议 Protocol Lab 的累计变化请同时参阅 [v3.19.2-24 完整说明](./v3.19.2-24-zh.md)。v25 在该基础上新增和修正以下内容。

## 1. 第三方 Responses / Chat 真实运行闭环

- Responses 工具调用不再读取 `response.output_item.added` 中尚未完成的空参数，而是等待 `response.output_item.done` 或 `response.completed` 的终态 item。DeepSeek 等长推理模型不会再因为首个增量事件参数为空而被误判为“不支持工具”。
- Responses 与 Chat 转换统一处理 namespace、工具名称、call id、增量参数、工具结果和终态；reasoning-only 提前结束、工具调用缺失终态、SSE 提前 EOF 都会明确报错或进入既定降级，而不是把未完成任务当成正常结束。
- 历史续轮仍严格区分原生 reasoning item、真实 `reasoning_text` content 和 omit。只有明确的 400/422 replay-shape 拒绝才允许降级，不把原始推理伪装成 summary。
- Qwen/vLLM、DeepSeek、Kimi/Moonshot 等第三方来源继续由同一 Protocol Lab preparer 生成探测和生产请求。模型映射、认证、Custom User-Agent、Header/Body override、工具 schema 方言、推理参数与请求预算进入同一指纹。
- Kimi/Moonshot 的严格工具 schema、DeepSeek 的 object-root schema fallback、第三方 SSE keep-alive 和错误分类保留；HTTP 521/5xx、网络、超时、401/403/429 仍属于可用性或认证错误，不能被保存成“不支持某协议”。
- 移除旧的运行时协议改写 helper。新 Provider、Provider Set 叶子和 schema v2 Router 只使用持久化规划；动态协议选择仅保留在明确识别出的旧版混合数据迁移链中。

## 2. Codex Provider 与历史任务恢复

- 历史任务的 Provider 恢复同时读取和修复 `session_meta.model_provider` 与后续 `thread_settings_applied.thread_settings.model_provider_id`。只改首行、随后又被设置事件覆盖的半修复状态不再复发。
- 历史列表保存并展示真实模型与 Provider；同一 rollout 内的 Provider 状态按事件顺序重放，避免第三方模型在恢复后重新落到官方 `openai` Provider，从而出现“模型不支持 ChatGPT account”的误导报错。
- Provider 桶迁移和历史修复会处理“SQLite 已迁移、JSONL 设置事件仍旧”的状态，同时保持原始 mtime、任务内容和不属于来源集合的其它会话不变。
- 历史时间统一以 RFC3339 绝对时刻转换为 epoch 毫秒，前端按当前设备本地时区显示，不再固定写死 `+8`，也不会因为 ISO 字符串缺失而把有效时间显示为 `-`。
- Provider 切换、活动 Profile、模型目录和持久化线程 Provider 现在使用同一规范化链；Qwen、DeepSeek 等第三方任务不会因为设备 current 与活动 Profile 的旧值不一致而漂回官方 Provider。

## 3. 运行接管、异常退出和配置恢复

- Windows 的 CCSwitchMulti 进程、AppContainer 投影、`ChatGPT.exe` 桌面壳和 `codex.exe app-server` 分开识别。关闭或刷新 Codex 不再使用可能递归误杀 CCSM 的 `taskkill /T`。
- 15721 端口恢复继续校验 PID、路径、启动时间与文件身份；只处理已证明属于旧 CCSM 的 listener，未知程序、PID 复用和二次抢占保持 fail closed。
- 正常计划退出、旧实例接管、异常退出和待恢复 marker 使用明确代际；旧告警不会无限重复，真实恢复失败仍保留到用户处理。
- “随 CCSwitchMulti 启动 Codex”继续位于配置投影、端口接管和复检之后。配置或运行态没有准备好时不会先启动 Codex 再补写 TOML。
- Codex 配置一致性只管理 CCSM 自己拥有的字段。`agents.*`、`desktop.*`、`developer_instructions`、MCP command/env、plugins、projects trust 与其它 Codex 自有字段保持原样，不再被误报为路由漂移。

## 4. CLI 环境变量注入改为可证明的所有权模型

- 设置页新增独立的 CLI 环境注入区域，可分别控制 Claude Code 与 Codex，配置需要注入的变量，并查看每个目标的同步、冲突、待处理和失败状态。
- CCSM 使用 `~/.cc-switch/env-injection-ownership.json` 记录自己实际创建的键。关闭功能时只删除账本能证明由 CCSM 创建、且当前值仍未被用户修改的键。
- 目标文件中原本存在的同名键，即使值恰好相同，也视为用户所有并显示冲突；不会因为“同值”就取得所有权，之后再误删用户配置。
- 用户修改了 CCSM 曾拥有的值时，CCSM 主动放弃该键的所有权，不覆盖、不删除；同步失败以结构化状态返回界面，不再只写日志却报告成功。
- Codex 同时支持 inline `shell_environment_policy.set = { ... }` 与 `[shell_environment_policy.set]` table；Claude Code 保留 JSON 中其它设置。Provider 投影与反向读取会剥离或重放账本证明的注入键，避免环境变量被 Provider 配置吞掉。
- 本功能实现的是 CLI 子进程环境策略，不改变模型推理强度，也不会把 API Key、OAuth Token 等敏感值展示到冲突摘要。

## 5. MultiRouter schema v2 防污染

- schema v2 route 只允许 `targetProviderId + modelSelection + aliases + authPolicy` 等当前契约字段。旧 Provider 快照中的 `authProvider`、endpoint、protocol、models 等继承字段不会再次写回 route。
- 通用 Provider 保存事务在写入 Codex schema v2 文档前统一清理被继承的旧 route 字段；不是只修某一个按钮或某一个 Provider 类型。
- DeepSeek 原生 Responses 的旧数据修复只处理 legacy schema。schema v2 文档在迁移入口即跳过，避免迁移器把顶层 Provider 字段扩散到每条 route，触发 `invalid_v2_schema`。
- 旧 schema 数据仍按原迁移路径兼容；当前严格校验不放宽，从根上阻止“为了保存成功而接受未知字段”。

## 6. 向导的模型身份和 V2 Sub-Agent 跟随

- Provider 模型别名、公开名或同名消歧变化后，向导会先通过旧 alias 找到稳定上游身份，再解析成新公开名。
- `subagentV2.profiles` 的 key、Profile 内的 `model` 与 `spawnAgentModels` 同步迁移；不会出现模型已改名，但角色 Profile 还挂在旧名称、保存后变成不可路由的状态。
- 目标名称已被用户占用时保留双方配置，不静默覆盖；暂时无法解析的 Profile 也保留给后续对账，不以删除用户设置作为“修复”。
- 完整 13 页向导和零 Provider 时的动态第 14 页保持不变；协议深探测、模型选择、排序、推理、Sub-Agent、路由、保存启用和真实验收仍按前置状态逐页开放。

## 7. 模型顺序页支持隐藏和恢复

- 模型顺序工作区的移除动作现在表示对目标 Provider 模型写入 `enabled: false`，不是只从当前数组临时删掉。
- 隐藏模型在同一页面的独立区域显示来源和恢复动作；即使所有模型都被隐藏，恢复入口仍然可见。
- 恢复只移除该模型的显式 `enabled: false`，让它重新跟随 Provider；不会重写别名、协议、能力或模型顺序。
- `/models` 目录刷新保留已有 `enabled` 状态，不会把用户隐藏的模型自动复活。

## 8. 分支、PR 与 Issue 收口原则

- 本版本逐一比较了仍存在的本地分支、worktree、开放 Issue 和开放 PR。有效缺口按当前主线架构重做并独立提交；旧分支中已经被主线演进替代、基于旧 schema 或会回退 Protocol Lab 的实现没有整分支合并。
- Issue #84 / PR #85 的环境注入方向被保留，但采用了新的所有权账本、冲突与失败模型；旧实现不直接合入。
- PR #75 中 #76、#78、#79 对应的有效问题分别以 schema v2 防污染、Sub-Agent Profile 重映射、模型隐藏恢复收口；不把旧 base 上的整包实现覆盖到当前主线。
- Kimi schema、严格 Responses reasoning、活动 Profile 同步和 macOS 进程识别均以当前主线已有的演进实现为准，不重复 cherry-pick 旧候选。
- 插件注册类 PR 仍涉及安装来源、权限与生命周期边界，未达到本版本的安全门槛，因此没有借发布名义强行合入。
- 两个旧工作树保留了已被主线替代的跟踪修改，另有多个工作树只有可再生成的 `.tmp`/target 产物。本版本不执行 reset/clean，不把无法证明归属的残留伪装成发布功能。

## 升级说明

1. 可以从旧版覆盖安装；Provider、Router、V2 Profile、模型目录、历史任务和用户自己的 Codex/Claude 配置不会因安装而重置。
2. 第三方 Provider 建议在升级后重新运行一次协议深探测；会发送真实请求并可能产生少量费用。Responses 和 Chat 结果独立保存，用户仍可在高级模式覆盖自动选择。
3. 若旧任务显示官方 Provider 或历史缺失，请完全退出 Codex 后从“历史修复”进入；修复会先备份 JSONL，并明确区分 Provider 状态迁移与 Renderer 历史可见性。
4. 环境注入初次启用时请先查看冲突列表。已有同名变量不会被 CCSM 接管，需要用户自行决定是否移除旧值后重试。
5. Codex 对外仍使用 Responses；Chat 是 CCSM 面向第三方上游的内部兼容传输，不要把 Codex Desktop 改成 Chat 客户端。
