# CCSwitchMulti v3.19.2-27

这是 `v3.19.2-26` 之后的 Codex Desktop 历史兼容性修复版本。重点解决“任务实际仍有完整 rollout，但 Codex 页面只显示较早的一小段历史”、历史修复在“验证运行状态”阶段提前失败，以及从设置向导进入 Provider 后返回主页的问题。

## 1. 主动检测 Codex 分页历史缺失

- CCSM 会对当前 Codex 活动任务执行轻量、只读的分页历史健康检查；确认存在异常时主动弹窗，不再要求用户先发现消息缺失再手工寻找修复入口。
- 检查区分三层状态：`config.toml` 与路由接管、Codex 分页历史投影、renderer 跨 Provider 历史查询兼容层。某一层异常不会再被混报成另一层故障。
- 弹窗明确说明：历史缺失来自 Codex Desktop 自身的分页历史/rollout 缺陷，CCSM 只是检测与修复工具，不会把问题错误归因成 CCSM 删除了历史。
- 日常检测只读取 active state、rollout metadata 和投影停点；只有用户确认修复后才会执行完整扫描、关闭 Codex 所需进程及恢复操作。

## 2. 修复重复 ordinal 导致的投影冻结

- Codex rollout 可能在 `token_count N` 后再次写入 `thread_settings_applied N`。Codex 的 `thread_history_1.sqlite` 投影遇到重复 ordinal 后会停止推进，页面因此只显示停点之前的消息。
- CCSM 现在只回退派生 SQLite 投影游标，让 Codex 从已核验的重复记录重新建立索引；不会为了绕过问题而改写 canonical rollout 对话正文。
- 验证期间如果后续又遇到另一个重复 ordinal，会继续定位并回退到新的安全停点，不再一直等待并最终报 `codex_paginated_history_projection_not_caught_up`。
- 大型历史文件的重建等待预算会按文件体量增长，最高 15 分钟，避免 1GB 以上 rollout 尚在正常重建时被误判失败。

## 3. 恢复同一任务被拆成多个 rollout 的历史

- Codex 崩溃、强退或恢复续写后，可能把同一个 `session_meta.payload.id` 写入多个物理 rollout 文件，而活动状态仍只引用第一段，导致后续对话存在于磁盘却不显示。
- CCSM 会在确认 Codex/app-server 完全退出后，按 ordinal 流式合并同一任务的物理分段；后续分段覆盖前一段已经中断的尾部，保留真正继续产生的消息。
- 修复前会把所有原始分段移入独立备份，再安装合并后的 canonical 文件，并在同一 SQLite transaction 中清理逻辑任务 ID 与物理分段 ID 的派生投影。
- 文件移动、合并、数据库清理或验证中任一步失败，都会恢复全部原始文件；不会触碰无关任务。

## 4. 修复历史兼容层验证的假失败

- 旧逻辑只读取一次 renderer 注入状态，但“全部 Provider 历史查询”补丁需要经过约 1.5 秒注入周期才能收敛，因此可能提前报 `codex_history_compatibility_not_ready`。
- 新版本会在 10 秒窗口内等待 renderer 状态收敛。按时完成即正常通过；超时则明确标记为“已完成但有警告”，不再把模型可见性已恢复的情况整体判为修复失败。
- 配置运行态、分页历史恢复和 renderer 兼容层分别给出结果，用户可以看到真正失败的阶段。

## 5. 保留设置向导中的 Provider 返回上下文

- 从 MultiRouter 设置向导进入 Provider 新建或编辑时，向导继续保留在原位置，Provider 编辑器在其上层显示。
- 保存或取消后返回原向导步骤，不再跳回主页并要求用户重新配置。
- Provider 列表和 Codex Router 工作区等原有入口继续保留各自的返回行为。

## 升级与使用说明

1. 可从 v26 直接覆盖升级，不需要删除 Provider、MultiRouter 或历史数据库。
2. 检测本身是只读的；真正修复需要安全关闭 Codex 和 app-server，因此 CCSM 弹窗后仍需用户确认，不会在后台静默中断正在进行的任务。
3. 修复过程会先备份原始 rollout。对于正在持续写入的任务，应先结束当前运行，再执行修复。
4. 修复完成后重新打开 Codex，等待分页投影追上文件尾部；超大历史的首次重建可能需要数分钟。
5. 本版本不会批量重写历史消息内容，也不会把 CCSM Provider 元数据写入 canonical 对话来伪造可见性。
