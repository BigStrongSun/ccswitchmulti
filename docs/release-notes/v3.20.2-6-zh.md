# CCSwitchMulti v3.20.2-6

这是 `v3.20.2-5` 的定向热修复版本，修复 Codex 分页历史 cursor 恢复在开始前全量复制 3.5 GB 投影数据库、导致 15 分钟超时的问题。数据库 schema 继续保持 v22。

## Codex 状态与修复

- Provider 迁移 cursor 恢复不再对 `thread_history_1.sqlite` 做全量 SQLite 备份。此前 5 页/25ms 的备份节奏约 800 KB/s，3.5 GB 数据库需要约 70 分钟，会触发 15 分钟保护并误报 `codex_paginated_history_repair_timed_out`。
- 现在只在 recovery 目录写入 `cursor-repairs.json`，记录受影响游标的 `sourceId`、旧/新 offset 和 expected ordinal，用于审计与人工恢复。
- 真正的 cursor 更新继续由单个 SQLite transaction、compare-and-set 和 boundary postcheck 保证原子性；JSONL `history_base` 文件备份、长度校验和失败回滚保持不变。
- 新增回归覆盖“只写游标快照，不复制 projection 数据库”。

## 验证

- `paginated_history` 24/24、`codex_runtime_refresh` 37/37。
- Rust 串行全量 4134 passed / 0 failed / 7 ignored；`cargo check --all-targets`、rustfmt 通过。
- 本版本只修复执行路径，不改变数据库 schema、不删除既有 recovery 证据，也不批量修改历史文件。
