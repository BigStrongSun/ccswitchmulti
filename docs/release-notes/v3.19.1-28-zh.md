# CCSwitchMulti v3.19.1-28

v3.19.1-28 是 v27 之后的体验与兼容性修复版本：重新收敛 MultiRouter 配置向导的职责，明确区分创建与编辑入口，并根治 Codex Desktop Windows `notify` 配置和 Sub-Agent V2 固定字段丢失造成的热切换失败。

## 主要更新

### 1. 配置向导不再堆叠 Provider 细节

- 进入向导前明确选择“创建新配置”或某一条具体的已有配置；打开选择器前刷新 Provider 数据，并按名称和 ID 展示真实目标，避免缓存顺序变化后编辑错方案。
- 向导只负责 MultiRouter 编排。Provider 凭据、模型目录、协议、reasoning、OAuth 和 hosted tools 返回各 Provider 自己的配置页面维护。
- 模型源卡片保留紧凑摘要和直达 Provider 配置的入口，移除面向开发者的状态机、续接规则等大段内部说明。

### 2. Sub-Agent V2 候选更清晰

- “从模型目录添加可配置项”默认只列出当前路由权威提供的第三方模型，避免官方模型与第三方候选混在一起使用户误判。
- 已存在的官方 profile 继续兼容，但集中放入明确的高级区域，不会被升级静默删除。
- 不可路由是中性可用性状态，不再用红色表现为错误；未启用的不可路由草稿不能误启用或编辑，已经启用后变得不可路由的 profile 仍可关闭。
- 深色和浅色主题继续共用现有 MultiRouter 视觉语义，不再使用突兀的纯白高亮边框。

### 3. 修复 Windows `notify` 导致的热切换失败

- Codex Desktop 的 Windows Computer Use 初始化流程曾生成 `notify = ["C:\\Users\\...", "turn-ended"]` 的错误变体：路径在 TOML basic string 中含裸反斜杠时，`\U` 会被解析为 Unicode 转义并使整个 Live 配置无法读取。
- CCSM 现在只在原 TOML 确实无效时，对首个 table 前、非多行字符串内、根级 `notify` 数组首参数中的 Windows 绝对路径补齐转义。
- 合法双反斜杠、单引号 literal string、多行 developer instructions、其他 table 和非 `notify` 语法错误保持原行为，避免宽泛替换掩盖真实配置损坏。

### 4. 普通 Provider 保存不再破坏 Sub-Agent V2

- 修复 Provider 表单只重建少数 `codexRouting` 字段的问题。普通保存现在保留 `subagentVersion`、完整 `subagentV2`、reasoning、字段级 overrides 以及未来扩展字段。
- schema v2 已知 reasoning 结构错误返回具体校验码，不再全部折叠为 `invalid_configuration`，方便直接定位缺失的 policy、effort 或能力不兼容。

## 升级说明

1. Windows 覆盖安装必须让 CCSM 完成停止、卸载、安装、重新拉起、健康检查和失败回滚的完整事务，不要单独结束正在提供路由的进程。
2. 不需要删除 CCSwitchMulti 数据库、`~/.codex` 或用户自定义 role TOML。
3. 保存 Provider/MultiRouter 后若变更了 Sub-Agent role 或模型目录，请完整重启 Codex app-server，并新建会话读取新的工具和 role snapshot。
