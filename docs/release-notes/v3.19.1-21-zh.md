# CCSwitchMulti v3.19.1-21

本版本继续完善 Codex MultiRouter 的 Sub-Agent 配置体验：把 V1/V2、能力问卷、模型目录、角色预览和诊断收拢到独立的“子 Agent”工作区，并完成与 MultiRouter 其他页面一致的深色/浅色彩色主题。现有 Provider、路由、账号、V1 排序和 V2 profile 会继续保留。

## 用户可见更新

### 1. 独立的子 Agent 配置工作区

- MultiRouter 顶部导航现在按“总览 → 模型源 → 路由规则 → 子 Agent → 状态 → 测试发布”排列；子 Agent 配置不再藏在路由规则页的高级区域。
- V1 与 V2 同页保留并明确说明用途：V1 是最多五个 direct model override 的兼容路径，V2 是基于 Codex 官方 custom role 的推荐路径。
- 当前协议显示灰色“已启用 V1/V2”，另一协议显示蓝色“启用 V1/V2”；切换后会提示重启 Codex app-server 并新建会话，避免把旧会话的工具说明误当成新配置。

### 2. V2 能力问卷与语义自动选型

- 普通用户可以用任务强项、优化目标、写入范围、角色偏好和推理强度五类问题生成能力画像，无需手写 TOML 或在每次委派时选择具体模型。
- CCSwitchMulti 将画像编译为 Codex custom role 的 `description`、`developer_instructions`、`model`、`model_provider` 和 reasoning；父 Codex 再依据任务语义选择内置角色、DeepSeek Flash、DeepSeek Pro 或其他已启用 profile。
- Flash 默认面向长上下文阅读、仓库探索、证据收集和轻量验证；Pro 默认面向复杂调试、架构设计、复杂实现和高风险审查。最终整合与发布判断仍由父 Agent 负责。
- 自动选型是 Codex 对角色说明的语义判断，不是 CCSwitchMulti 在代理层强制改写同一次 `spawn_agent` 调用；模糊任务仍可能选择内置 `default`、`worker` 或 `explorer`。

### 3. 全模型折叠配置与可理解的目录同步

- 模型能力列表改为可搜索、可筛选的折叠卡片；只有展开的模型显示完整问卷，长目录不再一次铺满页面。
- “从模型目录添加可配置模型”会把当前可路由模型加入配置草稿，新模型默认关闭，不覆盖已有问卷和手工字段。
- 卡片直接显示官方/第三方、已启用/待配置/不可路由、自动生成/手工覆盖等状态；模型暂时消失时 profile 仍会保留，恢复可路由后可继续生成 role。

### 4. 最终字段、TOML 与诊断可追溯

- 高级字段支持逐项手工覆盖角色名、description、developer instructions、昵称和 reasoning；单字段可以恢复自动值，也可以清除全部覆盖。
- “生成结果与 TOML”改为独立折叠区，展开后显示实际角色名、模型、Provider、reasoning、上下文窗口、角色文件路径、告警和完整 TOML。
- 用户手写且没有 CCSwitchMulti marker 的同名 role 文件不会被覆盖；发生冲突时会展示请求名称与实际 `ccswitch-<role>` 名称。

### 5. 深色与浅色主题统一

- 子 Agent 页面复用 MultiRouter 的蓝、青、绿、紫、红和琥珀语义色，不再是与其他页面割裂的黑白区域。
- 协议状态、策略、Provider 类别、模型可路由状态、能力标签、折叠区和 sticky 保存栏在深浅主题下均有一致的信息层级。
- 保存栏持续显示是否存在未保存修改；没有修改时明确显示“所有更改均已保存”，禁用按钮不会与主操作竞争。

## 升级与使用

1. 完全退出 CCSwitchMulti，包括托盘中的后台进程，再安装本版本；不要只覆盖正在运行的 EXE。
2. 打开 MultiRouter 的“子 Agent”页，确认当前协议。旧配置会保留；V2 旧方案可以使用初始化入口生成结构化 profile。
3. 修改问卷或手工字段后点击保存。切换 V1/V2 或修改 V2 role 后，请完整重启 Codex app-server，并用新会话验证。
4. 若要判断实际选型，请在状态页和 child rollout 中核对 `agent_role`、`model`、`model_provider`，不要只看界面是否生成 TOML。
