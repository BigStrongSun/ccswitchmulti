# CCSwitchMulti v3.19.1-21

本版本修复 macOS 新版 `ChatGPT.app` 内嵌 Codex 首次启用 MultiRouter 时，当前对话不可用、代理没有收到请求、生成错误 OpenAI managed roles，以及切换失败仍显示“启用成功”的组合故障。修复同时消除了 Windows 与 Linux 共用的非原子启用和吞错风险。

版本没有数据库迁移，不需要先卸载、清库或删除 `~/.codex`。现有 Provider、MultiRouter 方案、OAuth 账号、会话、数据库和用户手写 agent 文件都会保留。

## 修复内容

### 1. MultiRouter 首次启用改为目标优先的原子事务

- 旧向导会先启动代理、用当前 Provider 接管 Codex，再切换目标 MultiRouter。如果启用前使用 OpenAI Official，官方模型目录和 legacy managed roles 会先被写入，随后才尝试热切换目标。
- 新版不再提前接管旧 Provider，只发起目标 Provider 切换。后端在同一个 app switch lock 内完成代理启动、live 备份、目标 current provider、目标配置接管和激活验证。
- takeover 写入或验证失败时恢复之前的 current provider 和 live config，不再留下“界面成功、实际未收敛”的半接管状态。

### 2. 启用失败不再被向导吞掉

- Provider action 现在返回明确的 success/error outcome。
- 后端切换失败时，MultiRouter 向导保留在失败步骤并显示原始错误；不会继续派发 `ENABLE_SUCCESS`、关闭向导或打开伪成功状态页。
- 普通 Provider 页面仍保留原有 toast 提示和使用方式。

### 3. macOS 支持新版 ChatGPT.app 统一壳

- Codex Desktop 已从旧 `/Applications/Codex.app` 迁移到新版 `/Applications/ChatGPT.app`，但 bundle identifier 仍是 `com.openai.codex`。
- CCSwitchMulti 现在以 `com.openai.codex` 和 `Info.plist` 的 `CFBundleExecutable` 识别真实应用与主程序，不再假设目录和可执行文件一定都叫 `Codex`。
- 运行进程、`/Applications`、`~/Applications`、remembered path 和 Spotlight 都兼容 `Codex.app` 与 `ChatGPT.app`。
- 独立 ChatGPT 应用不会因为同名而误入 Codex CDP 修复链；Windows 继续只接受 `OpenAI.Codex` MSIX 下的 `ChatGPT.exe`，Linux 现有 Codex/AppImage 发现逻辑保持不变。

### 4. 原子接管补齐 Desktop 生命周期收尾

- 通过 Provider switch 完成的原子接管现在与手动 takeover 使用同一个 Codex post-takeover lifecycle。
- 只有在 takeover 激活验证成功后才启动 guardian 和模型菜单修复。
- Desktop executable/CDP 注入仍是 best-effort：失败会留下明确诊断，但不会把已经验证成功的 HTTP 路由改判为失败。

## 为什么此前不是所有 macOS 用户都会遇到

完整故障需要同时满足：新版 `ChatGPT.app`、从向导首次启用、启用前 current provider 不是目标 MultiRouter、尚未 takeover，并继续使用未重载的当前会话。仍使用旧 `Codex.app`、已经接管、从 Provider 列表直接切换或启用后立即重启的用户，可能只遇到 warning 或完全绕开状态污染。用户的 V2 配置不是根因，只是触发了这条缺陷路径。

## 升级与恢复步骤

1. 若当前仍处于异常 takeover，先在 CCSwitchMulti 关闭 Codex 接管并恢复 OpenAI Official。
2. 正常通过应用内更新或安装本版本；不需要先卸载，也不要删除数据库或整个 `~/.codex`。
3. 完全退出 ChatGPT/Codex Desktop，包括后台进程，然后重新打开 CCSwitchMulti。
4. 重新进入已保存的 MultiRouter 方案，点击启用。
5. 完全重启或新开 ChatGPT/Codex 会话，确认状态页“当前链路、监听、Codex 接管、路由入口、最近转发”均成功。
6. 此前由 CCSwitchMulti 生成的 stale managed roles 会在目标 Provider 成功同步时按现有 marker 规则收敛；不带 CCSwitchMulti marker 的用户自建 role 不会被删除。
