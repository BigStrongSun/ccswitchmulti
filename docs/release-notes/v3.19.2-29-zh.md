# CCSwitchMulti v3.19.2-29

本版本改进 Codex 模型兼容性探测、向导草稿保留与混合协议配置的编辑体验。

## 协议探测与适配说明

- 深度探测使用有限并发：前端最多同时处理 2 个模型源，后端每批最多处理 3 个模型；Responses 与 Chat 分支并行验证，避免所有请求串行等待。
- 界面展示原始响应与目标格式的差异、自动适配动作和实际重试进度。适配说明由真实探测证据生成，不把尚未验证的处理说成已经修复。
- 重新探测期间只显示本轮进度和结果，旧的已保存 Verified 不再覆盖运行中或失败状态；历史结果仍可单独查看。
- 认证错误、限流、网络问题和上游故障与协议不兼容分开呈现。

## 配置向导

- 未保存的向导草稿在当前应用会话内保留；离开再回来可以继续，退出应用后不保证保留未保存草稿。
- 探测结束无需立即保存。可以取消勾选失败模型，保留通过验证的模型，继续到最终保存页；取消的模型在最终保存时停用。
- 编辑已保存方案时，自动复用仍有效且与当前模型源完全匹配的探测证据，不必每次重测；仍提供主动重新探测入口和请求费用确认。
- 已消耗的提交凭证可以从有效持久化证据重新签发，不修改原验证时间与过期时间。地址、密钥、模型或相关请求策略改变，以及证据缺失或过期时，需要重新验证。
- 修复保存后的规范化回读被误判为外部配置变更，造成“已经探测却仍要求探测”的问题。
- 批次保存会在模型源和协议叶子展开后校验 Sub-Agent，避免用旧目录误报已选模型不存在；校验失败后可以修正并再次保存。
- 修复最终验收页“关闭”和“打开状态页”未收起向导的问题；退出只保留草稿，不伪造验收完成状态。
- 通用配置更新和工作台目录写回不再隐式触发兼容性探测，也不再延长旧证据的有效期。证据失效时明确要求主动探测；混合协议源需要通过模型源编辑器或配置向导确认保存，不能由后台目录刷新静默重分组。

## 混合协议模型源

- Kimi 等模型源的内部协议适配入口不再列为用户创建的 MultiRouter 方案。
- 编辑时展示逻辑模型源和完整模型目录；运行时仍保留按协议拆分的内部配置，不删除正在被外层路由引用的记录。
- 混合协议配置保存后重新打开，也可以复用其已有有效证据。
- 修复恢复证据后底部“下一步”仍被旧状态拦截，以及未选择的同名模型源造成 Kimi 已选模型丢失的问题。
- 保存回包同时提供逻辑编辑视图，连续保存不再依赖查询刷新时序，也不会因内部叶子路由而丢失旧模型别名。
- 内部配置归属异常、路由目标被改动或缺少归属标记时，拒绝不安全的编辑还原，不静默改变实际路由含义。
