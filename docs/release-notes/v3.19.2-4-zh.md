# CCSwitchMulti v3.19.2-4

## 修复 Codex V2 子 Agent 前五模型排序

Codex 当前只在 `spawn_agent` 工具说明中宣传模型目录排序后的前五个模型。此前 CCSwitchMulti 虽然按用户配置重排了模型数组，但同 slug 的官方 GPT 元数据会再次覆盖路由目录生成的 `priority`，导致 Codex 仍把五个 GPT 放在最前面，`qwen3.8`、DeepSeek 等第三方模型无法进入工具说明。

本版本让 CCSwitchMulti 的路由目录拥有模型选择器排序所需的 `priority`，同时继续保留官方模型的 transport、reasoning、service tier 和展示元数据。V1 与 V2 共用同一套前五模型顺序；V2 工作台明确分为“配置模型与能力”和“选择工具说明前五模型”两步，完整模型目录与 V2 managed roles 不会因前五选择而被删除。

新增回归测试同时断言最终 catalog 的模型数组顺序和连续 priority，避免再次出现“文件看似已重排、Codex 实际仍按旧优先级排序”的假成功。

## 修复 MultiRouter 接管时 Common Config 丢失

MultiRouter 使用 `codexRouting` 和 `modelCatalog` 保存路由状态，不保存普通 Codex Provider 的完整 `settings_config.config`。旧的 Common Config 启用推断依赖完整 Provider TOML，因此无法识别 MultiRouter，可能让局部接管投影成为 live 配置和恢复备份的唯一基底，造成 reasoning、MCP、桌面、memory、approval 或 sandbox 等用户配置丢失。

本版本把完整 Common Config 作为 MultiRouter 最终投影的用户配置基底，再通过 `toml_edit` 结构化合并现有 live/恢复备份，并只让路由器覆盖其拥有的模型、Provider 和 catalog 字段。显式关闭 Common Config 仍然生效；未知用户字段、Matrix 等 MCP 配置和 reasoning 档位在接管、热切换与恢复备份中都会保留。

新增回归测试覆盖无普通 TOML 的 MultiRouter、显式 opt-out、Common Config materialization、未知 desktop 字段保留、MCP 合并、恢复备份与 Codex 热切换。
