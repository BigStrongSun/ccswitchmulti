# CCSwitchMulti v3.20.4-15

## Codex 容量错误自动续跑

- 修复通用 `error.type` 遮蔽明确容量 `error.code` 的问题。`service_unavailable_error` 与 `server_is_overloaded` / `slow_down` 同时出现时，可以正确进入容量恢复。
- 修复空的 `response.in_progress` / `response.queued` 进度事件被误判为实质输出的问题，正常的 Responses 生命周期不再提前关闭重放资格。
- 容量恢复仍使用同一 Provider 和独立的最多 10 次重连预算。已经交付正文、推理或工具调用后不重放；额度、认证、权限、策略和参数错误不进入容量重试。普通传输恢复仍由原生 Codex 客户端负责。
- 新增脱敏的容量决策日志，区分非容量错误、开关关闭、已有输出、缺少重连器、开始重试和预算耗尽，不记录错误正文或凭据。

## 图片与账号池

- 图片模型未出现在文本目录时，`/images/generations` 和 `/images/edits` 专用入口保留 OpenAI Official 身份兜底。收回此前候选在共享 resolver 中的过宽兜底，普通 Responses 和通用 raw 入口仍按目录选择模型，显式第三方图片路由仍优先。
- 修复官方账号池额度刷新失败时错误延长旧快照新鲜度的问题。额度尝试时间和成功观测时间分离，避免 `POOL-001` 持续误判空池；保留官方额度硬边界、凭据代际校验和刷新节流。

## 发布构建

- macOS 构建切换到受支持的 `macos-15` runner，继续生成 Intel / Apple Silicon 通用包；应用最低系统要求仍为 macOS 12。

本版没有更改数据库 schema。安装并由新进程加载后修复才生效；已经结束的 Codex 任务需要重新发起继续操作。持续容量不足仍可能耗尽有限预算，不会无限重放。
