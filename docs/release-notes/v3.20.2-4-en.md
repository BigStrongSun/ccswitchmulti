# CCSwitchMulti v3.20.2-4

This is a focused revision over `v3.20.2-3` that makes the Codex "Status & Repair" refresh observable and detects stalled work instead of leaving the UI in progress forever. Database schema remains v22.

## Codex Status & Repair

- Refresh progress is no longer just a stage name: closing processes, waiting for exit, paginated-history scan/migration/per-file repair, config reprojection, launch, and verification emit concrete log entries.
- Long operations emit a heartbeat every 2 seconds. The UI now shows a repair progress log, last activity time, and elapsed time for the current stage.
- Paginated-history repair has a 15-minute hard timeout, so a stuck file/SQLite operation no longer leaves the command pending forever.
- The frontend has a 30-second event-silence watchdog. A silent backend now fails visibly instead of continuing to show "refreshing".
- Each refresh run uses its own run id, so a late backend result cannot overwrite a stall failure. Sequence numbers and timestamps discard out-of-order or duplicate events.
