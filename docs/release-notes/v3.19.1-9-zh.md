# CCSwitchMulti v3.19.1-9

本版本修复 Codex 同一对话中在 OpenAI 官方模型、Qwen Chat 与 DeepSeek Responses 之间切换时，历史 reasoning 和 web search item 被目标接口拒绝的问题。修复针对跨 Provider 回放边界，不会删除官方加密 reasoning，也不要求清空对话或重新配置 Provider。

## Codex 跨模型切换修复

- 修复 Qwen Chat 切回 OpenAI 官方模型时，合成 reasoning 的 `rs_resp_chatcmpl-*` ID 被官方当成未持久化对象引用，导致 `Item with id ... not found` / HTTP 404。
- 修复 DeepSeek native Responses 切回官方模型时，plain reasoning 携带 UUID `id` 与 response-only `status=completed`，导致官方拒绝 `input[*].status` / HTTP 400。
- 修复 DeepSeek 等第三方 Responses 返回 `web_search_call id=call_*` 后切回官方模型时，官方要求 `ws_*` ID 而返回 HTTP 400。
- 修复 MultiRouter 官方 route 使用 managed Codex OAuth 时，因 route 物化后的临时 Provider ID 未被识别为官方 Provider，导致上述 replay normalizer 没有执行的问题。

## 回放兼容边界

- 第三方未加密 plain reasoning 回放给 ChatGPT Codex OAuth 时，仅移除不能跨 Provider 使用的 `id` 与 `status`，保留可读 reasoning summary。
- OpenAI 官方返回且带 `encrypted_content` 的 reasoning 完整保留，不改写官方密文、ID 或状态。
- 第三方 `web_search_call call_*` 使用确定性映射转换为 `ws_ccswitch_<hash>`，同一历史 item 在重试时保持相同 ID。
- 归一化按真实 OAuth transport 执行，而不是依赖易变化的 MultiRouter route Provider ID，因此官方 seed、直接官方 Provider 和 managed OAuth route 使用同一兼容边界。

## 升级方式

可在应用内“设置 → 关于 → 检查更新”升级，也可从 GitHub Release 下载对应平台安装包覆盖安装。升级不会改写已有 Provider、MultiRouter 路由、OAuth 账号或 Codex 对话历史。

- Windows x86_64 / ARM64：Setup.exe 或 Portable.zip。
- macOS：DMG 或 ZIP。
- Linux x86_64 / ARM64：AppImage、DEB 或 RPM。
- `latest.json` 和签名 updater 包供应用内自动更新使用。

## 能力边界

本版解决的是第三方 response item 回放到 OpenAI 官方 Responses transport 时的已确认协议不兼容。模型服务自身的额度、账号、网络或非重试型上游错误仍会如实返回；CCSwitchMulti 不会用 `store=true` 隐藏错误，也不会伪造 OpenAI `encrypted_content`。
