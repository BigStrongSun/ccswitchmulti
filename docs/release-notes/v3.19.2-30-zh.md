# CCSwitchMulti v3.19.2-30

本版本汇总 v3.19.2-29 之后已经完成并合入主线的可靠性与模型兼容改进。重点是让新的官方模型参数、协议验证、错误证据和 Codex Desktop 历史恢复使用同一套可追溯事实，不把推测或过期配置当成当前能力。

## 官方模型参数与协议适配

- 官方 OAuth 模型目录的推理等级、默认等级、工具能力和输入模态继续作为高优先级运行事实；模型别名或第三方 Provider 不再把静态模板误当成官方实时元数据。
- 新的 GPT-6 Astra 可保留官方目录给出的五档推理等级和默认等级；旧配置中的 `none` / `minimal` 会迁移到 Astra 支持的最低有效等级，而不是继续写入无效值。
- 模型目录刷新、Provider 编辑、MultiRouter 投影和 Sub-Agent 预览共用同一套规范化元数据，避免界面显示正确但实际路由仍使用旧参数。
- 自动协议选择只采用完整验证为 Verified 的分支；用户仍可显式选择尚未完整适配的 Chat 或 Responses 分支，但界面会保留真实能力缺口，不把手动选择伪装成自动验证成功。
- 工具 Schema 与推理历史适配必须完成真实重试闭环才会标记成功；探测界面显示脱敏的触发原因、结构调整和复测结果。

## 错误证据与流式请求

- 保留上游 SSE 的终止错误、HTTP 状态、请求阶段和重试原因，避免真实拒绝被折叠为笼统的 `stream closed before response.completed`。
- 默认记录有界、脱敏的错误证据日志；不保存 API Key、Cookie 或完整响应正文，并提供范围明确的导出脚本用于诊断。
- 对确定性的协议或请求错误停止无意义重试；仅在有证据表明可恢复时进入流式重试。

## Codex Desktop 历史与运行环境

- 按活动 lineage 恢复分页历史，并在 canonical history 被截断或分片时重建 renderer 缓存；不把可读取的单条会话误当成侧栏索引已经完整。
- Desktop 辅助进程隔离标准输入输出句柄，避免后台诊断或刷新过程继承当前终端而阻塞退出。
- 可自动检测 Codex 请求看到的出口时区差异，并在用户启用后把匹配的 IANA 时区安全应用到受管 Desktop 子进程；网络失败有退避，不对每个请求重复探测。
- 时区功能只解决运行环境一致性与可诊断性，不承诺绕过任何未公开的服务端路由策略。

## 发布边界

- 本 Release 只包含已经进入 `main` 的完成项；`codex-power-presets`、`codex-multirouter-ssot-v2`、`codex-reasoning-probe-backend`、`error-journal-20260904` 和 `ccsm-agent-mesh` 的未提交或未完成工作没有混入。
- 官方上游当前已有 v3.20.x 历史；CCSwitchMulti 与上游长期分叉较大，直接合并存在广泛冲突。本版本没有把未经逐项迁移和回归验证的上游提交冒充为已同步，后续会按独立迁移审计处理。
- 源码测试、GitHub 多平台构建、公开 Release、资产摘要与本机安装态是不同证据层。本次发布不停止或替换当前机器上的 CCSwitchMulti，也不重启 Codex Desktop。
