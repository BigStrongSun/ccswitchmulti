# CCSwitchMulti v3.19.1-24

本版本修复 Codex MultiRouter 为第三方模型生成错误推理强度的问题，并把原先分散在 Provider 预设、模型目录和请求转换中的能力声明统一为逐模型契约。保存或切换 MultiRouter 后，不再把 DeepSeek 等模型错误覆盖成 GPT 的通用档位。

## 主要更新

### 1. DeepSeek V4 使用官方推理档位

- `deepseek-v4-flash` 与 `deepseek-v4-pro` 统一使用 `low / high / max`，默认 `high`。
- 外部 `models.json`、Codex Desktop 兼容字段、`config.toml` inline models 和托管 Sub-Agent role 由同一能力源生成。
- MultiRouter 再次保存、切换 Provider 或刷新模型目录时，也会保持正确档位，不再恢复成 `low / medium / high / xhigh`。

### 2. 内置 Provider 按模型和协议准确适配

- DeepSeek V4、Grok 4.5、GLM-5.2、StepFun 等内置模型分别声明自身支持的档位、默认值、关闭语义与上游参数映射。
- 模型目录展示、默认选择、MultiRouter 路由物化和实际出站请求共享同一解析结果，避免“界面可选但上游不支持”或“界面与请求不一致”。
- GLM 等兼容档位会按维护的映射转换；Step 等未声明档位会在本地给出明确错误，不再静默猜测。

### 3. 不再为只有 thinking 开关的模型伪造档位

- Kimi、Qwen、MiniMax、MiMo、SiliconFlow 等只有布尔 thinking 开关的已维护路径不会显示虚假的 `low / medium / high / xhigh` 菜单。
- 聚合平台能力优先于模型原厂默认，例如 SiliconFlow 的 `enable_thinking` 与 OpenRouter 的 `reasoning.effort` 分别按平台协议处理。
- 未核实的第三方模型采用保守策略：不继承 GPT 档位，也不主动注入推理强度。

### 4. MultiRouter 完整保留目标 Provider 能力

- 向导生成、Provider 更新、已有 Provider 读回、模型别名和 upstream model 路由都会保留逐模型 reasoning 配置。
- 使用 CCSwitchMulti 内置预设时，MultiRouter 自动获得该预设的维护能力；不需要用户再手工修改生成后的 `models.json` 或 `config.toml`。

### 5. 支持高级自定义覆盖

- 自定义 Provider 可在模型目录高级区域编辑 reasoning JSON，配置支持档位、默认值、关闭语义和上游映射。
- 内置预设默认只读，避免误改维护值；需要偏离时可显式“创建高级覆盖”，界面会标记已偏离，并可一键恢复当前版本的内置默认。
- 保存前会校验默认档位、`none` 关闭语义和 `effortMap` 完整性，非法配置不会静默落库。

## 与 v3.19.1-23 的兼容性

- v23 的 Codex `model_catalog_json` 绝对路径修复、Agent 并发 alias 迁移、Sub-Agent V1/V2 工作台、MultiRouter 原子启用、更新器代理检查和 macOS `ChatGPT.app` 兼容均完整保留。
- 已有自定义 Provider 若未声明逐模型能力，会继续使用保守兼容策略；旧 `codexChatReasoning` 仅在模型级能力缺失时作为 legacy fallback。

## 升级方式

1. 完全退出 Codex/ChatGPT app-server 与 CCSwitchMulti，包括托盘后台进程。
2. 安装本版本；无需先卸载，也不要删除 CCSwitchMulti 数据库或 `~/.codex`。
3. 启动 CCSwitchMulti，重新切换一次当前 Codex Provider，或保存一次当前 MultiRouter 方案，使模型目录按新能力契约重新生成。
4. 完整重启 Codex/ChatGPT 并新建会话，确认目标模型只显示其真实支持的推理档位。

## 已知边界

- 推理强度由 Codex 根据模型目录允许用户选择，并作为请求参数发送；实际如何解释和执行该档位由目标 Provider/模型协议决定。CCSwitchMulti 负责提供正确能力、验证选择并做必要的协议映射，不会在本地模拟模型推理。
- 本轮源码和完整测试在 Windows 主机完成；GitHub Actions 会继续验证 Windows、macOS 与 Linux 构建。正式 Release 成功不代表用户机器已经自动安装本版本。
