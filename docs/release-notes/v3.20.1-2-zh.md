# CCSwitchMulti v3.20.1-2

本版本是在 `v3.20.1-1` 完整迁移与发布基线上的小版本修复，集中处理 Codex OAuth 旧账号状态误判和无效刷新操作。数据库 schema 继续保持 v22，不引入新的迁移或降级要求。

## Codex OAuth 状态根修

- 旧版自管账号仍可能持有可用 token，但缺少新版要求的 `chatgpt_account_id` 或 `id_token.sub`。此前额度查询把这类身份升级需求统一显示为“会话已过期”；现在新增独立的“需要重新认证”状态，不再把身份资料缺失伪装成凭据失效。
- 只有 refresh token 被明确判定无效时才显示“会话已过期”。Device Code 本轮授权到期、用户拒绝、临时网络失败和 token 请求失败不会污染既有账号的凭据状态。
- 额度卡不再为身份升级场景显示无法解决问题的圆形“刷新”按钮，改为该账号专属的“重新认证”操作；认证进行中会禁用按钮并显示进度，避免重复发起流程。
- 重新认证成功后会立即失效 Codex OAuth 账号状态和额度缓存，界面无需重启或等待旧缓存自然过期即可重新查询。

## 协议探测与保存边界

- `v3.20.1-1` 已包含的协议探测修复继续保留：Partial/Unverified 模型可以由用户明确选择“仍然使用”或排除后保存，已有且仍有效的证据可以复用，不要求每次编辑都重新探测。
- 新建 Codex MultiRouter 供应商仍需先取得一次协议证据；本版本没有取消这条安全门禁，也不会把手动采用的失败分支标记为 Verified。

## 验证与运行态边界

- 新增后端错误分类、旧账号有效 token、定向重新认证 UI 和 React Query 缓存失效回归。
- 源码测试、本机构建、GitHub 多平台 CI、公开 Release 与本机安装运行态是不同证据层；本 Release 的发布不代表当前运行中的 CCSwitchMulti 已被替换或重启。
