# CCSwitchMulti v3.19.0-7

## 新增内容

- 新增 hosted `image_generation` 桥接：Codex 的 `{type: image_generation}` 对第三方 Chat 上游会转成普通 `generate_image` function tool，由 CCSM 使用独立 OpenAI hosted 凭据执行；base64 图片结果解码后保存到临时 `cc-switch-hosted-tools` 目录，只把本地路径和元数据交回模型。
- hosted web_search / image_generation 共用工具循环的扫描、执行、回灌逻辑；执行凭据优先复用已登录 Codex OAuth，显式配置 `CCSWITCH_HOSTED_TOOLS_OPENAI_API_KEY`、`CCSWITCH_HOSTED_TOOLS_OPENAI_BASE_URL`、`CCSWITCH_HOSTED_TOOLS_OPENAI_MODEL`、`CCSWITCH_HOSTED_TOOLS_TIMEOUT_MS` 时使用独立 OpenAI key。
- MultiRouter 工作台的“多路路由设置”和设置向导“配置核心参数”步骤新增 Web Search / Image Generation 两个 hosted tool 开关；默认开启，可在方案级单独关闭。

## 修复内容

- CCSM 代理内新增同一 Provider 传输重试：在流建立前遇到连接失败、请求构造失败或发送阶段失败时，使用已转换好的同一请求体重试 2 次，退避 200/600ms；仍失败才返回 502。
- 适用范围：Codex Responses、Chat Completions 以及原始 OpenAI-compatible 透传路径。
- 安全边界：`ResponsePending/429` 仍不重试，避免重复执行可能已经到达上游的请求；SSE 建立后仍不自动整轮重放。
- Codex 客户端 `request_max_retries=2` 继续作为第二层兜底，覆盖网络恢复后从客户端重新发起的场景。
- 修复 Kimi K3 等 Chat 上游在 Codex MultiRouter 下含 hosted `web_search` 时“发消息后无回复”的问题：此前本地工具循环会强制上游非流式，缓冲完成后只回一个 `response.completed`，Codex 不把它识别为正常 assistant turn。现在会完整重放 `response.created -> in_progress -> output item added/delta/done -> completed` 生命周期。
- 对齐缓冲响应的工具事件：function_call / tool_search_call 按 `in_progress added -> arguments done -> completed done` 重放，custom_tool_call 补齐 `custom_tool_call_input.delta/done`。
- Codex 路由日志新增 `upstream_stream` 字段，与客户端声明的 `streaming` 分开记录，hosted web_search 缓冲路径不再用 `streaming=true` 误导排障。
- codex_oauth / Responses SSE 上游在 HTTP 200 后、下游尚未收到实质内容前中途断流时，代理侧自动重连最多 5 次，退避 200/400/800/1600/3200ms，对齐官方 Codex CLI `stream_max_retries`；上游已返回语义错误或实质内容已转发时不再重试。
- GPT-5.x 长思考不再因“合法静默”被空闲计时器误杀：codex_oauth 开启 thinking 时兜底请求 `reasoning.summary:"auto"`，转换流在思考静默期每 10s 发一次 `ping`，连续静默 5 分钟后停止保活。
