# CCSwitchMulti v3.19.0-7

## 修复内容

- CCSM 代理内新增同一 Provider 传输重试：在流建立前遇到连接失败、请求构造失败或发送阶段失败时，使用已转换好的同一请求体重试 2 次，退避 200/600ms；仍失败才返回 502。
- 适用范围：Codex Responses、Chat Completions 以及原始 OpenAI-compatible 透传路径。
- 安全边界：`ResponsePending/429` 仍不重试，避免重复执行可能已经到达上游的请求；SSE 建立后仍不自动整轮重放。
- Codex 客户端 `request_max_retries=2` 继续作为第二层兜底，覆盖网络恢复后从客户端重新发起的场景。
- 修复 Kimi K3 等 Chat 上游在 Codex MultiRouter 下含 hosted `web_search` 时“发消息后无回复”的问题：此前本地工具循环会强制上游非流式，缓冲完成后只回一个 `response.completed`，Codex 不把它识别为正常 assistant turn。现在会完整重放 `response.created -> in_progress -> output item added/delta/done -> completed` 生命周期。
- 对齐缓冲响应的工具事件：function_call / tool_search_call 按 `in_progress added -> arguments done -> completed done` 重放，custom_tool_call 补齐 `custom_tool_call_input.delta/done`。
- Codex 路由日志新增 `upstream_stream` 字段，与客户端声明的 `streaming` 分开记录，hosted web_search 缓冲路径不再用 `streaming=true` 误导排障。
