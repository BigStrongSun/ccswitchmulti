# CCSwitchMulti v3.20.2-13

Fixes the loop where the proxy port was held by the app own lingering connections and the UI kept repeating the same error toast.

## Root cause (measured)

- `ProxyServer::stop()` closed only the listening socket; accepted connection tasks were never aborted. Those keep-alive/streaming connections kept the local port bound, so the immediate rebind on Windows failed with 10048.
- The retry loop then failed every 5 seconds and recorded a *new* "port occupied" recovery outcome each time, which is why the same toast kept popping. The diagnosis showed the owner was the app itself (readable path, only ESTABLISHED rows, no LISTEN row).
- A second defect: when the stale LISTEN row owner PID was gone, `OpenProcess` could return Win32 31 (GEN_FAILURE) instead of 87, so the "release the stale listener" branch never ran.

## Fix

- `stop()` now aborts every in-flight connection task (and logs how many), releasing the port immediately so it can be rebound.
- A port held only by the app own lingering connections is no longer treated as an unknown owner: no error toast and no recovery outcome, just retry until it frees.
- Identical unacknowledged recovery outcomes (same operation, kind, app) are deduplicated within a generation, so toasts cannot stack.
- Stale listeners are now detected by "does this PID still exist" instead of an error code, and listener sockets are explicitly non-inheritable to avoid ghost LISTEN rows after a crash.

## Verification

- New regression `restart_rebinds_while_previous_connections_still_open`: with a client connection still open, `stop()` followed by an immediate `start()` on the same port must succeed.
- New tests `process_exists_matches_reality`, `port_rows_are_attributed_to_the_listening_process`, `repeated_identical_failures_do_not_stack_duplicate_outcomes`.
- Full Rust suite single-threaded: 4180 passed / 0 failed / 7 ignored.
