# CCSwitchMulti v3.20.2-13

本版修“代理端口一直被本进程自己占住、提示反复弹”的问题。

## 根因（实测）

- `ProxyServer::stop()` 只关闭了监听 socket，**已接受的连接任务没有被结束**。这些 keep-alive/流式连接仍占着本地端口；Windows 下紧接着的重绑定会直接 10048。
- 于是复位重试每 5 秒失败一次，每次都写一条新的“端口占用”恢复结果 → 界面不停弹同一个提示；诊断里显示占用者其实是自己（pid=本进程、路径可读，只有 ESTABLISHED 没有 LISTEN）。
- 另有判定缺陷：残留监听的 owner PID 已消失时，`OpenProcess` 可能返回 Win32 31（GEN_FAILURE）而不是 87，导致“释放残留监听”分支没触发。

## 修复

- `stop()` 现在会中止所有在途连接任务（并记录数量），端口立刻真正释放，可立即重绑。
- 端口只被本进程残留连接占用时，不再当成“身份不明的程序”：不报错误提示、不写恢复结果，等连接释放后自动重试恢复。
- 相同（操作+类型+应用）的未确认恢复结果在同一代际内只保留一条，杜绝重复弹窗。
- 残留监听改按“PID 是否还存在”判定（不再依赖错误码），并让监听 socket 句柄显式不可继承，从源头减少“已死 PID 的 LISTEN 行”。

## 验证

- 新增回归 `restart_rebinds_while_previous_connections_still_open`：保持一个客户端连接不关闭，`stop()` 后立刻在同端口 `start()` 必须成功。
- 新增 `process_exists_matches_reality`、`port_rows_are_attributed_to_the_listening_process`、`repeated_identical_failures_do_not_stack_duplicate_outcomes`。
- 全量 Rust 单线程 4180 passed / 0 failed / 7 ignored。
