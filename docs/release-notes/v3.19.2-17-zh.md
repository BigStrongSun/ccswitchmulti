# CCSwitchMulti v3.19.2-17

## 重点修复

- **第三方协议自动探测**：Codex Provider 保存前会对当前部署实际测试 Responses 与 Chat Completions，两条分支分别验证普通响应、流式响应、强制工具调用和工具结果续接，再按可用能力与推理内容保真度选择协议。历史 `wire_api` 只作为提示，不再因为模型名称或旧配置跳过真实协议；探测证据只保存脱敏结构和哈希。
- **MCP 配置所有权**：CCSwitchMulti 只更新或删除自己写入且指纹未变化的 Codex MCP。用户手写的同名 MCP 不会被认领，用户修改过的托管 MCP 会自动退出 CCSM 所有权；Provider、MultiRouter、MCP 和官方认证写入统一从最新 `config.toml` 快照重建，避免并发保存互相覆盖。
- **Provider-aware 路由投影**：`mode=all`、V2 Agent 与 live catalog 的发布链全部携带当前 Provider 上下文，无前缀模型也能按真实目标 Provider 归属；旧 prefix-only Router 迁移会过滤已停用模型，Router 数据库继续只保存路由策略，不回存派生模型目录。
- **启动身份与恢复结果**：Windows 端口复用同时核验真实监听 PID、进程创建时间、可执行文件、配置作用域、运行协议和监听角色；External OpenAI API 或未知进程不会被误认、终止或接管。运行 marker 不再被第二实例覆盖/误删，恢复失败按应用与操作持久保留，并通过可确认的本地化提示展示，不会被后续成功覆盖。
- **启动行为拆分**：`开机自启`现在只会在登录后启动 CCSwitchMulti，不会再隐式拉起 Codex Desktop。新增独立的“启动 CCSwitchMulti 时启动 Codex Desktop”开关，默认关闭；Codex 已运行时不会重复启动，启动失败也不会阻断 CCSwitchMulti。
- **Codex MultiRouter 严格路由**：路由选择改为 fail-closed。未勾选、未匹配或已停用的模型不再回退到默认或第一条路由，避免请求被转发到错误的供应商。界面中的路由显示名称与内部 ID 分离，保存和编辑不会把可读名称写回路由身份。
- **模型目录投影一致性**：SSOT 恢复、启动接管和热切换统一写入排序后的模型目录及对应依赖指纹，同时保留认证、Common Config 和用户自定义设置，避免菜单排序与 Router 当前配置脱节。
- **Provider 全字段自动跟随**：schema-v2 MultiRouter 继续只保存路由策略，模型增删/启停、上下文、输入模态、推理档位、Ultra、协议、缓存、显示名和排序都从目标 Provider 实时编译。`mode=all` 自动跟随目录变化，`mode=include` 保持用户明确选择的白名单。
- **双前端与 V2 Agent 同步**：MultiRouter 工作台和创建/编辑向导统一读取最新 Provider 状态；新增模型会自动进入“全部模型”规则，并为已初始化的 V2 Agent 补充默认关闭档案。停用 Router 也会更新 Agent 数据，但不会覆盖当前运行投影。
- **Codex Desktop 目录热刷新**：Guardian 现在比较真实目录 payload 指纹，Provider 目录变化时即使 renderer target 未变化也会重新注入；renderer wrapper 动态读取最新 payload，不再绑定首次启动时的旧模型列表。
- **V2 路由认证归属**：统一兼容 `upstream.auth`、`auth`、`authPolicy` 和 `auth_policy`，并覆盖认证门面、账号池、迁移及 raw passthrough 的官方端点识别；v2 声明不再被残留的空旧字段遮蔽，避免官方路由误写 `PROXY_MANAGED` 或转发到错误后端。
- **V2 旧数据兼容**：同步或旧版本产生的 v2 route 缺少 `modelSelection` 时，前后端统一按“目标 Provider 全部模型”解释，避免界面恢复后又在保存、编译或运行阶段失败。
- **共享投影单写者**：多个 Router 共用模型源时只允许当前活动 Router 发布目录；活动归属不明时不会让多个 Router 依次覆盖共享文件。
- **DeepSeek 角色别名**：Flash/Pro 的自动后缀别名按规范化模型 ID 识别，大小写不同也不会误报“目录中缺失”，Vision 变体仍明确排除。
- **Windows 配置写入稳定性**：配置文件被 Codex、杀毒软件或索引程序短暂占用时进行有界重试；同时使用同卷备份处理 `ReplaceFileW` 已部分移动文件的失败状态，能够完成新文件安装或恢复旧文件，不降级为可能产生半写配置的直接覆盖。
- **第三方推理内容**：兼容层保留可读的第三方 `reasoning_content` 与 `<think>` 内容，并以 Codex 可显示的原始推理字段呈现，避免正常回答内容泄漏或被错误改写。
- **原生 Responses 推理档位**：原生 `/v1/responses` 直通现在与 Chat/Messages 转换共用 Provider 能力映射。Codex Ultra 的线级 `max` 会按模型声明转换为上游真实档位（例如 `xhigh`），不再对特定模型写死，也不会把 Chat 参数形态混入 Responses 请求。
- **Responses 完成语义**：Chat、假流式和原生 Responses 不再把 `[DONE]` 或干净 EOF 直接当作成功。代理会校验最终状态、正文/refusal、完整工具调用或合法 compaction 输出；缺失终态、reasoning-only 假完成和不完整工具调用会返回协议错误，避免 Codex 突然结束任务。
- **本地升级事务**：Windows 本地升级流程补齐端口租约释放、NSIS 安装态哈希推导、成功 PID 契约和 PowerShell 模块缺失兼容；旧进程未清理或端口仍被占用时会拒绝继续替换。
- **多设备同步稳定性**：本机 Codex 会话增量进度不再随 WebDAV/S3 同步传输，目标机器保留自己的文件路径与读取进度，避免跨设备路径冲突和同步导入失败。

## 新增基础能力

- **Provider 预设注册表地基**：增加带版本、哈希、过期和签名校验的预设来源配置；内置预设继续作为离线兜底。该版本只提供获取与校验基础，不会自动覆盖用户现有 Provider 配置。
- **分层能力目录**：增加可签名、可更新的模型能力 bundle 与本地覆盖地基，为后续不随应用 Release 更新上下文、模态和推理能力预设建立版本化入口；用户 Provider 仍是当前运行事实源。

## 升级说明

- 本版本会把数据库 schema 自动迁移到 v18，用于保存脱敏的协议兼容性档案和推理高级覆盖；迁移前沿用现有数据库备份机制，不修改 Provider 凭据和 Router 的 Provider SSOT 边界。
- 若此前只希望登录后运行 CCSwitchMulti，请保持新增的 Codex Desktop 启动开关关闭；升级后的旧设置默认就是关闭状态。
