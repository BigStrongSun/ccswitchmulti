# CCSwitchMulti v3.20.2-12

This build turns "keep CCSM alive" into a **built-in cross-platform watchdog** instead of a Windows-only PowerShell script plus scheduled task.

## How it works

- On startup (setting `watchdogEnabled`, on by default) the app starts a supervisor process from the **same binary**:
  `cc-switch --ccsm-supervise <parent-pid> --ccsm-supervise-config <config-dir> --ccsm-supervise-port <port>`.
- The supervisor never creates a UI. It watches the main process and, when the main process **died unexpectedly** (the run marker still points at it but the process is gone), restarts the installed executable and waits until the local proxy port is serving again, then exits. A normal tray quit is left alone.
- Restarts are rate limited to 5 per 30 minutes and recorded in `<config-dir>/logs/watchdog.jsonl` (`supervisor-spawned`, `supervisor-watching`, `supervisor-restarted`, `supervisor-restart-ready`, `supervisor-clean-exit`, `supervisor-restart-limited`, `supervisor-parent-unhealthy`).
- One Rust implementation covers Windows, macOS and Linux; Settings has a toggle to turn it off.

## Why not an in-process thread / scheduled task / systemd

- An in-process thread dies with the process, so it cannot restart anything.
- A PowerShell plus scheduled task (the previous approach) only covers Windows, is not shipped with the app, is invisible to users, and would have to be rewritten per platform.

## Verification

- Unit tests cover argument parsing, crash-vs-clean-exit classification and the restart budget; full Rust suite single-threaded 4161 passed / 0 failed / 7 ignored.
- After installation: killing the main process produced `supervisor-restarted` + `supervisor-restart-ready` in the watchdog log and the proxy port was serving again.
