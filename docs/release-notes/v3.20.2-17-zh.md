# CCSwitchMulti v3.20.2-17

修掉“弹窗打开时通知点不动”的渲染层缺陷。

## 问题

当「正在刷新 Codex 状态」弹窗打开时，顶部的黄色通知（例如“检测到上次运行未正常退出，请检查配置恢复结果”）连同它的「查看日志」按钮完全点不动，看起来像被上层的弹窗容器遮挡。

实际原因不是 z-index：

- Radix 的模态弹窗（`@radix-ui/react-dismissable-layer` 的 `disableOutsidePointerEvents`）会给 `document.body` 加**内联** `pointer-events: none`，只把弹窗内容自己标成 `auto`。
- sonner 的通知层挂在 `#root` 里（body 的后代），而 `pointer-events` 是继承属性，于是整棵通知层连同按钮一起变成 `none`，点击落不到任何元素。

## 修复

- 通知容器显式声明 `pointer-events: auto`，覆盖从 body 继承来的 `none`。
- sonner 自己的 `[data-sonner-toast][data-visible='false'] { pointer-events: none }` 依然生效，隐藏/移出中的 toast 不会变得可点；模态对后台应用界面的封锁也不受影响。

## 验证

- 新增 `src/components/ui/sonner.test.tsx`：先断言模态确实把 `body` 锁成 `pointer-events: none`，再断言通知容器/toast/按钮的 computed `pointer-events` 为 `auto`，并用 `user-event` 真实点击「查看日志」。修复前该用例会直接报 `element has pointer-events: none`。
- `tsc --noEmit`、Prettier、`vitest`（sonner + CodexConfigConsistencyDialog 15 passed）通过。
