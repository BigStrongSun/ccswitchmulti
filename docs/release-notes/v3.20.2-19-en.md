# CCSwitchMulti v3.20.2-19

This release fixes the "missing from catalog" false alarm on the V2 Agent configuration page and the missing `deepseek-flash` role file, both caused by a mismatch in the DeepSeek role slug aliasing. The root cause: the product's internal canonical slugs (`deepseek-v4-flash`/`deepseek-v4-pro`) differ from DeepSeek's current API slugs (`deepseek-flash`/`deepseek-pro`), and several role-classification points hardcoded the old slug. `deepseek-pro` was unchanged, so the pro side always worked.

## Problem

After enabling/selecting DeepSeek's current official slug `deepseek-flash` in the model catalog, the flash role-coverage badge on the V2 Agent page still showed "missing from catalog", and no `deepseek-flash` role toml was generated. The model was clearly enabled (a live request returned HTTP 200), so this was a bug.

## Root cause

The product's internal canonical slugs (used by V2 default profiles, catalog templates, and presets) are `deepseek-v4-flash`/`deepseek-v4-pro`, while DeepSeek's current API slugs are `deepseek-flash`/`deepseek-pro`. Several role-classification points hardcoded the old slug (exact match or `contains`). When the catalog uses the new slug:

1. **UI badge** (`CodexRouterWorkspacePage`) only recognized `deepseek-v4-flash*` → false "missing from catalog".
2. **V2 compiler** (`codex_subagent_profiles.rs`) matched the catalog case-insensitively by exact slug → the old-slug profile was marked Unroutable and the role file was never generated.
3. **V2 auto-generation** (`catalog_profile_draft` / `preferred`) looked up the default preset by identity → `deepseek-flash` did not resolve to the `deepseek-v4-flash` preset and degraded to a disabled generic stub.
4. **V1 role-file helpers** (role name/description/effort/guidance) used `contains` on the old slug → the new slug did not get Flash/Pro role semantics.
5. **text-only guard** was missing two exact-match aliases → the new slug was not forced into text modality, so Codex would inject the hosted `image_generation` tool that DeepSeek does not support.
6. **reconcile** PruneUnroutable/Recover used the old criteria → an alias profile could be wrongly deleted.

**Upstream verification (decisive evidence):**

- `GET https://api.deepseek.com/v1/models` lists only `deepseek-flash` and `deepseek-v4-pro`.
- A minimal `POST /v1/responses` with `model: "deepseek-v4-flash"` → HTTP 200, and the response echoes `"model":"deepseek-flash"`. The two are the same model; the old ID is a legacy alias that upstream still accepts. No catalog-template or preset changes were needed — only the product's internal alias criteria needed to be unified.

## Fix (single source of truth, no patching)

- New shared Rust helpers (`codex_subagent_profiles.rs`, pub):
  - `deepseek_role_identity_for_model`: the flash family (`deepseek-flash`/`deepseek-v4-flash` and their `-` prefixed variants, excluding anything containing `vision`) → canonical `deepseek-v4-flash`; the same for pro.
  - `deepseek_role_models_match`: case-insensitive exact match, or same role-family equivalence.
- All catalog↔profile match points now use this criteria: V2 compile match, pinning the role model to the catalog's actual slug on alias match, `catalog_profile_draft` preset lookup, the two `preferred` flags, `routable_by_identity` (prune/recover alias keys), compile/preview input_modalities hydration and spec/role lookups, `route_classifications`/`reasoning_capabilities` queries, the four V1 helpers, and the text-only guard (now with exact `deepseekflash`/`deepseekpro` entries).
- New shared TS helper (`src/utils/deepseekRoleModels.ts`, mirroring the Rust logic): badge, the priority-model list, and `modelNameLooksTextOnly` (which also fixes a previously missed `deepseekv4` prefix overmatch on the TS side).

## Behavioral boundaries (intentional)

- `deepseek-v4-flash-vision-exp` is no longer matched as a flash text role by the V1 role helpers' `contains` (it takes the generic slug path with an independent role name), consistent with the established criteria.
- V2 default profile keys, provider preset slugs, and profile collision identity are unchanged; when two alias profiles coexist, each remains routable (existing behavior preserved).
- Existing user configuration is not auto-"upgraded": a pre-existing disabled stub profile is left as-is; after toggling the enable switch and saving, the role file is generated (with the fix, both the compile match and the badge are correct).
