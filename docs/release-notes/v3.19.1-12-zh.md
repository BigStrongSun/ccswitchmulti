# CCSwitchMulti v3.19.1-12

本版本修复启用 Codex Desktop 模型菜单兼容层后，文件改动摘要、命令状态和耗时等界面把 ICU/React Intl 占位符原样显示的问题，例如 `{linesAdded}`、`{time}`、`{command}` 和 `{fileCount, plural, ...}`。

## 修复内容

- 根因不是 Codex 中文语言包缺失，而是旧版模型菜单解锁脚本每 1.5 秒遍历整棵 React Fiber，并给普通对象无条件写入 `defaultModel/useHiddenModels`。
- 该写入会污染 React Intl 的 `formats`、`defaultFormats` 和 `formatters`，形成循环引用；MessageFormat 缓存序列化失败后按官方 fallback 返回未插值的消息 source。
- 模型目录解锁现在只修改具有明确模型门字段的对象，并且只更新对象原本存在的 camelCase/snake_case 控制字段，不再凭空给普通对象追加另一套字段。
- 移除对全局 `Response.prototype.json` 的劫持，不再把所有 JSON 响应当成潜在模型目录。
- 移除 React Fiber 对象图的通用模型字段改写。模型列表只在 app-server 的模型列表响应、已关联的 MCP `model/list` 响应和 Statsig 模型配置三个已知边界处理。
- Codex 登录态兼容仍使用独立、只识别 `setAuthMethod + authMethod` 的定向 context 查找，不改变 Provider、请求路由或认证材料。

## 验证

- 当前 Codex Desktop `26.803.5235.0` 现场复现了未插值占位符，并确认三个 React Intl 对象都被 `3.19.1-11` 旧注入污染。
- 新增 QuickJS 行为回归，直接执行与 renderer 共用的模型 patch 核心：React Intl 对象序列化前后完全一致，四次 patch 均返回未修改。
- 显式模型门回归同时确认 Qwen/DeepSeek 模型仍会加入目录、已有 `useHiddenModels` 会解除、已有 `defaultModel` 会设置，且不会凭空新增 snake_case 字段。
- 模型菜单定向测试、完整 Rust library 测试、`cargo check --lib`、rustfmt、typecheck 和安装包校验结果以最终构建记录为准。

## 升级方式

完全退出 Codex Desktop 与 CCSwitchMulti 后覆盖安装本版本，再从 CCSwitchMulti 启动 Codex Desktop，使新版兼容脚本进入全新的 renderer 上下文。仅刷新当前页面不足以清除旧脚本已经污染的 React Intl context。

升级不会修改 Codex 历史、Provider、MultiRouter 路由或账号配置。
