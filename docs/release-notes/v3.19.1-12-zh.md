# CCSwitchMulti v3.19.1-12

本版本是 `3.19.1-11` 的累计修复版，不只处理 Codex Desktop 的 ICU/React Intl 占位符，还包含 DeepSeek Pro/Chat 路由归属修复，以及两项 Windows 本地发布可靠性修复。

## 用户可见修复

### 1. DeepSeek Pro/Chat 不再被改写为 Flash/Responses

- 修复选择官方 DeepSeek Pro/Chat 后只能“一问一答”、无法稳定继续工具循环的问题。
- 根因不是 DeepSeek Chat 不支持工具调用，而是旧启动迁移从整份 MultiRouter JSON 推断协议。只要同一 Router 存在 Flash 路由，独立 Pro/Chat 路由也会在后续启动时被反复改成 Flash/Responses。
- 迁移现在按每条 route 的 `targetProviderId` 读取目标 Provider 的真实模型目录：
  - 只包含 `deepseek-v4-pro` 的 Provider 保持 `openai_chat`；Codex 对外仍连接 CCSwitchMulti 的 Responses 门面，由 CCSwitchMulti 在内部转换到 `/chat/completions`。
  - 只包含 `deepseek-v4-flash` 的 Provider 继续使用官方原生 Responses。
  - 旧版把 Flash 与 Pro 放在同一 Provider 的配置仍会拆分为两条正确路由。
- 已被旧迁移污染的 Pro route 会在启动时自愈模型匹配、前缀、模型映射和 Chat 协议；重复启动不再改变修复后的配置。
- 对应生产提交：`4d62e500`。

### 2. Codex Desktop 不再原样显示 ICU/React Intl 占位符

- 修复文件改动摘要、命令状态和耗时等界面显示 `{linesAdded}`、`{time}`、`{command}`、`{fileCount, plural, ...}` 等原始模板的问题。
- 根因不是中文语言包缺失，而是旧模型菜单解锁脚本每 1.5 秒遍历 React Fiber，并给普通对象无条件写入 `defaultModel/useHiddenModels`。这会污染 React Intl 的 `formats`、`defaultFormats` 和 `formatters`，形成循环引用；格式化失败后按 FormatJS fallback 返回未插值的消息 source。
- 模型目录解锁现在只修改具有明确模型门字段的对象，并且只更新对象原本存在的 camelCase/snake_case 控制字段。
- 移除全局 `Response.prototype.json` 劫持和 React Fiber 通用对象图改写。模型列表只在 app-server model-list、已关联的 MCP `model/list` 和 Statsig 模型配置三个已知边界处理。
- Codex 登录态兼容继续使用独立、只识别 `setAuthMethod + authMethod` 的定向 context 查找，不改变 Provider、请求路由或认证材料。
- 对应生产提交：`e7aacf26`。

## 发布可靠性修复

### 3. 并发本地发布不再互相删除锁

- 旧流水线在竞争者获取锁失败后，仍可能在 `finally` 中删除另一条活跃流水线的锁，导致多个 Tauri 构建并发争写 `cc-switch.exe`。
- 发布锁现在使用原子 `CreateNew`、每进程 ownership token 和 owner-only release；失败的竞争者不能再释放其他进程持有的锁。
- 对应提交：`906a2b7b`。

### 4. SHA256 清单路径不再被重复分隔符截断

- 修复 Windows `ReleaseRoot` 含重复反斜杠时，`SHA256SUMS.txt` 相对路径可能丢失前导字符的问题。
- 两个 checksum writer 现在先用 `Path.GetFullPath` 规范化根目录，再枚举文件并计算相对路径，保持 Windows PowerShell 5.1 兼容。
- 对应提交：`434541de`。
