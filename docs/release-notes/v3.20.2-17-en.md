# CCSwitchMulti v3.20.2-17

Fixes a rendering-layer defect where notifications could not be clicked while a dialog was open.

## Problem

With the “Refreshing Codex state” dialog open, the yellow notification at the top (for example “The previous run did not exit normally — check the configuration recovery result”) and its “View logs” button could not be clicked at all; it looked like the dialog container was covering it.

The real cause is not z-index:

- Radix modal dialogs (`disableOutsidePointerEvents` in `@radix-ui/react-dismissable-layer`) set an **inline** `pointer-events: none` on `document.body` and only mark the dialog content itself as `auto`.
- The sonner notification layer is mounted inside `#root` (a descendant of body), and `pointer-events` is inherited, so the whole notification layer — including its action buttons — became non-interactive.

## Fix

- The notification container now declares `pointer-events: auto` explicitly, overriding the inherited `none`.
- sonner's own `[data-sonner-toast][data-visible='false'] { pointer-events: none }` still applies, so hidden or exiting toasts stay non-interactive, and the modal still blocks the background application UI.

## Verification

- New `src/components/ui/sonner.test.tsx`: asserts the modal locks `body` to `pointer-events: none`, then asserts the toaster container, toast, and button compute to `auto`, and performs a real `user-event` click on “View logs”. Before the fix this test fails with `element has pointer-events: none`.
- `tsc --noEmit`, Prettier, and `vitest` (sonner + CodexConfigConsistencyDialog, 15 passed) are green.
