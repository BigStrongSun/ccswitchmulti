# CCSwitchMulti v3.20.2-6

This is a focused hotfix over `v3.20.2-5` for Codex paginated-history cursor recovery copying the entire 3.5 GB projection database before applying a tiny cursor repair, which caused a 15-minute timeout. Database schema remains v22.

## Codex Status & Repair

- Provider-migration cursor recovery no longer performs a full SQLite backup of `thread_history_1.sqlite`. The previous 5-pages/25 ms backup pace was roughly 800 KB/s, so a 3.5 GB database needed about 70 minutes and tripped the 15-minute guard with a false `codex_paginated_history_repair_timed_out`.
- Recovery now writes only `cursor-repairs.json` into the recovery directory, recording `sourceId`, old/new offset, and expected ordinal for affected cursors for audit and manual recovery.
- The actual cursor updates remain atomic through one SQLite transaction, compare-and-set, and a boundary postcheck. JSONL `history_base` backups, length validation, and rollback remain unchanged.
- A regression now covers "write the cursor snapshot without copying the projection database."

## Verification

- `paginated_history` 24/24; `codex_runtime_refresh` 37/37.
- Serial Rust library suite: 4134 passed / 0 failed / 7 ignored. `cargo check --all-targets` and rustfmt passed.
- This release changes only the execution path. It does not alter the database schema, delete existing recovery evidence, or bulk-modify history files.
