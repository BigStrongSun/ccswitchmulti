# CCSwitchMulti v3.20.2-7

This is a focused hotfix over `v3.20.2-6`, fixing inability to force-release the proxy port when an older CCSM instance or its AppContainer hardlink still owns it. Database schema remains v22.

## Proxy Port Recovery

- Force-restore now reads the listener's `/status` before termination and verifies `app=ccswitchmulti`, same major version, PID/start ticks, executable identity, config scope, runtime API, `listener_role=takeover`, and `running=true`.
- Even when the old listener comes from a different CCSM version (for example a stale 3.20.2-5 after a failed upgrade), it is terminated and takeover is restored if `/status` proves it is the same CCSM takeover instance. Unverifiable foreign processes still fail closed.
- When the current process owns the port, it stops its own proxy server before rebinding, instead of treating its own listener as an unknown owner.

## Paginated History Repair

- Includes the `v3.20.2-6` fix: provider-migration cursor recovery no longer copies the entire 3.5 GB `thread_history_1.sqlite`. It writes a small `cursor-repairs.json` snapshot instead; actual cursor updates remain atomic through one SQLite transaction, compare-and-set, and a boundary postcheck, avoiding the false 15-minute timeout.

## Verification

- `services::proxy` 98/98 and `paginated_history` 24/24 passed; `cargo check --all-targets` and rustfmt passed.
- The serial full suite still has one unrelated pre-existing failure, `database::dao::usage_rollup::tests::test_rollup_merges_with_existing`, recorded for separate investigation; this release does not hide it or count it as passed.
- Runtime replacement still requires the published installer or a controlled replacement after the port is released.
