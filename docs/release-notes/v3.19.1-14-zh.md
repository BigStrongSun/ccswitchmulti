# CCSwitchMulti v3.19.1-14

本版本吸收并整理了社区 PR #36 的有效贡献，集中修复 Claude Desktop 每模型用户偏好丢失、Windows 后台 PowerShell 周期性闪窗，以及开机自启在含空格安装路径或任务管理器状态变化后不生效的问题。感谢 @zhushihao 的定位与实现。

## 用户可见更新

### 1. Claude Desktop 保留每个模型的 1M 上下文偏好

- 修复用户在 Claude Desktop 中启用 “Default to 1M context” 后，切换或重新应用 Provider 会丢失 `inferenceModels[*].prefer1m` 的问题。
- CCSwitchMulti 重建托管模型列表时，会按模型 `name` 合并旧条目中未由新配置生成的用户字段。
- 网关地址、模型映射、显示名称等 CCSwitchMulti 托管字段仍以当前 Provider 配置为准，不会被旧 profile 反向覆盖。
- v3.19.1-13 已修复 profile 顶层扩展字段保留；本版补齐嵌套在单个模型条目内的偏好字段。

### 2. Windows 后台探测不再周期性弹出 PowerShell 窗口

- 修复 Codex guardian 每隔数秒探测 Desktop 主进程时可能闪现 PowerShell 控制台窗口的问题。
- 同步补齐 Codex Desktop 安装候选探测和代理诊断进程探测的隐藏窗口标志。
- 用户主动执行安装器或打开终端的流程不受影响；只有应用内部后台探测使用 `CREATE_NO_WINDOW`。

### 3. Windows 开机自启注册表状态修复

- 自启 Run 命令现在会正确引用 exe 路径，安装在 `Program Files` 等含空格目录时不会被 Windows 按空格截断。
- 启用和禁用会同步维护 `HKCU\\...\\Run` 与任务管理器使用的 `StartupApproved` 状态，避免注册表看似存在但登录后不启动。
- 状态检查会尊重用户在任务管理器中手动禁用自启的结果，并按 Windows 路径大小写不敏感语义校验当前 exe。
- 注册表权限或写入失败会明确返回错误；写入启用状态失败时会撤销刚写入的 Run 值，避免留下半配置状态。
- macOS 和 Linux 继续使用原有自启实现，不受本次 Windows 专属修改影响。

## 升级与验收

1. 完全退出 CCSwitchMulti，包括托盘中的后台进程，然后安装本版本。
2. 在设置中启用开机自启；安装路径包含空格的 Windows 用户可注销并重新登录，确认 CCSwitchMulti 正常启动。
3. 如果在任务管理器的“启动应用”中手动禁用 CCSwitchMulti，设置页应同步显示为未启用。
4. Claude Desktop 用户可为一个模型启用 1M 上下文偏好，再切换并重新应用 Provider，确认该模型的偏好仍保留。

发布流水线成功只证明构建和远端资产完整，不等同于已在所有用户机器完成安装后运行验收。升级不会主动删除 Codex/Claude 历史、Provider、MultiRouter 路由或账号配置。
