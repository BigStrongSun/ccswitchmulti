# CCSwitchMulti v3.19.1-14

本版本在 fork 分支 `fix/preserve-user-extras` 上发布，包含 prefer1m（Default to 1M context）在切换 Provider 时被覆盖的修复，用于本地验证。

## 用户可见修复

### 1. 切换 Provider 后 "Default to 1M context" 不再被覆盖

- 修复选择 1M context 上下文长度后，再切换 Provider 会被重置的问题。
- 根因：`inferenceModels` 数组是托管字段，应用 Provider 时会按路由整体重建；旧版只合并顶层非托管字段，`prefer1m`（Default to 1M context）是 `inferenceModels` 条目内的 per-model 字段，因此在重建时被丢弃。
- 修复：新增 `preserve_inference_model_extras`，按模型 `name` 匹配已有 `inferenceModels` 条目，合并条目内未在新建条目中出现的用户字段（如 `prefer1m`）。顶层非托管字段继续沿用既有 `preserve_user_profile_extras` 合并逻辑。
- 对应提交：`0fd46f7d`。

## 验证结果

- 回归测试 `claude_desktop_apply_preserves_per_model_1m_preference`：应用 Provider 后注入 per-model `prefer1m: true`，重新应用 Provider，断言 `prefer1m` 保留且托管字段（labelOverride、supports1m）仍按路由更新。
- `cargo test` 通过。

## 升级与验收

1. 完全退出 Codex Desktop 与 CCSwitchMulti，包括托盘中的 CCSwitchMulti。
2. 覆盖安装 `CCSwitchMulti_3.19.1-14_x64-setup.exe`（或 fork release 对应安装包）。
3. 在模型选择中开启 1M context，切换 Provider，确认 "Default to 1M context" 保持开启。
