# CCSwitchMulti v3.20.2-12

本版把「防止 CCSM 挂掉」做成**应用自带的跨平台看门狗**，不再依赖 Windows 专属的 PowerShell 脚本或计划任务。

## 做法

- 主程序启动时（设置项 `watchdogEnabled`，默认开启）用**同一个二进制**再拉起一个守护进程：
  `cc-switch --ccsm-supervise <parent-pid> --ccsm-supervise-config <config-dir> --ccsm-supervise-port <port>`。
- 守护进程不初始化界面，只做一件事：盯着主进程。主进程**异常退出**（运行标记仍指向它、但进程已经不在了）时，
  它重新拉起安装态可执行文件，等到本地代理端口重新可用后自行退出；正常运行期间的“用户托盘退出”不会被拉起。
- 频率上限 30 分钟 5 次，事件写入 `<配置目录>/logs/watchdog.jsonl`：
  `supervisor-spawned` / `supervisor-watching` / `supervisor-restarted` / `supervisor-restart-ready` /
  `supervisor-clean-exit` / `supervisor-restart-limited` / `supervisor-parent-unhealthy`。
- Windows/macOS/Linux 共用这一套 Rust 实现；设置界面新增「崩溃自动恢复（看门狗）」开关，可随时关闭。

## 为什么不是进程内线程 / 计划任务 / systemd

- 进程内线程会随主进程一起消失，无法实现“进程死了再拉起来”。
- PowerShell + 计划任务（旧方案）只覆盖 Windows、不随软件分发、用户看不到开关；同样的情况在 macOS/Linux 上需要再写一套。

## 验证

- 单元测试：参数解析、崩溃/正常退出判定、重启预算；全量 Rust 单线程 4161 passed / 0 failed / 7 ignored。
- 安装后实测：kill 主进程 → 守护日志 `supervisor-restarted` + `supervisor-restart-ready`，端口恢复可用。
