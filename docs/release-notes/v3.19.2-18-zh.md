# CCSwitchMulti v3.19.2-18

## 重点修复

- **深度协议探测进度页**：Codex Provider 的“验证连接”现在直接运行完整兼容性探测，并实时展示每个启用模型在 Responses 与 Chat Completions 两条协议上的基础响应、SSE 流式、推理字段、强制工具调用和工具结果续轮。进度来自后端真实阶段事件，不使用前端计时器模拟。
- **协议选择只比较可用能力**：选择器按“工具结果续轮、强制工具、SSE 流式”比较两条协议；能力完全相同时优先原生 Responses。raw reasoning、native summary、opaque reasoning 等形态继续记录并用于选中协议后的字段投影，但不再被错误当成协议质量分数。
- **链路故障不再伪装成模型不支持**：HTTP 521、超时、网络错误、响应过大和非法响应会以脱敏类别呈现。基础响应失败时，推理阶段显示“未检测/已跳过”，不会再把上游故障写成“不支持推理”；错误信息不包含 endpoint、API Key、prompt 或响应正文。
- **Responses 终态判断更严格**：Responses SSE 必须到达合法终态；只收到 `response.created` / `response.in_progress` 后提前 EOF 会被记录为流式失败，避免探测把“HTTP 200 但流已崩溃”当作兼容。
- **MultiRouter 推理档案自动同步**：独立 Provider 的 verified 协议档案会在完整目标身份一致时同步到依赖 route。旧 route 档案缺失或过期时，运行时也可继承完全等价 Provider 的 verified 档案；模型、协议、endpoint、认证或凭据任一不一致仍会 fail closed。
- **第三方推理字段保持真实语义**：可读 raw reasoning 始终投影为 `reasoning_text`，只有上游原生 summary 才投影为 `reasoning_summary_text`。CCSwitchMulti 不再为了某个客户端的显示行为把完整原始推理伪装成摘要，也不会在代理层自行生成摘要。
- **多模型探测结果一致性**：普通 Provider 会探测目录中所有启用模型；全部模型选中同一协议时才更新全局 `apiFormat` / `wire_api`，混合结果会保留原配置并提示拆分 Provider，停用模型不会发出探测请求。

## vLLM / Qwen 说明

- 本版本能够准确识别 vLLM Responses 流在 `created/in_progress` 后异常结束，并保留 Chat 作为安全可用协议；它不会静默修改远端 vLLM 配置。
- 已确认的一类上游原因是非 Harmony 模型启用实验 `ParsableContext` 后，特定 vLLM 版本的 Responses 流式路径仍要求 `SimpleContext`。该问题需要在对应 vLLM 部署修正或升级后重新运行深度探测；CCSwitchMulti 会依据新的真实结果重新选择协议。

## 验证

- 发布候选会运行完整 Rust library、完整前端 Vitest、TypeScript、renderer build、Cargo check、Rust/Prettier 格式、UTF-8 与 diff hygiene 门禁。
- 正式安装包由 tag 对应的 GitHub Actions 在 Windows x64/ARM64、Linux x64/ARM64 与 macOS universal 上重新构建，并校验六个平台的 updater 资产、签名和 `latest.json`。

## 升级说明

- 已保存的旧协议档案不会被无条件覆盖。升级后请在目标 Provider 设置页重新运行一次深度探测并保存，使当前 endpoint、模型、认证和凭据对应的新档案生效。
- 如果 Responses 仍只出现起始事件而没有终态，请先查看探测页显示的失败阶段，再检查上游服务日志；不要仅凭 HTTP 200 判断流式协议已经完成。
