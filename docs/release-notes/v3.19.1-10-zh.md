# CCSwitchMulti v3.19.1-10

本版本修复 `v3.19.1-9` 在 Codex Multi-Agent V2 主会话中错误拦截 OpenAI 官方加密 Agent 历史的问题。升级后，OpenAI 官方父/子 Agent 的合法加密消息继续原样交给 ChatGPT Codex 后端；Qwen、DeepSeek 等第三方子 Agent 仍使用 CCSwitchMulti 的明文兼容链路。

## 修复内容

- 修复 MultiRouter 的 OpenAI Official route 被误判成第三方 child，导致主会话收到 `third-party child cannot read encrypted Codex agent payload` / HTTP 400。
- 根因是 managed Codex OAuth route 物化后使用 request-local route ID；旧判断只识别内置 `codex-official` seed，没有同时按 `provider_type=codex_oauth` 识别 OpenAI ownership。
- 第三方 Agent payload 投影现在同时排除原生 OpenAI Official 与 managed Codex OAuth，仅对真正的第三方 Responses/Chat/Anthropic route 生效。
- 保留安全边界：CCSwitchMulti 不解密、不记录也不转发 OpenAI 密文给第三方 Provider；如果真正的第三方 child 仍收到不透明密文，请求继续显式失败，避免空任务或密文泄漏。

## 验证

- RED 回归测试在 `v3.19.1-9` 逻辑上稳定复现 managed OAuth 被错误判定为第三方，修复后通过。
- Codex Multi-Agent payload 定向测试：`5 passed, 0 failed`。
- Codex OAuth Responses 回放定向测试：`14 passed, 0 failed`。
- 完整 Rust library 测试、`cargo check --lib`、rustfmt 与 Windows 安装包校验结果见最终构建记录。

## 升级方式

关闭 Codex Desktop 后覆盖安装本版本，再重新启动 CCSwitchMulti 与 Codex。升级不会修改 Provider、MultiRouter 路由、OAuth 账号或历史会话。

本版本只修复 CCSwitchMulti 的 Provider ownership 误分类；Codex 官方 Multi-Agent V2 仍为 beta，第三方模型无法解密 OpenAI 私有 payload 的上游限制仍然存在，因此混合路由继续依赖非 reserved `agents` namespace 的明文兼容链路。
