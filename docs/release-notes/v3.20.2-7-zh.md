# CCSwitchMulti v3.20.2-7

这是 `v3.20.2-6` 的定向热修复版本，修复旧 CCSM 实例/AppContainer hardlink 占用代理端口时“解除占用并恢复接管”无法强制释放的问题。数据库 schema 继续保持 v22。

## 代理端口恢复

- 强制恢复接管现在会在终止前读取端口监听实例的 `/status`：验证 `app=ccswitchmulti`、同 major 版本、PID/start ticks、可执行文件身份、配置 scope、runtime API、`listener_role=takeover` 和 `running=true`。
- 即使旧监听器来自不同版本的 CCSM（例如升级失败后残留的 3.20.2-5），只要 `/status` 证明它是同一 CCSM 接管实例，就允许安全终止并恢复接管；无法证明的外来进程仍然 fail closed。
- 当前进程自己持有端口时，先停止自身代理服务器再重新绑定，避免把自己的监听当成占用进程。

## 分页历史修复

- 同时包含 `v3.20.2-6` 的修复：Provider 迁移 cursor 恢复不再全量复制 3.5 GB `thread_history_1.sqlite`，改为写入小型 `cursor-repairs.json` 快照；实际 cursor 更新继续由 SQLite transaction、compare-and-set 和 boundary postcheck 保证原子性，避免 15 分钟误超时。

## 验证

- `services::proxy` 98/98、`paginated_history` 24/24；`cargo check --all-targets`、rustfmt 通过。
- 全量串行中仅剩一个与本改动无关的既有 `database::dao::usage_rollup::tests::test_rollup_merges_with_existing` 失败，已记录待独立调查；本版本没有掩盖或把它算作通过。
- 本机运行时需要用已发布安装包或在端口释放后做一次受控替换验收。
