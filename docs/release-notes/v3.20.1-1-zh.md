# CCSwitchMulti v3.20.1-1

本版本以官方 CC Switch v3.20.1 为迁移基线，并审计了截至官方 v3.20.2 的后续提交。CCSwitchMulti 没有直接合并长期分叉的官方分支，而是逐项核对 154 个非合并提交，在现有多客户端、协议证据、账户池和数据所有权边界内采用或重写适用改动。

## 官方能力迁移

- 新增 Pi 作为独立受管应用，覆盖 Provider、Prompt、Skill、Session 和用量索引；配置写入采用版本化事务、内容指纹与冲突拒绝，不把 Pi 错接到 Codex MultiRouter、Provider Set、takeover 或本地代理。
- 加固 Codex OAuth 身份边界，区分未绑定官方 Provider、绑定账户、CCSwitchMulti 账户池和第三方 Provider；重复账户、设备登录取消、刷新凭据和请求归属均按稳定身份处理。
- 修复跨协议代理细节，包括中途 system message、Moonshot/Kimi `$ref`、Claude hosted WebSearch、DeepSeek 搜索能力、Codex OAuth 并行工具调用、Chat 用量和 StepFun 推理档位。
- 改进 Windows/WSL 写入、PATH 与版本检测、启动窗口、Skill SSOT 缺失检测、SQL 备份保真、原子发布、恢复前验证以及同步串行化。
- Claude 会话增量索引升级为字节游标与尾部指纹，避免 UTF-8、多行内容、文件截断和同尺寸重写导致漏计或重复计费。

## CCSwitchMulti 重写与增强

- Provider live 状态只由受管配置、磁盘投影和进程事实共同决定，不再把陈旧缓存或不完整探测当成当前生效证据。
- Codex Provider 表改为可加载、可审计的运行目录；未知 vendor 模型先尊重显式能力和 text-only 注册表，再对仍未知的输入模态采取兼容回退。
- Claude takeover 对齐 Sonnet 5、Opus 5 和 adaptive thinking，同时保留 CCSwitchMulti 的别名、1M 标记、优化器与 Responses 转换边界。
- OpenCode Go 采用共享的多协议模型目录：Responses、Anthropic Messages 和 Chat Completions 模型分开暴露；五端可自动读取 rolling、weekly、monthly 用量，稳定 `x-opencode-session` 身份不会被随机请求 UUID 覆盖。
- 新增或更新 PPIO、Tencent Token Plan/TokenHub、QwenCloud 和智谱预设；按产品线、地域、协议、套餐与推理能力隔离端点和模型，不把静态预设冒充动态验证成功。
- 内置价格新增 GLM-5.3、GPT-6 Astra、Gemini 3.8 Flash 等已核实项目，并继续保护用户自定义价格与 tombstone。

## 已有能力与审计边界

- 官方部分改动在 CCSwitchMulti 中已有等价或更强实现，例如 Codex Images generations/edits 路由、DeepSeek 搜索能力约束、并行工具目录标记、Pi 翻译键和 GPT-6 OAuth 身份，因此保留现有实现。
- 官方 release/version、上游专属 CI 与 README 维护不直接移植；CCSwitchMulti 独立维护版本、签名、updater 和三平台发布流程。
- 审计矩阵最终覆盖 154/154 个官方非合并提交：50 项 adopted、16 项 already-covered、54 项 rewritten、15 项 deferred、19 项 not-applicable。

## 明确延期项

- 官方 v3.20.2 在冻结后到达的测试 `LOCALAPPDATA` 隔离、`mask_url` 多字节边界 panic、Claude workflow journal、Updater 错误详情、takeover `requires_openai_auth`、九月时效价格、JieKou/Novita 模型 URL、SoleAPI 和价格下拉布局未静默混入本版本。
- 其余仍标记为 rewritten 或 deferred 的 Provider 表单、目录、配额和视觉调整，需要独立来源证据、RED/GREEN 回归或截图验收后再进入后续版本。

## 数据库升级与降级

- 本版本将 CCSwitchMulti 数据库 schema 从 v20 升至 v22；启动迁移前会创建数据库备份，迁移在事务内完成并支持重复启动。
- v21 增加 Claude 会话字节游标与尾部指纹，v22 增加受管 Codex OAuth 身份数据。升级后，旧版 CCSwitchMulti 会拒绝打开更高版本数据库，不能直接覆盖安装后继续复用 v22 数据库。
- 如需降级，请在升级前导出配置或保留自动生成的迁移前备份；退出新版后恢复与目标旧版本兼容的完整备份，再启动旧版。不要手工修改 `PRAGMA user_version`，也不要只删除新增列来伪造兼容。

## 发布与运行态边界

- 源码门禁、本机 Windows 构建、GitHub Windows/Ubuntu/macOS CI、公开 Release、updater 元数据以及本机安装运行态是不同证据层；只有各层实际完成后才分别声明通过。
- 本版本候选在 Ryzen 9 9950X 上执行一次集中完整本地门禁。候选验证前不会创建 tag、推送 Release、替换当前安装或触碰 `127.0.0.1:15721` 的运行服务。
