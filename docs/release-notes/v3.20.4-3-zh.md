# CCSwitchMulti v3.20.4-3

本版基于 v3.20.4-2，修复原生 Codex Responses 流式请求在上游响应头建立前发生传输中断时，CCSM 旧逻辑立即返回 HTTP 424 的问题。发布不表示用户本机已安装，也不表示已在用户账号上完成端到端验收。

- 真实 424 并非 ChatGPT 上游返回的限流或业务状态，而是 CCSM 对 `ProxyError::ResponsePending` 的本地映射。现场底层错误为 `client error (SendRequest): connection closed before message completed`。
- 原生 Codex 流式 `/responses` 和 `/responses/compact` 请求现在会在原有五次传输重试预算内继续尝试同一请求，不再把第一次响应头前断连直接交给 Codex 客户端。
- 图片、Chat Completions、普通非流式请求、其它 App 和其它非 Responses 路径保持原有语义，不自动重放。
- 收到响应头后仍由流重连接管：只有尚未向客户端提交语义输出时才能透明重连；一旦语义内容到达客户端，继续禁止整轮重放。
- 每次重试都会记录“上游处理结果未确认”，且仍受固定次数和退避预算限制；全部重试失败时仍返回真实的未知结果错误，不会把结果未知伪装成成功。

本修复提升 CCSM 对短时响应头前断连的自愈能力，但不消除 QWRT 代理中转节点或上游网络故障。
