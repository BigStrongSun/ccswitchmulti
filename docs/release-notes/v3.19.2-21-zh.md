# CCSwitchMulti v3.19.2-21

本版本修复“随 CCSwitchMulti 启动 Codex”与配置恢复、代理接管之间的启动竞态。

## 主要改进

- Codex Desktop 不再在 CCSwitchMulti 数据库、模型目录、配置投影和代理接管恢复之前启动。
- 新增启动门禁：先修复当前 Provider 的托管配置并复检，再允许启动 Codex；接管恢复或配置验证失败时阻止启动并记录明确原因。
- 对可修复的托管配置漂移只自动修复一次；复检仍失败时停止，避免反复覆盖用户配置。
- Codex 已经运行时保持幂等，不关闭、不重启，也不影响当前任务。
- 继续允许 Codex 合法维护 `projects.*.trust_level`、`desktop.*`、插件和 MCP 等非 CCSM 托管字段；一致性检查只比较 CCSM 管理的 Provider、模型目录和接管投影。

## 根因说明

旧实现自 `a8870050` 起在 CCSwitchMulti 完成数据库初始化和代理恢复之前启动 Codex。新版 Codex app-server 会在启动时读取并冻结 Provider 配置，同时会因项目信任、桌面设置和插件状态合法写入共享的 `config.toml`。旧启动顺序因此可能让磁盘配置随后被 CCSM 修复，但已运行的 Codex 仍保留旧 Provider 快照，表现为“刚启动就仍在使用旧配置”。
