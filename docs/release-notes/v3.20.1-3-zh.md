# CCSwitchMulti v3.20.1-3

这是 `v3.20.1-2` 的小版本修复，解决新建 Codex 模型源仍被强制要求先完成付费深度测试的问题。数据库 schema 继续保持 v22，不引入迁移或降级要求。

## 新建供应商不再强制深度测试

- 在 Codex“单独接入模型源”中，新建供应商没有探测凭证时，可以直接按表单当前选择的 Chat Completions 或 Responses 协议保存。
- Universal Provider 新建或复制并同步到 Codex 时，同样不再自动弹出深度测试确认；当前 Universal Codex 配置固定按 Responses 保存。
- 保存成功后会明确提示该配置“未经深度验证”，用户仍可稍后主动执行 Chat / Responses 深度测试。

## 安全与证据边界

- 未测试配置按显式手动协议保存，不会伪造 Verified 状态，不会写入虚假的协议 profile 或 observation。
- 已经完成深度测试并带有有效 receipt 的新建流程继续使用真实证据提交，不会降级为未验证配置。
- 编辑或同步已有的自动协议供应商仍保留原有证据复用和失效重测门禁；本版本没有全局关闭 Protocol Lab，也没有削弱 MultiRouter 的拆分、路由或 receipt 绑定检查。

## 验证与运行态边界

- 回归测试覆盖普通 Codex 新建、Universal 新建、Universal 新建/编辑意图传递，以及后端“自动空 receipt 仍拒绝、手动空 receipt 可保存且证据表为空”的事务不变量。
- 源码测试、本地构建、GitHub 多平台 CI、公开 Release 和本机安装运行态属于不同证据层；发布本版本不会自动替换或重启当前运行中的 CCSwitchMulti。
