# CCSwitchMulti v3.20.2-18

本版包含三处修复：通知层在弹窗打开时点不动（原 v3.20.2-17 的内容）、刷新流程最后一步“验证新运行态”死等 450 秒后失败、以及确认页说不清“到底有没有问题、要做什么”。v3.20.2-17 未单独发布，内容并入本版。

## 1. 通知层在模态弹窗打开时点不动

Radix 模态弹窗会给 `document.body` 加内联 `pointer-events: none`（只把弹窗内容标成 `auto`）。sonner 通知层挂在 `#root` 里，`pointer-events` 又是继承属性，于是整棵通知层连同「查看日志」按钮一起变成不可点。

**修复**：通知容器显式声明 `pointer-events: auto`；sonner 自己的 `[data-sonner-toast][data-visible='false'] { pointer-events: none }` 依然生效。

## 2. 「验证新运行态」死等 450 秒后报 `codex_paginated_history_projection_not_caught_up`

- 修复阶段本身是成功的（现场恢复快照里 1114 条游标全部修好，事后只读复核 1114/1114 都在修复位置之后）。
- 旧校验要求**每个**被修复的游标都推进到“修复时的文件末尾”。Codex Desktop 只在打开/继续任务时才物化历史，绝大多数历史线程永远不会被触碰，这个条件不可达 —— 于是流程死等到 450 秒超时并报错，即使修复早已生效。
- **修复**：判据改为“游标是否还在记录中间”。
  - `damaged`：游标仍落在记录内部（真正的损坏）→ 仍然 fail-closed，继续等待/报错。
  - `pending`：游标已是合法记录边界，只是 Codex 还没物化到文件末尾 → 记为正常，不再阻塞，并写一条日志说明有多少条在等 Codex 懒物化。
- 追平失败时的补写（把停在已核验重复元数据上的序号对齐回文件实际值）现在每轮验证**最多执行一次**，不再反复写 Codex 的投影库、和 Codex 自己的写入互相覆盖。

## 3. 确认页说不清“问题在哪、点了会做什么”

「确认刷新 Codex 状态」页面顶部现在先给出现状结论：

- 有可修复项：`需要修复的历史：N 个文件（重复序号 X · 迁移游标 Y · 父段引用 Z）`。
- 只有保持原样项：`没有需要修复的历史文件；N 个文件保持原样，不会被自动改写。`
- 都没有：`没有发现需要修复的历史文件。`

按钮也随现状改名：无可修复项时是「重新应用配置并打开」，不再显示「备份、修复并重新打开」。原来那段泛化说明改为「修复范围与边界」小节，保留全部细节。
