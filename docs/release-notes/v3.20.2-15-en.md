# CCSwitchMulti v3.20.2-15

The “Codex status & repair” dialog no longer reopens at every boot with an item that can never be handled, and a batch of safely repairable paginated history was recovered.

## Fixes

- **Repeated boot popup**: any “left unchanged” history file used to open the status panel automatically, even though those files are never modified. The panel now opens automatically only when there is **something that can actually be repaired**.
- **“Needs attention” said nothing useful**: the paginated-history row now has two explicit states — **“Needs repair”** with the pending count and the action to take, or **“No action needed”** when files are simply kept as-is.
- **Reasons are now visible**: a new “reason details” section groups the kept-as-is files by **reason / count / samples** (for example “no verifiable pre-migration backup, so the new byte offset cannot be derived · 1114 files”).
- **Recovered safely repairable history**: an older CCSM provider migration rewrote `model_provider` from `openai` to `codex_model_router_v2` (+15 bytes per record) without advancing Codex's projection cursor, leaving the cursor inside a record. The recovery flow only scanned part of the backup roots, so the verifiable pre-migration snapshot was invisible and every one of these sessions was reported as “left unchanged”. The “current desktop history visibility repair” snapshot is now a candidate generation, still verified record-by-record (provider field difference only, record boundary, contiguous ordinals). Local read-only preflight: repairable items went from 0 to 1114, blocked items fell from 1152 to 38.

## Verification

- Byte-level comparison against the real snapshot confirmed the only difference is `"model_provider":"openai"` → `"codex_model_router_v2"`, exactly +15 bytes per record, matching the cursor offset multiples of 15.
- Rust: `paginated_history` 27 passed / 1 ignored (including new regressions), `cargo test --lib codex` 1721 passed / 0 failed, `cargo fmt` clean.
- Frontend: `tsc --noEmit`, Prettier, `CodexConfigConsistencyDialog` + `useCodexConfigConsistency` 22 passed.
- Local read-only diagnostic `real_history_blocked_reason_census` (ignored by default) reports `affected=1114 blocked=38`.
