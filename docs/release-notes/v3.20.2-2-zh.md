# CCSwitchMulti v3.20.2-2

这是 `v3.20.2-1` 的定向修订版，修复 Provider Set 手动协议前置条件被误报为深度探测失败，以及旧 Codex CLI 或旧模型缓存环境中 GPT-6 Astra 从官方模型目录消失的问题。数据库 schema 继续保持 v22。

## Provider Set 探测结果与配置应用

- `codex_provider_set_manual_intent_required` 现在被识别为配置应用前置条件，不再显示成“探测中断、模型没有结果”。
- 已完成的 Responses/Chat 探测结果、进度与 receipts 会继续保留和展示；选择明确协议后可直接保存，无需再次发送付费探测请求。
- 尚未执行探测时会明确显示“未执行新的探测；配置未应用”。关闭对话框只跳过本次应用，不写入 Provider，也不创建虚假探测证据。
- Provider Set prepare/commit 继续 fail closed；本版本不会自动猜测或绕过用户的 Responses/Chat 手动选择。

## GPT-6 Astra 官方目录回退

- 在线 Codex OAuth 模型目录仍是首选动态来源；在线失败时，模型选择器与配置投影现在复用同一官方来源链。
- CCSM 随包携带 `gpt-6-astra` 官方 Codex 基线，旧版 Codex CLI 的 bundled catalog 缺少 Astra 时仍能显示并投影该模型。
- 本机官方 cache 覆盖 packaged 基线，当前 Codex bundled catalog 最后覆盖，避免发行快照压过更新的官方元数据。
- 基线按 OpenAI 当前 Codex `models.json` 声明默认 `low`，支持 `low/medium/high/xhigh/max/ultra`，并保留图像输入、WebSocket 偏好和 Codex context 字段。

## 边界与验证

- 该修复只调整 CCSwitchMulti 的 Provider Set 工作流和官方模型目录回退，不修改或部署 Codex 本体，不自动改写真实 Provider、历史或 SQLite。
- 发布安装不会自动重启正在运行的 Codex；模型目录刷新仍遵循现有 CCSM takeover/投影生命周期。
- 聚焦 TDD 已覆盖 action-required 状态、对话框文案、探测证据保留、Astra packaged fallback 和更新来源优先级；完整发布门禁结果以 Release 构建记录为准。
