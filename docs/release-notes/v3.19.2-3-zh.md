# CCSwitchMulti v3.19.2-3

## 消除传输中断被误报为 HTTP 429

此前 CCSM 会把“请求可能已经到达上游、但连接在最终响应前关闭”的 `ResponsePending` 映射为 HTTP 429。Codex 因而显示 `Too Many Requests`，即使 OpenAI 从未返回限流响应。

本版本将三类恢复路径彻底分开：

- DNS、TCP、TLS、连接超时等确认未送达的失败，由 CCSM 在同一 Provider 内执行 5 次有界重连，不占用 Codex 自身的重连额度。
- OpenAI 明确返回的 HTTP 429 才进入限流恢复，遵循 `Retry-After`；永久额度错误立即停止。
- 请求已进入发送阶段、是否执行无法确认时，返回 HTTP 424、`cc_switch_response_result_unknown` 和 `retryable=false`，不再携带 `Retry-After`，也不再显示为 Too Many Requests。

结果未知的请求不能在代理层盲目重发，因为底层传输错误无法证明第一次请求是否已经开始采样、计费或产生副作用。CCSM 会优先通过连接前重试和流式安全重连避免进入该状态；一旦真正越过幂等安全边界，则明确失败而不是制造重复执行风险。
