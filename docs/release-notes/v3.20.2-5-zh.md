# CCSwitchMulti v3.20.2-5

这是 `v3.20.2-3` 之后的正式修订版，汇总 Codex 状态与修复可观测性、OpenAI Official Provider 认证所有权、Codex 容量自动续跑、DeepSeek/GLM reasoning 投影和 Moonshot MFJS 兼容性修复。数据库 schema 继续保持 v22。

## Codex 状态与修复

- 刷新进度不再只有阶段名：关闭进程、等待退出、分页历史扫描/迁移/逐文件修复、配置重投影、启动和验证都会显示具体日志。
- 长操作每 2 秒发送心跳；界面显示修复进度日志、最后活动时间和当前阶段已等待时间。
- 分页历史修复增加 15 分钟硬超时，底层文件或 SQLite 卡住时不再让命令永久挂起。
- 前端增加 30 秒无事件看门狗；后端事件链静默会明确失败，不再一直显示“正在刷新”。
- 每次刷新使用独立 run id，迟到的后端结果不会覆盖已经判定为卡死的失败状态。

## OpenAI Official Provider 认证

- Official Provider 现在是官方认证配置的唯一事实源：可在 Provider 内选择 Desktop 原生登录、固定 CCSM OAuth 账号或 OAuth 账号池。MultiRouter 只消费已解析的认证策略，不再拥有平行 OAuth 配置。
- 关闭 MultiRouter 后，direct Official route 仍可继续使用固定 OAuth 或账号池；旧 schema-v2 Router 认证在来源唯一时迁移，存在歧义时 fail closed。
- raw 转发顺序修正为“按 endpoint 解析唯一 route -> 记录 request-local hit/miss -> 仅对命中的 Official route 展开账号池 -> 转发”；未知非文本 endpoint 不再套用文本 fallback。
- direct Official 的账号池候选保留 canonical `codex-official` 归因，status、health、failover、hot-switch 和 current provider 不再制造虚假路由。

## 其他修复

- Codex 容量类响应支持有界自动续跑，并在数据库 v22 迁移顺序上修复相关种子写入。
- Codex 最新 `automation_update` 的根 union 分支经 `$ref` 指向嵌套 `oneOf` 时，MFJS 编译会在根投影前正确展开，不再本地 422。
- DeepSeek/GLM 的 reasoning 投影和目录元数据保持修复，避免首个请求 400 或 raw reasoning 丢失。
- 版本发布验证覆盖前端全量、Rust 全量、TypeScript、Prettier、rustfmt 和 cargo check；数据库 schema 仍为 v22。
