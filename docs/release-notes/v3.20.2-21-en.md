# CCSwitchMulti v3.20.2-21

This release focuses on Codex stability and history visibility: it fixes takeover hanging when the Codex proxy is enabled, the synchronous official-catalog refresh that blocked the takeover hot path, the paginated-history repair being rejected as a whole, and the v25 migration failing on databases without the base tables. It also ships the official model catalog refresh entry point and the Token Exchange static provider descriptor integration.

## Fixes

### 1. Enabling Codex takeover could hang

**Problem**: after enabling Codex routing takeover the UI stopped responding, with logs stopping after the Live config backup and no takeover-success record.

**Root cause**: two synchronous blocks ran inside the locked config-write path:

- The Desktop version gate added in v3.20.2-20 enumerated WindowsApps and fell back to `Get-AppxPackage`, whose `.output()` had no deadline; `codex debug models --bundled` on the same path had none either.
- The official catalog refresh used `block_on_tauri_runtime` to wait for a network fetch. Under a runtime driven by `futures::executor::block_on` the timers never advance, so it hung forever instead of timing out.

**Fix**:

- Desktop version and bundled-model discovery are prewarmed before the takeover lock is acquired; the synchronous projection only reads a ready cache and falls back to the documented unknown-version behavior.
- The PowerShell AppX probe and the Codex CLI probe both have deadlines; timed-out direct children are terminated and reaped, and output draining is bounded by the same deadline.
- The synchronous projection no longer performs network I/O: catalog refresh is a deduplicated background task with a time budget, triggered (not awaited) by the takeover prewarm.

### 2. Paginated history visibility repair is usable again

**Problem**: with any paginated rollout present, the whole repair run failed with `codex_paginated_history_immutable`, including the state DB, session index, workspace-hint, global-state and focus repairs that never rewrite rollout bytes.

**Root cause**: the visibility entry point ran a legacy guard over the entire Codex directory, which is far too coarse; real data is overwhelmingly paginated (2088 paginated versus 3 legacy rollouts on this machine).

**Fix**: per-envelope inspection. Legacy files keep the Provider-state rewrite; explicitly paginated files are only counted and stay byte-identical; state DB and index repairs still run, with resume handled by the existing live Provider compatibility layer. Batch Provider migration, direct writers, compaction and unknown envelopes stay fail-closed.

### 3. Official catalog overlay precedence

**Problem**: the bundled runtime catalog was overlaid before the public snapshot, letting the public schema override newer on-machine metadata and pushing public-only future models to the end of the list.

**Fix**: fixed order of packaged baseline, trusted local cache/backup, refreshed public snapshot (field-level merge), then the current bundled catalog last.

### 4. v25 migration failed without the base tables

**Problem**: the v24 to v25 migration queried `providers` unconditionally and failed with `no such table: providers` on databases that only carried a version number.

**Fix**: the same `table_exists` guard already used by v19 to v20 (no table means no legacy OpenClaw rows to project); descriptor table creation stays unconditional.

### 5. Other

- Codex provider drafts now fail closed instead of persisting invalid input.
- Save and cancel outcomes are reported more precisely.
- Explicit Responses prompt cache breakpoints survive the hot path.
- Rolled back the failed dual-file model catalog projection and separated partial projection failure from a no-op.

## New

- **Codex official model catalog refresh**: manual refresh entry point plus automatic background refresh with TTL and failure cooldown; failures keep using the existing snapshot and never break routing.
- **Token Exchange static provider descriptors**: atomic descriptor registration with the OpenClaw public projection isolated.

## Notes

- This release never rewrites your history on its own; run the repair explicitly and preview first.
- Duplicate ordinals, stale projection cursors and broken `history_base` references produced by Codex itself remain a separate recovery task that must be handled per backup.
