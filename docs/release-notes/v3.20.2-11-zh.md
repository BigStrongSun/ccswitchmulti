# CCSwitchMulti v3.20.2-11

本版修复「代理端口被占用、但强制解除占用也失败」：端口被一个**创建者已经退出**的残留监听占着时，应用现在会找出真正持有该 socket 句柄的本产品子进程并释放它。

## 根因

- 本机可复现：把监听 socket 的句柄复制给另一个存活进程后杀掉创建者，Windows TCP 表里的 LISTEN 行仍显示**已死的 PID**，此时 bind 报 10048，而按 PID 既无法核验也无法终止 —— 这正是“强制解除失败”的现场。
- 旧实现只按 TCP 表里的 owner PID 处理，因此这种残留既不能释放，也不会自愈。

## 修复

- 启动恢复遇到该情况时：定位创建者 PID 的存活子进程，仅终止**本产品自己**的镜像（msedgewebview2.exe、ccsm.exe、codex-history-repairer.exe、cc-switch.exe 或安装目录内的程序），随后重试一次启动；非本产品进程继续 fail-closed。
- 「解除占用并恢复接管」同样先走这条释放路径，端口真正空出后直接完成接管恢复，不再只报错。
- 端口占用诊断仍会记录 PID、状态与不可读原因，便于事后追溯。
