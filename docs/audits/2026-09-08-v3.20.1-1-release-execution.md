### Gate findings

- The first full frontend run at `a908c389` failed 1 of 1537 tests: the OpenCode PPIO preset exposed Tencent Token Plan models instead of its own DeepSeek V4 Flash model.
- Root cause: `1a905f16` inserted the Tencent OpenCode presets but also replaced the adjacent pre-existing PPIO `settingsConfig.models` object with a duplicate of the Tencent personal-plan catalogue. This was source-data contamination, not a shared-object runtime mutation.
- The existing PPIO assertion supplied the RED evidence. Restoring only the PPIO model object made the combined PPIO/Tencent focused suites pass 31/31. The full frontend item remains unchecked until it is rerun against the repaired candidate.
- The repaired candidate `110da36f` passed the full frontend suite: 185/185 files and 1537/1537 tests.
- The first parallel Rust full run compiled successfully, then passed 4045 tests, ignored 6 and failed 2. The Codex config CAS test passed alone, identifying process-wide test-home/settings interference between parallel tests rather than a product CAS failure. The final Rust suite will therefore use one test thread while Cargo compilation remains parallel.
- The other Rust failure was deterministic: `b30b470d` changed the Grok 4.5 cache-read seed from 0.50 to 0.30 but the historical backfill assertion still expected the old amount. Its existing RED now passes with cache cost `0.000075` and total cost `0.001575`.
