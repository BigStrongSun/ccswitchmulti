# v3.19.2-25 Release Closure Implementation Plan

> **For Codex:** Execute this plan task by task with test-first checkpoints. Do not merge old feature branches wholesale; current `main` is the architecture baseline.

**Goal:** Finish the remaining production-grade environment injection work, restore the ordinary CI quality gate, reconcile stale branches/issues against current behavior, and publish a fully verified `v3.19.2-25` release.

**Architecture:** Environment injection remains a device-local settings feature. The backend owns all mutation semantics through one target-neutral reconciliation engine, a durable per-key ownership ledger, and structured status/results. Claude JSON and Codex TOML are adapters; provider/live writers only reapply entries already proven to be CCSM-owned. Existing provider data, common config, Protocol Lab, MultiRouter and config-consistency ownership remain separate sources of truth.

**Tech Stack:** Rust/Tauri, serde JSON, `toml_edit`, React/TypeScript, TanStack Query, Vitest, Cargo test/clippy, GitHub Actions and GitHub CLI.

1. Store a versioned device-local ledger outside provider data; each entry records target, key, managed value and original state.
2. Acquire ownership only when the key was absent. An equal pre-existing value is a conflict, never proof of ownership.
3. Update/remove only while the live value still equals the recorded managed value; otherwise relinquish ownership.
4. Reconcile Claude and Codex independently, rollback completed writes on a later failure, and report rollback failures explicitly.
5. Support both Codex inline tables and table form without changing unrelated TOML.
6. At provider/live write boundaries, reapply only currently desired entries already recorded as owned; never infer ownership from a matching value.
