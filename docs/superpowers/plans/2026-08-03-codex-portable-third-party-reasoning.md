# Codex Portable Third-Party Reasoning Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make CCSM-managed third-party native Responses reasoning stream and persist in a portable Codex summary representation, restore it only when sending back to the same third-party path, and prove the task can switch to direct OpenAI WebSocket and back without CCSM conversation storage.

**Architecture:** Add one focused Rust codec for pure Responses JSON/SSE conversion, a conservative provider predicate that enables it only for verified non-official native Responses routes, and two integration points: request restoration in `forwarder.rs` and response wrapping in `handlers.rs`. Route capability plumbing and the DeepSeek repair migration opt in existing and newly generated DeepSeek V4 Flash routes; OpenAI official, Chat/Messages transforms, unknown providers, and mixed genuine-summary/raw items remain unchanged.

**Tech Stack:** Rust 1.85, serde_json, bytes/futures/async-stream SSE handling, Axum proxy responses, TypeScript/Vitest route configuration, rusqlite migration tests, Codex Responses API over HTTP/SSE and direct official WebSocket for live acceptance.

## Global Constraints

- Third-party reasoning must remain visible incrementally in the Codex reasoning UI.
- Prompts, responses, and reasoning must never be copied into CCSM SQLite, logs, or sidecar files.
- After restoring built-in OpenAI, CCSM must be absent from the request path and Codex must use the official Provider and WebSocket.
- OpenAI official responses, official `encrypted_content`, and official compaction items must remain byte/semantics preserving.
- The bridge may run only for explicitly enabled non-official native Responses routes; first production opt-in is DeepSeek V4 Flash.
- Existing polluted rollouts are out of scope for this first protocol experiment.
- Every implementation task follows RED -> minimal GREEN -> focused regression -> local commit.
- Every commit message ends with `本次提交由BigStrongsSun完成`.

## File Structure

- Create `src-tauri/src/proxy/providers/portable_reasoning.rs`: pure item codec, deterministic marker IDs, request restoration, SSE state machine, and module-local tests.
- Modify `src-tauri/src/proxy/providers/mod.rs`: register the module and export only the provider predicate needed by handlers/forwarder.
- Modify `src-tauri/src/proxy/providers/codex.rs`: decide whether a request is a verified non-official native Responses portable-reasoning route.
- Modify `src-tauri/src/proxy/forwarder.rs`: restore CCSM-marked summaries before sending a native third-party Responses request.
- Modify `src-tauri/src/proxy/handlers.rs`: wrap successful native third-party Responses SSE/JSON before Codex persists it.
- Modify `src/types.ts`: add the route capability `portableReasoningBridge?: boolean`.
- Modify `src/lib/codexMultiRouterWizard.ts`: enable the capability only on DeepSeek V4 Flash native Responses routes generated by the wizard.
- Modify `tests/lib/codexMultiRouterWizard.test.ts`: prove Flash opt-in and official/Chat non-opt-in.
- Modify `src-tauri/src/database/schema.rs`: add the capability to repaired existing DeepSeek Flash routes without touching Pro Chat routes.
- Modify `memory.md`: record implemented behavior, tests, live evidence, and any remaining limitation after acceptance.
