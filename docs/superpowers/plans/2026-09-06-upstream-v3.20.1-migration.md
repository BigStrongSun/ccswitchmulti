# CCSwitchMulti v3.20.1-1 Upstream Migration Implementation Plan

> **Execution rule:** Work sequentially in the isolated `bigstrongsun/upstream-v3.20.1-migration` worktree. Do not modify, merge, clean, or remove any existing worktree. Use focused tests during development and reserve full suites/builds for the checkpoints defined below.

**Goal:** Semantically migrate applicable official CC Switch v3.20.1 changes plus audited post-tag fixes into CCSwitchMulti and publish `v3.20.1-1` without regressing CCSwitchMulti-specific routing, OAuth, protocol evidence, or history behavior.

**Architecture:** Treat the 131 upstream-only commits as an input catalogue, not as a merge branch. Classify every commit, then adopt isolated data/reliability changes and rewrite architecture-sensitive behavior against current CCSwitchMulti boundaries. Database, identity, protocol, Pi, and UI layers remain independently reviewable and independently revertible.

**Stack:** Rust/Tauri, SQLite/rusqlite, React/TypeScript/Vitest, PowerShell release tooling, GitHub Actions.

**Design:** `docs/superpowers/specs/2026-09-06-upstream-v3.20.1-migration-design.md`

## Verification cadence

- Inner loop: only the smallest RED/GREEN test that proves the current change.
- Batch close: one affected-module test set plus lightweight format/diff/UTF-8 checks.
- Integration checkpoints: after Tasks 3, 6, and 9.
- Final candidate: one concentrated full local gate on the Ryzen 9 9950X, followed by cross-platform CI.
- A failed test is diagnosed and rerun with its dependency scope; do not rerun unrelated full suites after every commit.
- Disable the repository post-commit release hook for intermediate commits with command-scoped `core.hooksPath`; do not alter persistent Git configuration.
