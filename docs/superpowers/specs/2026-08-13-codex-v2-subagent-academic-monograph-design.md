# Codex V2 Sub-Agent 学术型技术专著课件设计

## 2. 受众与写作原则

受众包括第一次接触 Agent 协作的技术读者、希望理解 Codex Sub-Agent 的工程师，以及需要审阅 CCSM 实现边界的研究和开发人员。材料不是运维手册，也不是产品宣传册。

每一页都必须同时回答两个问题：

- 这页在讲什么；
- 这件事为什么重要。

专业术语保留英文以对应论文、Codex 和 CCSM 源码，但首次出现时提供直白中文定义。不能用英文名词堆叠替代解释。

## 3. 证据与引用规则

### 3.1 时间范围

- 核心论文不少于 25 篇；
- 计入最低数量的论文年份只能是 2025 或 2026；
- 优先纳入 2026 年正式发表论文；
- 2025 年正式论文作为稳定证据主干；
- 2026 年 arXiv 或 OpenReview 材料可纳入，但必须标为“预印本”“在审”或具体提交状态；
- 2024 年及更早材料只能作为历史背景，不能计入 25 篇最低数量。

### 3.2 来源等级

从高到低：

1. ACL Anthology、会议正式论文页、DOI 与出版方页面；
2. arXiv 原始摘要页与 PDF；
3. OpenReview 原始 submission 页面，连同接收、撤回或在审状态；
4. 官方项目仓库和作者发布的实验资料；
5. 二手报道只能用于发现，不作为结论证据。

### 3.3 每篇论文的记录字段

每篇论文必须记录：

- `id`、标题、作者、年份；
- venue、DOI、论文页、PDF URL；
- `publication_status`；
- 研究问题与方法；
- 实验对象、模型、任务和规模；
- 可以支持的结论；
- 不可以外推的边界；
- 对应报告章节和课件页码；
- 本地 PDF 状态与 SHA-256（若下载）。

### 3.4 数字引用边界

性能、Token、延迟、成功率和提升比例只能在原论文的模型、任务、基线和实验条件下表述。禁止把单个 benchmark 的结果写成“多智能体普遍优于单智能体”。

## 4. 核心学术框架

材料以一个条件判断为主线：

> 只有当任务能够形成可委托、可隔离、可验收的子目标，并且并行、能力互补或上下文治理收益大于通信、整合和错误传播成本时，Sub-Agent 才具有系统价值。

### 4.1 概念边界

- **Model**：生成和推理能力本体；
- **Agent**：模型加上目标、状态、工具、环境观察和执行循环；
- **Agent harness/runtime**：承载工具、上下文、审批、沙箱和生命周期的运行系统；
- **Sub-Agent**：由 Parent 在同一用户目标下委托、受范围约束、需要返回可整合结果的 Child Agent；
- **Multi-Agent system**：两个或更多 Agent 通过组织结构和通信协议共同或竞争完成任务；
- **Tool call**：执行一个已有能力，不天然拥有独立目标、上下文和生命周期；
- **Parallel sampling/ensemble**：多次生成或投票，不一定形成协作关系。

Sub-Agent 是 Multi-Agent 的层级式子集。其“Sub”来自授权、目标和责任关系，不来自模型大小或模型是否便宜。

### 4.2 为什么使用 Sub-Agent

需要从研究证据分别讨论：

- 上下文隔离与分布式知识处理；
- 可并行的独立子问题；
- 不同技能、模型或工具形成能力互补；
- 独立审查降低同一轨迹的确认偏差；
- 长任务中稳定的责任与状态管理；
- 审计、回收和局部失败隔离。

同时必须说明不适用条件：任务不可分、沟通成本高于收益、多个 Agent 同质化、验证与终止机制缺失、共享状态强耦合、错误会沿通信拓扑扩散。

### 4.3 组织结构

课件至少比较：

- 单 Agent；
- Parent–Child 星形结构；
- 多层层级结构；
- 链式流水线；
- 对等讨论或 debate；
- 树形探索；
- 一般图拓扑；
- 动态选角与动态拓扑。

组织结构不做抽象美学比较，要围绕信息流、决策权、回收点、错误传播、Token 与延迟解释。

### 4.4 Agent 能力与评级

“Agent 评级”不采用一个总分，而采用系统级能力向量：

- 任务分解；
- 角色/能力匹配；
- 工具使用；
- 上下文与状态管理；
- 协作与通信；
- 结果验证；
- 终止与恢复；
- 成本、延迟和鲁棒性；
- 安全与权限边界。

评价对象既包括 Agent，也包括整个 harness、拓扑和 orchestration。模型分数不能替代系统验收。

## 6. Codex 与 CCSM 表述边界

- V1/V2 是本材料对已审计 Codex 工具与协作模型的工程分期，不声称是通用学术标准；
- `description` 是语义选角信号，不是确定性硬路由；
- `task_name` 建立任务路径，不能替代 `agent_type`；
- CCSM 不重写 Codex orchestrator；
- CCSM 不解密 OpenAI ciphertext；
- Official → Official 保留原生语义；
- 只有第三方 Provider 已真实物化后才做第三方消息投影；
- opaque ciphertext 必须 fail closed；
- TOML 文件存在不等于真实 Child 已运行；
- GitHub 构建成功不等于受影响机器完成运行验收。

“VEVR”若无法在用户或源码中找到权威定义，不作为正式术语写入结论；报告将使用可验证的 V1/V2、Role runtime、Provider materialization 和模型绑定术语，并在术语说明中记录该输入歧义。

## 7. 视觉与交互设计

- 延续 `document-deck` 阅读型模板；
- 默认 `engineering-whiteprint`，支持 `academic-paper` 与 `tokyo-night`；
- 网格只允许出现在页面空白区，正文承载表面必须不透明；
- 每页保留“这页用大白话说”；
- 页内引用使用 `[P01]` 等稳定编号，点击可进入论文说明；
- 每个章节导览显示本节问题、概念和证据；
- 每个章节总结显示“能得出的结论 / 不能外推的结论”；
- 图表必须配 caption 和证据编号；
- 代码页继续采用“代码—逐行中文机制说明—整体控制流”；
- 900×650 时允许纵向滚动，不允许横向溢出，不缩小代码至 12.5px 以下。

## 8. 数据流与文件职责

`papers.json` 是论文元数据的唯一结构化来源；注释书目由其内容人工扩写，不反向覆盖元数据。报告引用稳定论文 ID，课件复用相同 ID。证据索引把论文证据、OpenAI 官方证据、Codex 源码证据和 CCSM 源码证据分开。

HTML 课件继续由 `index.html` 提供静态页面，`deck.js` 负责导航、术语、解释框和论文引用交互，`style.css` 负责三主题通用内容表面与学术引用样式。

## 9. 失败处理

- PDF 下载失败时保留官方论文页、PDF URL、失败原因和重试状态，不能用第三方镜像冒充归档成功；
- 元数据冲突时以出版方/ACL/DOI 为准，并记录冲突；
- 论文结论与其他研究冲突时并列呈现任务和实验差异；
- 课件页数超过 70 时优先合并应用案例或参考入口，不压缩定义、V1/V2 概括和章节总结；
- 内容过密时拆页，不缩小字体或隐藏末行。

## 10. 验收标准

### 10.1 研究验收

- 核心论文不少于 25 篇，全部为 2025–2026；
- 2026 年论文数量多于 2025 年；
- 正式论文与预印本状态准确；
- 每篇拥有完整注释字段与至少一个正文引用位置；
- 所有数字可以回到原论文实验条件；
- 两条独立检索链及其差异被记录。

### 10.2 内容验收

- 清楚定义 Agent、Sub-Agent、Multi-Agent、Tool Call 和 ensemble；
- 明确解释 Sub-Agent 相对单 Agent 的收益条件和失败条件；
- 明确解释“为什么叫 Sub-Agent”；
- V1、V2 前各有概括页，V1→V2 有独立转换章节；
- 包含组织结构、能力向量和系统级评价；
- Codex/CCSM 结论与源码边界一致；
- 每个大章节都有导览和总结。

### 10.3 HTML 验收

- 页面数在 66–70；
- 三套主题全部可用；
- 32页旧内容迁移后不存在引用丢失；
- 1280×720 与 900×650 全页无横向溢出；
- 代码字体不低于 12.5px；
- 正文表面不透明，背景网格不穿透卡片和文字；
- 术语、论文引用、exploration、总览、主题切换和 hash 深链均可操作；
- 浏览器控制台无 error/warning；
- 关键页截图在至少 900ms 过渡等待后生成，且仅一个 slide 可见。
