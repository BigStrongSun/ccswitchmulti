# Codex Sub-Agent 双主题视觉设计

## 问题

当前 Sub-Agent 工作台虽然能够随全局主题切换，但信息主体仍主要使用中性的 `bg-background`、`bg-card`、`bg-muted` 和默认边框。结果是：

- 深色主题下呈现为大面积黑灰表单，状态之间缺少视觉区分；
- 浅色主题下呈现为大面积白色表单，能力问卷、模型状态和保存状态难以快速定位；
- 与同一 MultiRouter 工作台已经使用的蓝、紫、青绿、橙、红语义色不一致。

根因不是主题框架缺失，而是 Sub-Agent 新组件没有建立并复用 MultiRouter 的双主题语义色契约。

## 设计目标

1. 浅色和深色使用同一套语义，不为某个主题单独维护结构。
2. 颜色表达信息，不只做装饰：蓝色表示配置与动作，紫色表示角色与 Provider，青绿色表示可路由和成功，橙色表示待配置，红色表示不可路由或错误。
3. 保留现有 V1/V2 切换、Accordion 单开、键盘操作、筛选、问卷、覆盖字段、TOML 预览和保存逻辑。
4. 重要状态不能只依赖颜色，继续保留文字、图标、边框和 ARIA。

## 视觉契约

### 页面层级

- Sub-Agent 总区使用低饱和蓝紫渐变，作为功能边界，不表达成功或错误。
- V1 卡使用蓝/青语义；V2 卡使用紫/绿语义。
- 当前协议的按钮保持灰色 disabled 并显示“已启用”；可切换协议的按钮保持蓝色。
- 选择策略使用蓝色配置面板；模型目录同步使用青色工具面板。

### 模型状态

- `enabled && routable`：青绿色卡片。
- `!enabled`：紫/橙色待配置卡片。
- `routable === false`：红色卡片，优先级高于 enabled。
- Provider、路由、启用、偏好、推理、自动/覆盖和任务优势使用不同语义色 Badge，避免一排同色描边标签。

### 编辑区域

- 任务优势改为双主题能力 chip 网格；选中项使用蓝青色实底，未选中项保留可点击边界。
- 四个问卷 select 置于紫色轻底的独立单元中。
- “高级字段”使用紫色折叠区；“生成结果与 TOML”使用青色折叠区。
- TOML 代码块继续使用深色代码表面，在浅色和深色主题下保持高对比。

### 保存状态

- 已保存：绿色 sticky bar。
- 有未保存更改：蓝色 sticky bar。
- 保存错误：红色 sticky bar。
- 投影警告仍以橙色文字和状态提示呈现。

## 双主题要求

- 每个彩色背景、文字和边框必须提供对应的 `dark:` 类。
- 浅色表面使用低饱和 `*-50`/透明背景和较深文字；深色表面使用 `*-950` 或 `*-500/10`，配较浅文字。
- 不使用仅在深色可读的固定文字色；TOML 代码块除外。
- 焦点、disabled、hover 和 active 状态继续使用现有组件行为，不降低键盘可用性。

## 验收

- 浅色和深色实际应用截图都能一眼区分策略区、目录工具、可路由模型、待配置模型、不可路由模型、能力问卷、高级字段、TOML 和保存状态。
- 与状态页的语义色含义一致。
- 视觉契约测试同时断言浅色类和 `dark:` 配对类，防止后续只适配单一主题。
