01 / WHY SUB-AGENTS

单 Agent 的瓶颈常常不是推理，而是上下文竞争

仓库探索、日志、测试输出和最终决策都挤在同一线程时，中间材料会逐渐覆盖真正重要的目标与约束。OpenAI 将这种风险描述为 / context rot。

Sub-Agent 不会凭空增加模型能力。它改变的是信息组织：过程噪声留在独立 child thread，parent 只接收经过压缩的结论、证据与产物。

关键收益：把“谁做过程”与“谁保留全局目标并整合”分开。
CONTEXT BUDGET COMPETITION

左：过程材料挤压决策空间；右：child 隔离过程，parent 保留目标。

02 / RESPONSIBILITY

Sub-Agent 是有边界的协作执行者，不是第二个总负责人

Parent

持有用户目标、任务拆分、文件所有权、冲突协调、验收与最终交付。

Child

在独立 Agent thread 中完成一项清晰任务，返回证据、局部产物或风险。

共享边界

工具和工作区可以共享，但全局承诺、合并与发布不会因 spawn 自动转移。

PARENT / CHILD RESPONSIBILITY GRAPH

Parent 保留“对用户负责”的全局职责；child 承担可委派、可验收的局部过程。

03 / V1 BASELINE

V1 以 Agent ID 为句柄：直接、显式、需要 Parent 手工记账

V1 工具族围绕一个运行中的 agent id 管理生命周期。Parent 创建 child 后保存 id，再用 id 发送输入、恢复、等待或关闭。当前官方 V1 handler 把调用翻译成 AgentControl 操作，并让 child 继承有效 provider、审批、sandbox 与 cwd，再叠加 role 配置。

机制很直观，但当 child 数量增加时，parent 必须自己维护“a1 对应哪个任务、谁已完成、谁需要追问”。

V1 TOOL FAMILY

  • spawn_agent：创建并返回 id
  • send_input：继续发输入
  • resume_agent：恢复运行
  • wait_agent：等待状态
  • close_agent：关闭生命周期
ID-CENTRIC STRUCTURE
Parent turnAgentControlchild a1wait / resultParent integration

精确工具名与 schema 可能随版本变化；这里固定的是已审计版本的运行抽象。

04 / V1 LIFECYCLE

V1 生命周期：Parent 围绕一个运行实例推进状态

Spawned
Running
Waiting
Running
Completed
Closed

状态转换由具体操作驱动。spawn_agent 创建实例；child 运行中可能等待工具；send_input 或 resume_agent 让它继续；wait_agent 只是观察状态，不替 child 执行工作。

完成与关闭也不是同一概念。Completed 表示某一轮返回 final，Closed 才表示生命周期被明确收回。

转换触发
Spawned → Runningchild turn 开始
Waiting → Running工具完成 / resume / input
Running → Completedchild 返回 final
任意可运行态 → ClosedParent 主动关闭
V1 管得很好的是“一个 child 实例”；不擅长表达的是“一个可寻址、可后续追加的协作任务”。

06 / WHY V2

V2 把“运行一个 Child”提升为“创建一个协作任务”

V2 的核心不是多几个模型参数，而是协作对象变了。 给任务规范身份； 让任务间可以定向通信；follow-up 能给已完成任务追加新一轮工作。

于是 parent 面对的不是一组随机 id，而是一棵有层级、可寻址、可继续的任务树。

V1：管理 child 实例。V2：管理带身份和生命周期的协作任务。
CANONICAL TASK TREE

task path 表达协作树身份；它不等于 custom role 名。

07 / V2 COLLABORATION

V2 把“消息”和“追加工作”分成不同语义

工具协作语义是否启动 turn
spawn_agent创建有 task_name 和 canonical path 的 child是
send_message向现有任务 mailbox 发送信息否，默认只投递
followup_task给既有任务追加工作空闲时启动
interrupt_agent打断当前 turn，保留任务身份终止当前轮
list_agents按路径检查协作树和活动状态否

这套语义让“告知一个事实”和“要求再做一轮”不再混在一起。task path 也使兄弟任务可以被明确寻址，parent 不必把所有横向协调都翻译成 id。

11 / CODE SLICE

官方 SpawnAgentArgs：task_name 与 agent_type 进入不同机制

struct SpawnAgentArgs {
 message: String,
 task_name: String,
 agent_type: Option<String>,
 model: Option<String>,
 reasoning_effort: Option<ReasoningEffort>,
 service_tier: Option<String>,
 fork_turns: Option<String>,
 fork_context: Option<bool>,
}
01message 是 child 的任务正文，后续会被包装为协作通信。
02task_name 参与 canonical path；它不加载 role。
03agent_type 才进入 apply_spawn_agent_role。
04model/effort/tier 是运行覆盖，但会受 reserved schema 和 fork mode 约束。
05fork_turns 决定 child 继承 none/all/最近 N 轮。
06fork_context 是旧字段，V2 当前明确拒绝。
整体控制流：handler 解析 fork → 构建 child config → 应用 role/model/runtime → 建 task path 与 communication → AgentControl 创建 thread。真实副作用发生在 AgentControl spawn，而不是 struct 解析。

12 / CONTEXT FORK

fork_turns 决定历史继承；当前默认 all 会影响异构 Role

let fork_turns = self.fork_turns
 .as_deref()             // 读取显式策略
 .map(str::trim)         // 去掉空白
 .filter(|v| !v.is_empty()) // 排除空值
 .unwrap_or("all");     // 当前默认完整历史

if fork_turns == "none" { return Ok(None); }
if fork_turns == "all" {
 return Ok(Some(FullHistory));
}
let last_n = fork_turns.parse::<usize>()?;
Anone：child 不 fork 历史，适合独立异构 worker。
Ball：完整继承 parent 历史，当前实现默认值。
C正整数：只继承最近 N 轮，在上下文与隔离间折中。
Dfull-history fork 会限制 role/model override；不能同时假设完整继承和自由换 runtime。
整体控制流：fork mode 改变 child 的上下文来源，不直接决定 Provider。选择异构 custom role 时应明确给出 fork_turns: "none" 或经过验证的最近 N 轮。

14 / SEMANTIC ROUTING

模型名说明“在哪里跑”，能力描述才说明“为什么选它”

Flash Explorer

匹配：长上下文阅读、仓库探索、证据收集、总结与测试观察。

排除：复杂架构、复杂实现、高风险审查。

范围：只读。

Pro Engineer

匹配：复杂调试、架构设计、跨模块实现、高风险审查。

排除：泛化阅读和简单摘要。

范围：委派目标内复杂改动。

即使两个角色来自相同模型家族，它们也可以承担完全不同的任务边界。Parent 依据 description 做 best-effort 语义选择；选中后，developer instructions 决定 child 行为；最后 runtime binding 才把请求送到具体模型。

description 不是确定性硬路由。真实模型与 Provider 必须通过 child config、请求或路由证据验证。

15 / IDENTITY SEPARATION

task_name 只建立任务路径；agent_type 才选择 Custom Role

错误理解

{
 "task_name": "deepseek_flash", // 只得到路径
 "message": "审计仓库"          // 没有选择 role
}

结果可能是 generic inherited child；路径像角色名，不会触发 role 加载。

正确分离

{
 "task_name": "audit_router",       // /root/audit_router
 "agent_type": "deepseek-v4-flash", // custom role
 "fork_turns": "none",              // 独立异构上下文
 "message": "只读审计路由代码"      // 本次任务
}

任务身份、角色身份、上下文策略与具体工作各自有独立字段。

官方 handler 从 args.agent_type 计算 role_name；thread_spawn_source 才消费 task_name。源码路径已经把两个概念分开。

④ 失败

17 / BARRIER ONE

Reserved schema：多一个可选字段，也可能让整个请求在推理前失败

部分模型把 collaboration.spawn_agent 视为服务端保留工具。客户端提交的 JSON Schema 必须与后端模型配置严格一致。旧方案设置 hide_spawn_agent_metadata=false 后暴露 model、reasoning、service tier，这不是无害扩展，而是契约变化。

公开 issue #32674 复现了 schema mismatch 400。issue 能证明具体版本发生过，设计边界仍需由官方源码和实际 schema 共同判断。

硬边界：不要修改 reserved collaboration.* 来换取第三方 routing metadata。

18 / PAYLOAD BARRIERS

改 Namespace 只能通过第一层，任务正文仍可能无法投递

② Encrypted

V2 可标记 spawn/send/follow-up 的 message 为 encrypted。Official backend 返回 opaque argument，第三方没有 OpenAI 解密能力。

③ agent_message

即使正文已是明文，Codex 私有 input item 也不等于第三方实现的标准 Responses message。

④ Replay

reasoning、web search、encrypted content、item ID 和工具历史不能跨 transport 原样重放。

{
 "type": "agent_message", // Codex V2 私有协作 item
 "author": "/root",       // 发送者任务路径
 "recipient": "/root/a", // 接收者任务路径
 "content": [{"type":"input_text","text":"检查路由"}]
}
因此 V1 可用不代表 V2 可用：二者经过的工具 schema、协作正文与 input item 路径不同。

  return d.clone();

  excluded_strengths(&p.strengths),

24 / PROVIDER MATERIALIZATION

路由命中不是终点：真实认证、URL 与协议来自 Target Provider

pub fn materialize_codex_routed_provider_from_target(
 route_provider: &Provider,
 target_provider: &Provider,
) -> Provider {
 let mut p = target_provider.clone();
 p.id = route_provider.id.clone();
 p.name = route_provider.name.clone();
 // 仅叠加 route id、capabilities、apiFormat、
 // model override 与 plaintext compatibility marker
 p
}
01route provider 表示本请求命中的模型路由，不一定持有真实凭证。
02target provider 是数据库中的真实上游，持有 URL、认证和转换配置。
03先 clone target，确保 transport 与认证完整。
04再保留 request-local route 身份，用于统计和模型映射。
05只叠加必要字段，不复制整个 router，也不二次路由。
整体控制流： 按 model 的 exact/prefix/default 解析 route，再按 targetProviderId 物化。它不会修改 GUI current provider，也不会把一个请求变成跨模型 fallback 池。

30 / V23 + TAKEAWAYS

V23 修的是入口阻断；完整适配仍是一条分层因果链

V23 两个根因

Catalog path：旧相对文件名进入新版 AbsolutePathBuf 解析失败。

Agent alias：max_threads 与 canonical 字段同时存在，被 Serde 视为 duplicate。

V23 写绝对路径、迁移并删除 legacy alias；修的是 config → catalog → role 入口。

五个不能混淆的问题

  1. 能力描述：为什么选这个角色
  2. Role runtime：使用哪个可路由模型
  3. MultiRouter：实际去哪个 Provider
  4. Payload compatibility：任务怎样被第三方读到
  5. Codex V2：child 如何创建、通信、回收
CCSM 没有重写 Orchestrator，也不能解密 OpenAI ciphertext。它实现的是能力编译、配置投影、路由物化和跨 transport 的最小兼容层。
