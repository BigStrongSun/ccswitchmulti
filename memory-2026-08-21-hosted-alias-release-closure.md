# 2026-08-21 Hosted search, MultiRouter alias, and release closure

- Screenshot feedback from CCSwitchMulti v3.19.2-10 reports `alias_target_missing` for route/provider UUIDs while the selected catalog model is `deepseek-v4-flash` and its provider `upstreamModel` is `deepseek-v4-flash-0731`.
- The root cause was identity mismatch: the old MultiRouter validator/compiler compared aliases only with the visible catalog model. Commit `bd217d9a` on `main` keeps `model` as the canonical catalog identity, keeps `upstreamModel` as the outbound identity, accepts either identity for alias validation and `Include`/`All` selection, and renders route/provider labels with UUIDs as secondary diagnostics. The schema regression already covered the screenshot shape; this closure adds a compiler regression for `Include + upstream alias` and preserves the runtime canonical/upstream contract.
- The v3.19.2-10 tag does not contain `bd217d9a`; therefore an installed `-10` build can still reproduce the screenshot. There is no v3.19.2-12 tag yet in the local repository, so source fixes require a new build and release before installed users receive them.
- Hosted web search requests now use explicit Responses `tool_choice: {"type":"web_search"}` after CCSM receives a third-party `web_search` call. This prevents the official hosted bridge from declining the already-requested search. A model that never emits a function call remains an upstream model/gateway capability issue and is not forced by CCSM.
- The local release pipeline now captures commit/branch/version identity, requires a clean tracked worktree, exports to a sibling staging directory, checks source identity before and after export, writes BOM-free metadata/checksums, and atomically swaps staging into the final release directory with rollback on failure.
- Do not cherry-pick the old MultiRouter SSOT or reasoning branches wholesale: the audited branches do not contain `bd217d9a`, and several would remove or conflict with current alias/projection behavior. Selective porting is required.
- Verification evidence for this closure: compiler 14/14, schema 6/6, hosted OpenAI client 6/6, hosted-loop focused tests 1/1 each, front-end wizard tests 65/65, release Pester 18/18, rustfmt check, TypeScript check, PowerShell syntax checks, strict UTF-8/BOM checks, and `git diff --check`.
- Follow-up audit found a separate presentation defect: the wizard preview rendered `targetProviderId` directly, so UUIDs remained visible even after backend diagnostics gained labels. The preview now resolves the Provider name and keeps the stable ID only in the tooltip; old routes without `label` also inherit the Provider name in compiler diagnostics and compiled route metadata.
